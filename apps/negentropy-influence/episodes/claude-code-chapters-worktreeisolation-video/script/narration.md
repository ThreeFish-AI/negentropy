## P0 同一张桌子

> 画面：系列片头装置之后冷启动——同一目录窗口里几支光标同时落笔，同一配置文件被反复改写、后笔覆盖前笔（角标 config.py）；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是同一个目录里挤着的几个队友：各干各的活，改的却是同一份代码。
- [p0-02] 你理你的认证，我做我的界面，笔却压在同一个配置文件上。
- [p0-03] 后写的盖掉先写的；想退回去，哪笔是谁的都分不清。

> 画面：任务板小卡（谁干什么）与收件箱小卡（怎么说）依次亮起又退到两侧，中间「在哪干？」问号悬空；一支光标孤军排队的落寞感被翻页扫掉——一栋账本立起，侧面挂出多间房（兰紫初现）

- [p0-04] 任务板管了谁干什么，收件箱管了怎么说——在哪干，没人管。
- [p0-05] 答案不是让大家小心点，而是给每个任务，发一间独立的房。
- [p0-06] 一本账，同时挂出好几间房——机制是现成的。
- [p0-07] 更要紧的是，拆房那一步，藏着全片最值得学的一道守卫。

## P1 一间账本几间房

> 画面：账本主视觉首次亮出（陶土橙环体旁挂）——从账本侧沿「生长」出一间新目录房，拒绝复制图标划掉（非副本粘贴）；角标 git worktree

- [p1-01] 先说这间房是什么——不是复制粘贴出来的副本。
- [p1-02] 它是同一本账上，同时铺开的另一份工作目录，<行|HANG2>话叫工作树。
- [p1-03] 每个目录，挂自己的一条线，各改各的，互不相扰。

> 画面：建房动画三件逐一点火——目录房落位、分支线从账本抽出（兰紫）、任务卡上写入房号字段（钢青框）；角标 create_worktree / .worktrees/ / wt/&lt;name&gt;

- [p1-04] 这套设计的用法，是把房绑在任务上，一任务一间。
- [p1-05] 建房只要两个参数：一个名字，一个任务编号。
- [p1-06] 落地三件事：开出自己的目录，起一条专属的线，把房号写上任务卡。
- [p1-07] 妙在绑定只写房号、不动状态：任务还是没人做，等人来领。
- [p1-08] 于是主事的能提前备好任务和房；谁空了谁来，领走就带房。

> 画面：名字门禁卡弹出——字符白名单滚动，`..` 与 `../evil` 撞门弹回（警示红描边一闪）

- [p1-09] 名字也有门禁：一到六十四个字符，只认字母数字和几种符号。
- [p1-10] 想拿两个点往上溜一层？创建这一步就被挡死；房备好了，接下来看怎么用。

> 角标：git worktree · create_worktree(name, task_id) · .worktrees/ · wt/&lt;name&gt; · branch

## P2 两间房两条线

> 画面：走查舞台双房间分屏——左「认证房」右「界面房」（兰紫同相不同亮），中央账本不动如山；同一配置文件在两房各一份；角标 .worktrees/auth-refactor/ · .worktrees/ui-login/

- [p2-01] 还是那摊活：一个任务理认证，一个任务做登录界面。
- [p2-02] 两间房挂出来：认证房、界面房，同一本账，各自的线。
- [p2-03] 两位队友各领一间，都要动那个配置文件——这回，谁也踩不<着|ZHAO2>谁。

> 画面：认领动作落地（角标 claim_task），左右房内各自的消息条与文件改动沿各自分支线生长（Animated State Trace）

- [p2-04] 用认领工具接走的那一刻，读写、跑命令，全落进自己那间房。
- [p2-05] 改动各记各的线：谁动了什么，一清二楚；要丢，丢的也是自己的线。

> 画面：双房同幕完工（两盏完成灯先后亮起）；镜头推向中央——「房，怎么收？」悬停

- [p2-06] 两边的活先后完工——房，怎么收？
- [p2-07] 先立一条规矩：任务完成，只把结果记在卡上；房的去留，另算。
- [p2-08] 而拆房这道工具，动手前要先<数|SHU3>两样东西。

> 角标：claim_task · bash / read_file / write_file · .worktrees/auth-refactor/ · .worktrees/ui-login/

## P3 拆房三出口

> 画面：拆房工具卡（钢青）登场——两侧弹出计数器：左「未提交文件」右「未推送提交」，数字动态跳；角标 remove_worktree

- [p3-01] 一<数|SHU3>改了还没记到线上的文件，二<数|SHU3>记了还没送回账本的提交。
- [p3-02] 第二条，要线连着上游——远处对着的那本账——才<数|SHU3>得<着|ZHAO2>；第一条，不看这条前提。

> 画面：三出口门卡依次亮——「默认拒绝」（钢青描边）／「强拆」（警示红描边，角标 discard_changes）／「保留等审」（确认绿描边，角标 keep_worktree）

- [p3-03] 有一样不是零，默认拒绝——这是三个出口里的第一个。
- [p3-04] 想强拆是第二个出口，必须显式说一句丢弃；第三个，整条留下等人审。

> 画面：左红右绿消融同屏——左「守卫在位」：房内一个未提交文件，拆房被拒（报错条闪现），文件与分支俱在（全绿）；右「旁路强删」：目录虚化消失、文件无声蒸发、分支线被连带抹掉（警示红）

- [p3-05] 实测一遍：守卫在位，房里放一个没提交的文件，去拆——被拒，房和线都在。
- [p3-06] 绕开守卫强拆呢？目录没了，文件无声蒸发，线也连坐删掉。
- [p3-07] 一句话教训：收尾的保护，比创建更值得学。

> 画面：事件日志条带随每次生命周期操作滚动追加（建 / 拆 / 留三色小事件）；角标 events.jsonl

- [p3-08] 还有一本流水账：建、拆、留，每一步都追加一条事件。
- [p3-09] 出了事，翻这本账就有得查。
- [p3-10] 那真实的 Claude Code，这套房长什么样？

> 角标：remove_worktree · discard_changes=true · keep_worktree · events.jsonl · branch -D

## P4 生产版：两个入口

> 画面：拉远——真实版双入口全景：左「会话进房」整个会话容器（对话气泡 + 工具卡）平移进目录房；右「子代理进房」小舱体带着房号入场、整场活都在自己目录里；角标 EnterWorktreeTool / ExitWorktreeTool / AgentTool · isolation: "worktree"

- [p4-01] 拆解过 Claude Code 源码的同学们应该知道：真实的 Claude Code，把这件事做成了两个入口。
- [p4-02] 进房，是会话级的一步。
- [p4-03] 进房工具一落，整个会话当场切进那间目录。
- [p4-04] 退房时，官方文档写得清楚：改到一半想走，它先检查会被删的工作，再送你回原处。
- [p4-05] 另一个入口是子代理：给一次性任务包一间房，活全在自己目录里干。

> 画面：边界墙剖面图——墙内目录与线分色清晰，墙外路径虚线仍连通（警示红虚线贯穿墙体）；金句卡衬线体压轴

- [p4-06] 最后把边界说死：这堵墙挡互踩，不挡越狱。
- [p4-07] 它分开的只是目录和线；房里跑的命令，够得<着|ZHAO2>的地方一点没变。
- [p4-08] 拿它关不可信的代码，是把它当成它不是的东西——施工面，不是笼子。

> 角标：EnterWorktreeTool · ExitWorktreeTool · AgentTool · isolation: "worktree" · .claude/worktrees/ · worktree-{slug}
