## P0 冷开场：AI 的三个失忆现场（§1）

- 【二】痛点四类（官方博客归纳，经 014 §1 转述）：跨仓库丢失局部上下文、长跑任务遗忘约束、团队知识散落各处、缺少组织「品味」；共同根因 = 信息组织缺位。
- 【二】平铺向量检索的规模问题：语料越大区分度越差，topK 小时漏召回致命；**reranker 救不回从未进入候选集的证据**（014 §1 引官方架构博客）。
- 【二】上下文现状三分裂：记忆在各家记忆库、文档在各家向量库、技能躺在 prompt 里（014 §1）。
- ANALOGY 主角设定：Agent = 带着问题来的研究员（读者）；OpenViking = 一座会自己编目的图书馆：编目员自下而上给书架写标签与导览、参考馆员带路找书、借阅推车限量、每次接待完把要点归档进读者档案。

## P1 范式：一棵树装下三类上下文（§3）

- 【二】一句话定位：把 Agent 的资源、记忆、技能统一放进一棵 `viking://` 目录树的开源上下文数据库（火山引擎 Viking 团队，2026-01 开源，AGPL-3.0 自 2026-03 起）。
- 【二】三个分区（scope）：`resources` 公共馆藏区 / `user/{uid}` 读者个人档案室 / `agent` 馆员手册室；`viking://~` 像 shell 的 `~`，只在请求边界展开成自己的档案室。
- 【二】**类型由位置推导，不按关键字**：`user/alice/memories/…` 是记忆；`resources/memories/x` 仍是资源（014 §3，锚点 `core/namespace.py:114`）。同一棵树上 ls / read / find 一套动作通吃。
- 【二】向量主键 = `md5(租户:位置)`——id 由位置决定，挪了位置就要重新编号（014 §3）。
- 【二】边界（作者自认）：**不是文件系统**——上传内容被解析成 AI-ready 数据，原始文件默认不保留（014 §1/§11）。

## P2 分层：书架标签与导览页（§4）

- 【二】L0/L1/L2 是**目录级** sidecar，不是每本书一张卡：每个目录可有 `.abstract.md`（L0 一句话标签）与 `.overview.md`（L1 一页导览）；书（L2）只有正文。
- 【二】体量代码实值：L0 ≤256 字符、L1 ≤4000 字符，**软上限**（截断只落在句末，首句超长整句保留）——文档写的「~100/~2k tokens」是旧口径（014 §4，矛盾 C1）。
- 【二】**L1 一次 LLM、L0 零 LLM**：目录 L1 =「直接文件摘要 + 子目录 L0」调一次 LLM 汇总；L0 直接从 L1 首段裁出（014 §4）。
- 【二】自底向上 + 采样：最深的书架先编；直接子项 >32 时确定性等距采样（含首尾），采样只限 prompt 宽度、首次入库每本书仍要写简介（014 §4）。
- 【二】新鲜度冒泡漏斗：子书架标签没变 → 零成本；变了才上报；父级 ≤32 子项立即重印、宽书架攒到一成变动才重印（10% 判据，014 §4）。
- 【二】成本公式（014 §4 推导）：入库 LLM 调用 ≈ 非代码文件数 + 目录数；嵌入 ≈ 文件数 + 2×目录数。隐藏放大器：祖先重印会把被采样的兄弟文件重新写简介（≤32）。

## P3 检索：默认档与豪华档（§5）

- 【二】**默认档其实是平铺**：`find` 固定平铺向量检索；默认配置不带 rerank ⇒ `search` 开箱也是平铺——「目录递归」是豪华档，只有配了 rerank 才开（014 §5.1；这是本集最重要的边界）。
- 【二】豪华档流程（014 §5.3）：①意图分析把问题拆成「找书 / 查档案 / 翻手册」几路检索单（没有会话就用原问题）；②全局卡片柜只查书架卡（L0/L1）取前十——一个书架可能占两席；③每次同时进四个书架、每个书架先向量预选最像的 20 条再请专家逐条打分；④打分不过线（0.1）的书架直接淘汰——**唯一剪枝**；⑤书架好坏只决定进不进、先进谁，不给书加分（α=1.0）；⑥候选名单连续三批不变、或书堆三批不涨就收工。
- 【二】检索期从不读整本书（L2 正文）；读正文发生在检索之后。
- 【二】借阅推车（014 §5.5）：默认 1600 token 预算；先每样拿薄的（摘要），有余量再换厚本（全文），装不下换薄本、**绝不撕书**（降档不截断）。
- 【一】QUICK vs THINKING 对照（lab S3 实测）：12 份「已废弃」旧流程措辞与现行高度重合——平铺档 top-3 全被旧文档占据（recall 0.75）；豪华档靠专家认出「已废弃」降权（recall 1.00）。

## P4 记忆：来访归档与读者档案卡（§6）

- 【二】两阶段提交（014 §6.1）：第一阶段**同步**把对话原样装订归档（messages.jsonl，必成）；第二阶段**异步**后台整理——写来访小结（L0/L1）+ 更新读者档案卡（长期记忆）；两步都成功才最后盖「已整理」章（`.done`）。「整理失败」是终态封条：不重试、已写入的不回滚。
- 【二】**相似 ≠ 同一**（014 §6.3，全片最想教的一招）：找相似的旧卡只提名候选；「是不是同一张卡」由规则算出的**卡名**裁决——偏好卡名 = 读者 + 主题，同一主题永远写同一张卡。「是否同一条记忆」被降维成「文件名是否相同」。
- 【二】九类卡片与合并算子（014 §6.4）：偏好卡/人物卡原地修订（patch）；**事件卡只增不改**（宁可重复，不可错并）；案例卡首写即冻结；经验卡整篇重写可推翻旧版。
- 【二】变更登记簿（memory_diff）只记不撤——真回滚能力只在经验卡的快照。
- 【一】三次来访一张卡（lab S6 实测）：「美式 → 拿铁 → 拿铁」三次对话后偏好卡仍 1 张（内容=拿铁），diff 里能看到改前改后；队列重投同一条消息直接跳过（`.done` 幂等，lab S7）。
- 【二】残余风险照实说（014 §6.3）：主题起名不一致（「咖啡」vs「饮品」）两条卡会并存——设计是**有意**把风险从「不可逆丢信息」挪到「可修复的冗余」。

## P5 拆台：馆方公布的成绩单怎么读（§9 + §11）

- 【三】归属句（必须原样带）：「据 OpenViking 团队 2026 年 5 月的自测报告」；并补口径：「打分的是豆包系模型、判分标准宽松、没打分的题不进分母、没有任何单项拆解」。
- 【三】LoCoMo 数字（自报）：OpenClaw 原生 24.20% → 82.08%（×3.39）、输入 token 392.6M → 37.4M；「Claude Code 组」答题模型其实是豆包——验证的是 harness 不是 Claude 模型。
- 【三】**主动讲反例**（014 §9.1）：单轮问答五数据集均值 66.87%，**低于** LightRAG 的 76.00%——但建库 token 只用了对方约 14%、检索快约 48 倍。省钱省时与单轮精度不是一回事。
- 【三】算术错误照实说（014 §9.1）：ClawWork「每小时 token −22.8%」按原始数据复算是 −15.3%。
- 【三】三篇论文的实验都不在开源版上跑（生产 VikingDB / 内部引擎 / 独立仓库）。
- 【二】批判边界五条（014 §11）：无消融（增益归因不到单项机制）；默认部署不触发递归、经验默认不召回；基准无可复现产物；论文结论≠开源版行为；「全链路可追溯」与「可回滚」名不副实（轨迹 schema 无生产者、memory_diff 只写不读）。

## P6 实验室与收尾（§10 + 015）

- 【一】六次破坏实验（lab B1–B6 实测，本集挑 3 个讲）：
  - B1 拔掉书架标签：豪华档 recall 1.00→0.50（答案书架整片不可达），平铺档不受影响——**越聪明的档位越押注标签质量**；
  - B3 卡名不再由主题决定：三次来访 3 张矛盾卡并存（美式/拿铁/拿铁）——身份判据不是学术洁癖；
  - B6 去掉「已整理」章：队列重投一次，事件卡翻倍——至少一次投递下提交点是不可省的。
  - （B2/B4/B5 备选：刹车收紧只省成本；关冒泡→逐层浏览拿到过期地图；α=0 排序反转。）
- 【二】我们该学什么（015）：13 条映射里 ✅4/🔶5/⏸4；**最大真增量不是照搬这棵树**，而是「会话结束 → 后台整理成记忆」的显式提交链——对准本仓「对话聊完就忘」的断链；副本式文件系统与「目录只存指针」的设计原则冲突，可取的是寻址思想与身份判据，不是存储形态。
- 【三】收尾一句（带归属）：这座图书馆自己公布的借阅成绩单还没被独立复现——但它把「AI 的上下文」从各家私藏变成了一个可以打开研究的开源对象，这件事本身值得记一笔。
