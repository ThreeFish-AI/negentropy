## 二、叙事策略

**主线问题（P0 抛出、P6 回答）**
> 商业大厂能把数据含义治理好，你手边的 AI 助手该怎么办？——上下文层能不能像修一座城一样，自己动手搭一个？

**贯穿比喻体系：给 Agent 的数据世界修一座城（五大市政系统）**
- **对象层** = **地籍册**：每条定义有主人、边界与公证，没登记的地块绝不许开工；Ossie/YAML 规范，三条字段纪律，状态机，Data Contract 产权文件与弃用纪律。
- **目录层** = **门牌索引**：只立门牌不替人盖楼，全城只有一本账（逻辑视图，杜绝 Split-Brain）；四层信号；读方向元数据联邦，永不碰数据行。
- **富化层** = **规划局、近道与听证会**：官方金标准修志（authority=1.0）+ 测绘民间近道（desire paths，authority<1.0，突破 <5% 覆盖瓶颈）；eval 自纠环；**冲突浮出听证会（核心契约）**：同名异义标 conflict 出示 CONFLICT 卡片，绝不按热度自动选（D4 实验警示）。
- **激活层** = **国标插座与问询台**：问询台 resolve 契约只递两页带盖章与争议卡；四因子对数封顶 log1p 防刷热度；国标插座 MCP 供给面四工具（纯标准库无外部依赖）；互操作三重边界（可携带 ≠ 可执行 ≠ 已验证）。
- **治理与安全** = **在路上执勤的门禁 + 海关检疫**：双层防线防 CTE 绕行；供给面海关检疫：四类真实威胁、Anthropic 官方 Git MCP Server 漏洞教训（官方受信组件也必须当不可信处理）、安全控制清单。
- **边界对策** = **市政图纸救不了塌方地基**：治理 ≠ 验证（477 vs 48），三级对策。
- **评测与运营** = **市政年检与街道命名权**：known-answer evals，期望值有人签字，越权用例，报错优于错数；Spider 2.0 鸿沟；街道命名权 Propose → Certify，RACI，Prukalpa 三死因，从 5 个指标起步；城市仪表盘三刻度。
- **演进路线** = **P0 机制验证（当前代码已全绿跑通）→ P1 最小服务 → P2 信任自纠 → P3 互操作**。

**术语降落规则**（严格执行）
- 英文标识符**只进画面角标与代码走廊，不进口播**：`resolve` → 「问询台」（首现解释「解析」）；`catalog` → 「门牌索引」；`provenance` → 「溯源标签」；`log1p` → 「对数封顶」；`Ossie` → 「开放规范」；`fail-soft` → 「优雅降级」。
- **例外名单**（可口播）：**MCP**（本集主角之一）、**Horizon Context / Snowflake / dbt / Claude**，标准简称 **AI / SQL / Agent**。
- 遵循单一世界观剧场，严禁跨段落剧场跳跃，同一个实体在全文始终绑定同一个比喻。

**证据分级的口播义务**
- 路线图 P1–P3 未全部工业级量产，口播明确表述为「路线图规划」；已验证的为 P0 纯标准库原型（selftest 全绿）。
- 第三方实证与评测数字必须带归属：Spider 2.0 最强模型 21.3%、UIUC 审计 Spider2-Snow 金标准 62.8% 标注错误率、IBM 13% 泄露 97% 缺 AI 控制等。
- 原型实测压「本仓 lab/MCP 原型实测输出」角标。

**理性收尾**：
- 不鼓吹「人人都能造大模型」，而是落脚于「上下文层是新关键基础设施」。
- 收尾金句：「含义被治理好之前，AI 的聪明都是租来的。」

## 三、视觉语言与色彩语义

**色彩语义契约**（对应 `video/src/design/theme.ts`）：
- 工程蓝 `blueprint` (`#6FB1E8`)：**蓝图与五层架构**——市政规划线、正交层边界。
- 苔绿 `grown` (`#A3D977`)：**生长与自纠**——生命周期、自纠环、状态机流转。
- 暖橙 `activate` (`#FF9F6B`)：**激活与接口**——问询台、四因子天平、MCP 插头与海关检疫。
- 警示红 `danger` (`#FF5C5C`)：**冲突、越权、供给面威胁**（语义唯一）。

**视觉母题**：
1. **五块市政积木**：蓝图纸上依次立起五座市政机关建筑，彼此通过标准管道连接，换掉门牌楼不动地基。
2. **词条一生轨道图**：草稿站台 → 治理站台 → 冲突岔道（红灯亮起，听证会卡片）→ 取代缓行线。
3. **前台问询窗口**：圆形 AI 头像排队，窗口递出两页精装纸，四因子天平在后方平稳称重。
4. **USB-C 插头与海关检疫门**：MCP 插头接入，海关检疫门亮起扫描线，拦截投毒工具与恶意提示词。
5. **三级对策台阶**：表达式校验在脚下，问答对账居中，eval 自纠在顶层兜底。

## 五、边界与不做的事

1. 不做代码逐行 walkthrough，原型代码以「代码走廊 + 终端断言」形式承接实景自证。
2. 路线图 P1–P3 严禁口播为已实现，清晰区隔 P0 玩具验证与工业落地。
3. 厂商与第三方评测数字 100% 忠实注明出处。
4. 全片独立成篇，口播绝不出现其他系列片名、集数序号或顺序词。
5. 遵循严格字数与时长预算控制，确保一次性通过自动化管线门控。
