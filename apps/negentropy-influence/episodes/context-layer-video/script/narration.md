## P0 你的 AI 也在裸奔吗

> 画面：桌面一个 AI 助手图标，头顶冒出三张对话气泡（写周报✓ / 查数据? / 算错数✗）；「入职第一天」日历粉碎消散。
> 镜头拉远：直连数据库模式被标上醒目的红色卡片「一个连接良好的猜测器」。
> 转场：桌面铺开一张宏伟的深蓝色市政工程设计图。

- [p0-01] 你可能有个常用的 AI 助手。
- [p0-02] 帮写周报、润色邮件，它表现利索。
- [p0-03] 但如果直接丢一堆数据给它。
- [p0-04] 问它上月活跃用户多少，它要么不敢答，要么瞎编。
- [p0-05] 分析师一针见血：直连数据库的 AI，只是个连接良好的猜测器。
- [p0-06] 它就像刚入职的天才实习生，每次被 Call 都在猜贵司方言黑话。
- [p0-07] Snowflake 通过 Horizon Context 搭建了一整套自进化的规章手册，可以让天才实习生秒变业务老司机。
- [p0-08] 这集，我们就把 Horizon Context 的核心拆解成五块通用积木。
- [p0-09] 通过标准库代码实现和验证每一块积木。
- [p0-10] 看看自己动手，怎么给 AI 搭出一套可信的 Context Layer。

## P1 五方积木：市政五系统

> 画面：蓝图纸上五座市政建筑依次拔地而起（地籍册 / 门牌索引 / 规划局 / 执法部门 / 国标问询台），标准管道相互连通。
> **四路线象限图展开**（p1-13）：生在城里 / 按图纸自己盖 / 买自带物业的独立城 / 画地图，蓝图落位独立可执行层。
> **代码走廊 ①**（p1-21）：展示 `horizon_context_lab.py` 的五层架构骨架。

- [p1-01] Context Layer 之于 Agent，就像数据世界中城市的五大市政系统。
- [p1-02] 第一是地籍册即对象层，决定城里放什么。
- [p1-03] 指标、字段、文档技能与权限，都是受治理对象。
- [p1-04] 第二套是门牌索引即目录层，决定怎么找。
- [p1-05] 它给全城拉一张总账，指回原处，引用不复制。
- [p1-06] 第三是规划局即富化层，决定城怎么养。
- [p1-07] 兼顾官方修志与民间近道，让定义变厚变准。
- [p1-08] 第四是在路上执勤的执法部门，即治理层，决定怎么信。
- [p1-09] 角色权限、出口安检与威胁，都在这关执行。
- [p1-10] 第五是国标问询台，即激活层，决定怎么用。
- [p1-11] 智能体插上插头，拿到的都是受治理上下文。
- [p1-12] 五大系统核心原则，是正交。
- [p1-13] 行业格局里，获得城有四条路线。
- [p1-14] 生在城里的平台内嵌，治理在引擎内但绑定大厂。
- [p1-15] 按图纸盖的定义即代码，治理在转换层但脱离运行。
- [p1-16] 只画地图的元数据平面，被批只描述不执行。
- [p1-17] 异类 Palantir 把动态动作也铸进本体。
- [p1-18] 蓝图选第三条路：可独立部署的可执行层。
- [p1-19] 关键把治理挪到查询生成前，防嵌套绕行。
- [p1-20] 正交意味着解耦：换门牌系统不需要重修路。
- [p1-21] 每一层独立演进，城才不会牵一发动全身。
- [p1-22] 这张市政总图，就是接下来的施工地图。

## P2 地籍册与门牌索引：万物皆对象与单一事实源

> 画面：地籍册翻开，展示对齐开放规范的 YAML 词条卡片，三条字段纪律逐个高亮。
> **词条一生轨道图**（p2-11）：draft 起点站 → governed 站台 → conflict 岔道 → superseded 缓行线。
> **代码走廊 ②**（p2-09）：展示 `horizon_context_lab.py` 的 `validate_view` 结构校验门与 `Catalog` 逻辑视图。

- [p2-01] 施工第一步，建对象层这本地籍册。
- [p2-02] 城市铁律：没登记的地皮绝不许开工。
- [p2-03] 定义泛化为对象，并立下三条字段纪律。
- [p2-04] 第一，同义词必须当成一等资产填写。
- [p2-05] 没同义词的定义，在检索面上完全是隐形的。
- [p2-06] 第二，给智能体的说明书必须随对象走。
- [p2-07] 规则随定义演进，不硬编码在外部提示词里。
- [p2-08] 第三，人工核准的问答必须附带签署溯源。
- [p2-09] 每个对象登记时，必经严格结构校验门。
- [p2-10] 引用必须命中键约束，非法结构注册期拒之门外。
- [p2-11] 每个词条都有一生，对应严密状态机。
- [p2-12] 从草稿态起步，经校验与评审晋升治理态。
- [p2-13] 同名异义进冲突态，被新版取代转废弃态。
- [p2-14] 对象还携带数据契约与严格弃用纪律。
- [p2-15] 变更必走弃用窗口通知，严禁静默改口径。
- [p2-16] 接着是第二块积木：门牌索引即目录层。
- [p2-17] 市政职责是立门牌，绝不替各家各户盖楼。
- [p2-18] 目录是逻辑视图，汇聚各源头元数据指针。
- [p2-19] 全城只有一本账，出现第二本就会精神分裂。
- [p2-20] 目录里沉淀着四层活信号。
- [p2-21] 结构记录字段血缘，运维记录新鲜与健康。
- [p2-22] 语义记录口径本体，行为记录频次与热度。
- [p2-23] 静态图谱记是什么，上下文图谱记演变与使用。
- [p2-24] 目录承诺：只做元数据联邦，永不碰数据行。
- [p2-25] 来源受限无法合并，退化为路由不落地数据。
- [p2-26] 地籍册界定含义，门牌索引打通寻址路径。
- [p2-27] 实体和街道，到这里被清晰地锚定下来。
- [p2-28] 城市有了基座，接下来要给它注入活水。
- [p2-29] 把散落各处的经验，源源不断养进城里。
- [p2-30] 这就轮到了规划局出场。

## P3 养上下文：双轨富化与冲突浮出

> 画面：规划局双轨运行。左侧是专家伏案修志（金标准），右侧是航拍草坪近道（desire paths）。
> 镜头聚焦：两套定义打架时，红灯爆闪，一张中间数字刻意留白的 CONFLICT 听证会卡片升起。
> **代码走廊 ③**（p3-19）：展示 `horizon_context_lab.py` 的 D4 破坏性实验断言：
> `[D4 PASS] 冲突改 auto_popularity -> 推断层胜出 [6,1,2]（477 vs 48 事故玩具版）`。

- [p3-01] 任何城光靠专家关门规划，赶不上城市生长。
- [p3-02] 实测显示上万张表里，人工手册覆盖不到百分之五。
- [p3-03] 这就必须靠富化层双轨：显式轨道与隐式轨道。
- [p3-04] 显式轨道是官方修志，权威打满，机器辅助起草。
- [p3-05] 机器起草人类盖章，建模从数天压至数分钟。
- [p3-06] 隐式轨道则是观察人们实际踩出来的近道。
- [p3-07] 从真实日志、看板调用痕迹提取长尾经验。
- [p3-08] 隐式口径权威较低，作为候选条目进入目录。
- [p3-09] 后台挂着自纠环：拿金标准与反馈跑自动化测试。
- [p3-10] 发现语义错配补同义词，检索偏航微调热度。
- [p3-11] 缺口榜直接转化成工作清单，驱动城市自愈。
- [p3-12] 但近道要转正，必须面对最关键的冲突处理。
- [p3-13] 比如两部门对活跃用户这词，各有不同算法。
- [p3-14] 当两本志书打架，系统该听谁的？
- [p3-15] 很多团队犯过大错：让机器按热度自动选择。
- [p3-16] 蓝图锁死核心契约：冲突必须浮出听证会。
- [p3-17] 一旦同名异义，两份定义双双标上冲突。
- [p3-18] 问询接口返回冲突卡，并列两定义，数值刻意空白。
- [p3-19] D4 破坏性实验清晰复现了这种风险。
- [p3-20] 一旦按热度自动选，错误口径就会借调用量胜出。
- [p3-21] 活跃数直接翻倍，四百七十七对四十八事故即由此来。
- [p3-22] 错误胜出比直接报错危险十倍，因为极其隐蔽。
- [p3-23] 机器绝不能假装共识，裁决权必须交还责任人。
- [p3-24] 听证会由人定夺，胜者转正，败者归档。
- [p3-25] 规矩立在台面，城市才不会从内部腐烂。
- [p3-26] 养好上下文后，下一步是把它安全开放出去。

## P4 国标插座与海关检疫：一个窗口 + 一个插头

> 画面：市政前台一排 AI 排队等待问询，后方天平精确称重，递出盖章的两页纸。
> 画面右侧亮起 USB-C 形状的国标插座（标注 MCP），插头接通，整排治理指示灯点亮。
> 镜头推近海关安检机：红外线扫描工具定义与报文，四类供给面威胁被盾牌拦下。
> **代码走廊 ④**（p4-12）：展示 `horizon_context_mcp.py` 的 JSON-RPC 处理循环与四大标准工具定义。

- [p4-01] 激活层是对外窗口，由问询台与国标插座组成。
- [p4-02] 问询台是所有智能体交互的唯一入口。
- [p4-03] 契约极其克制：绝不把整座档案库倒在桌上。
- [p4-04] 只递出相关两页，附带盖章人、新鲜度与冲突提示。
- [p4-05] 排序融合四路信号：相关度、权威度、热度与新鲜度。
- [p4-06] 热度采用对数变换封顶，防止某些高频查询刷榜。
- [p4-07] 命中核准题直接短路重放，无覆盖诚实告警。
- [p4-08] 对外联通手段，就是模型上下文协议 MCP。
- [p4-09] 业界金句：MCP 是传输层，语义层是逻辑层。
- [p4-10] 把插头当成上下文，等于把电话线当成对话本身。
- [p4-11] 蓝图把上下文层封装成标准 MCP 供给面。
- [p4-12] 在开源原型里，纯标准库实现了四个标准工具。
- [p4-13] 列举目录条目、解析问询包、编译指标与反馈热度。
- [p4-14] 外部智能体插上插头，立刻获得整座城支撑。
- [p4-15] 开放互操作有三重边界：可携带不等于可执行与已验证。
- [p4-16] 带着定义走，别家引擎未必替你执行规则。
- [p4-17] 把城市开放为口岸后，攻击面被急剧放大。
- [p4-18] 必须在插座前设海关检疫，防御四大真实威胁。
- [p4-19] 第一类是工具描述投毒，注释里偷藏指令诱导失控。
- [p4-20] 第二类是间接注入，外部文档被误当成执行指令。
- [p4-21] 第三类是混淆提权，诱骗高权限服务端越权查数。
- [p4-22] 第四类是认证凭证透传与盗用。
- [p4-23] 现实中恶意伪造服务暗中抄送，官方工具被曝漏洞。
- [p4-24] 惨痛教训显示：官方受信组件也必须当不可信输入。
- [p4-25] 海关检疫必须落实七项硬核控制。
- [p4-26] 工具定义钉住哈希，防事后偷改行为。
- [p4-27] 拆分读写工具，严禁一把梭的万能接口。
- [p4-28] 破坏性与资金外发操作，强制人工二次确认。
- [p4-29] 监控响应内容，隐藏的指令式语言拉响警报。
- [p4-30] 出口配网络白名单，限制爆炸半径，凭证短命轮转。
- [p4-31] 加上此前验证的双层防线，编译期封死绕行漏洞。
- [p4-32] 既有标准插座开箱即用，又有海关检疫寸步不让。
- [p4-33] 智能体无论怎么调用，始终处在受治理的笼子里。
- [p4-34] 城市通路贯通，最后给工程建质检标尺与运营制度。

## P5 治理的边界：评测与街道命名权

> 画面：三级对策台阶拔地而起（表达式校验在脚下 / 问答对账居中 / 评测自纠兜底）。
> 展开 Spider 2.0 柱状图（91.2% 降至 21.3%），红字警示 UIUC 审计出的 62.8% 基准错标率。
> 街道命名权 RACI 审批流卡片（Propose → Draft → Test → Review → Certify），城市仪表盘发光。

- [p5-01] 任何严肃的工程，都必须正视自己的能力边界。
- [p5-02] 这一章直面最尖锐的问题：图纸验收合格，救得了地基塌方吗？
- [p5-03] 答案依然救不了：治理保图纸合法，救不了上游粒度塌陷。
- [p5-04] 蓝图给出了三级对策。
- [p5-05] 第一级，在表达式注册期自动识别非可加性，成本最低，先做。
- [p5-06] 第二级，用核准问答作为出口对账资产，重算不一致当场报警。
- [p5-07] 第三级，用自动化评测环事后打分，沿血缘定位源头。
- [p5-08] 怎么知道整套系统真的有效？市政工程必须有严格的定期年检。
- [p5-09] 业界实测显示，教科书式的基准测试在企业真实复杂场景前全面失效。
- [p5-10] 真实企业基准下，最强大模型表现跌到了百分之二十一点三。
- [p5-11] 高校审计发现，许多公开基准黄金答案错误率超六成。
- [p5-12] 连公开考卷都在犯错，企业绝不能盲目迷信外部榜单。
- [p5-13] 年检必须由业务团队亲自出题，期望值必须有人签字核准。
- [p5-14] 考卷不仅要考正常查询，还要派便衣警察故意发起越权闯红灯用例。
- [p5-15] 系统的第一原则永远是：报错优于错数。
- [p5-16] 拒绝回答并留审计，远好过自信给出一个错数。
- [p5-17] 考卷活起来之后，整座城市的日常运转，归结为人与组织的运营。
- [p5-18] 一座城，不能谁来了都能给街道命名。
- [p5-19] 命名权必须集中，提案权应当开放，使用权必须普惠。
- [p5-20] 业务团队是最终拍板人，数据团队负责起草测试与流程运转。
- [p5-21] 提案、起草、测试、评审、发布，每一步留下完整审计痕迹。
- [p5-22] 纵观三十年失败史，许多项目最后沦为无人维护空城。
- [p5-23] 核心败因在于不在执行路径，做成了表演性术语剧场。
- [p5-24] 避坑的第一处方，是从五个核心指标起步。
- [p5-25] 找有权高管亲自站台，拍定这五个词在公司就这意思。
- [p5-26] 把五个指标打磨成可执行的日常基础设施，逐步生根发芽。
- [p5-27] 日常运营依靠城市仪表盘的三个刻度。
- [p5-28] 覆盖缺口榜紧盯哪些未纳管词条被频繁问起，指引富化方向。
- [p5-29] 命中率衡量受信任资产的日常活跃度。
- [p5-30] 越权拒绝率证明门禁正在坚决履职，而不是系统故障。
- [p5-31] 制度、评测与指标咬合在一起，城市才能长久健康地呼吸。

## P6 路线图与理性落点

> 画面：四级演进阶梯依次点亮（P0 机制验证绿勾 ✔ → P1 最小服务 → P2 信任自纠 → P3 互操作）。

- [p6-01] 总结我们的建造历程，蓝图设计了一条清晰的四阶演进路线。

- [p6-13] 循序渐进，拒绝一开始就搞过度治理的空心蓝图。
- [p6-14] 第三，大模型技术还在一日千里地向前狂奔。

- [p6-18] 记住那句警醒全行业的工程箴言。
- [p6-19] 在含义真正被严肃治理好之前，AI 展现出来的所有聪明，都只是从概率里租来的。
