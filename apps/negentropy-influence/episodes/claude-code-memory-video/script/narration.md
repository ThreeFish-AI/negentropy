# 逐字稿：记忆管理：会丢的和不能丢的（v2，已过双重校验与成文优化）

> **格式约定**：`- [句id] 口播文本`——每行一句，一句 = 一条字幕 = 一段配音；幕内空行 = 一个 beat（分镜一镜）。
> `>` 引用块为画面备注，不进配音；英文标识符只进画面角标不进口播（例外：Claude Code／Harness；跨会话记忆／会话记忆的英文名走角标补名）。
> **断言回溯**：事实源 = [research/source-notes.md](../research/source-notes.md)，各 beat 备注以「回溯：§…」锚节号（§一＝压缩章／§二＝记忆章，章号不进观众层）——回溯不到的内容不进口播。
> **证据分级**：【三】断言口播带归属句（「这个开源项目的作者拆过真实实现后说」）；【官】断言带「官方文档明写／说／确认」；【一】【二】直接断言。
> **纪律**：口播零信源站标识（称信源一律「这个开源项目」）；双轨口径——机制断言钉教学版（占位符为「重跑提示」型、不携磁盘指针；先落盘再占位的顺序不变式；扉页派生重建；两层加载讲做一致），主线演进只在 P6 彩蛋段限定「后来又改了一版」；活数据（触发条数／保留窗口／长度门槛／字符上限）不进口播；反串线——口播不出现他集标题与顺序词，收尾只用「下期」；类比恪守工坊剧场角色单射（170 §2 台账），「桌子」一词禁用；画面文字只放关键词／数字／标签。
> **SSOT 下游**：本稿定稿后，TTS（story 档）、字幕、分镜（Stage ⑥）、动画与 QA 全部由本稿派生；改稿先回本稿再重派生。

## P1 收台四步

> 画面：3D 台面堆高母题一现（solids 堆叠）→ 收台工剪影上场（mech 绿）；字卡「上下文总会满，要有办法腾地方」。角标：`context window`。回溯：§一·定位与标语（章标语／四层压缩管线＋一条应急）

- [p1-02] 上下文总会满，要有办法腾地方——这一章的标语，原文如此。
- [p1-03] 教学版给了四层手段，还编了号：裁中段、压条子、搬仓库、请记录员。
- [p1-04] 四层一个脾气：便宜的先跑，贵的后跑。
- [p1-05] 前三层是纯文本活，一次模型调用都不花。
- [p1-06] 第四层才花一次调用，把整段历史收成一份摘要。

> 画面：archify compact-pipeline（workflow，全屏独占）——讲课编号列（灰置）与实序列对撞（budget → snip → micro → auto 逐拍点亮）；成本列 0/0/0/1。角标：`budget → snip → micro → auto`。回溯：§一·M-7（code.py:469-471 三连＋README「讲解编号」自白）

- [p1-07] 编号是讲课的顺序，干活却是另一套顺序。
- [p1-08] 真实执行，先搬仓库，再裁中段，再压条子，最后才请记录员。
- [p1-10] 这个顺序还不能换，下一幕专门讲为什么。

> 画面：四层速览小卡横排（裁中段保头尾／压条子／搬仓库留取货条／记录员摘要）；archify pair-guard（state，全屏独占）——工序卡与回单成对；切点向两侧让开动效；孤立回单 → 下一趟货单 deny 红叉。角标：`[snipped N messages]`、`tool_use ↔ tool_result`。回溯：§一·M-1（snip 保头尾＋边界保护）、M-5（reactive 尾切点同约束）、M-2/M-3/M-4（三层速览）

- [p1-11] 快速过一遍这四层。
- [p1-12] 裁中段：消息太多时，保住开头的交代和手头的活，中间整段掐掉。
- [p1-13] 压条子：师傅看过的旧工具结果，换成一<行|HANG2>小字。
- [p1-14] 搬仓库：最新一批结果太占地方，从最大的开始写进磁盘，台面只留取货条。
- [p1-15] 记录员：三层用尽还放不下，才轮到他动笔。

- [p1-16] 裁剪有一条铁律：请求和回执，必须同去同留。
- [p1-17] 模型递出的一张调用，和紧跟其后的那份结果，绝不能拆散。
- [p1-18] 留下孤零零的回执，下一趟请求本身就不合法，直接被拒。
- [p1-19] 所以切点宁可向两侧让开，多留一点，也不碰这对搭档。
- [p1-20] 一句话：裁剪可以丢内容，不能丢结构。

> 画面：常量打码卡（触发条数／保留窗口／长度门数值全打码，「随版本漂移」标签）；顺序与铁律恒亮。回溯：实测总表·数字纪律（口播不引绝对值与漂移常数）

- [p1-21] 至于每层触发的条数、保留的窗口，随版本漂移，不细抠。
- [p1-22] 稳定的是顺序和铁律，不是数字。

## P2 指针换空间

> 画面：archify pointer-trade（dataflow，全屏独占）——批次总账 → 超预算 → 按大小降序落盘 → 包裹标签（磁盘地址＋预览）回填台面。角标：`<persisted-output>`、`Full output:`、数字卡「预览 2000 字符」。回溯：§一·M-3（只统计最后一条 user 消息／超预算按大小落盘／标记＋预览）

- [p2-01] 把镜头拉近最有讲究的一步：搬仓库。
- [p2-02] 它只盯最新一批工具结果，算一笔总账。
- [p2-03] 超了预算，按大小排队，从最占地方的开始写进磁盘。
- [p2-04] 台面上只留一张包裹标签：磁盘地址，加一段两千字的预览。
- [p2-05] 模型看到标签，就知道全文在磁盘上，随时能再读回来。

> 画面：占位符化——旧条子滑出最近窗口 → 压扁成一行；引语卡（mono 引语态）占位符原文整行。角标：`[Earlier tool result compacted. Re-run if needed.]`。回溯：§一·M-2（最近窗口豁免／长度门／占位文本；**占位符形态＝本钉点重要事实：不携路径**）

- [p2-06] 另一层是压条子：滑出最近窗口的旧结果，压成一<行|HANG2>通用提示。
- [p2-07] 这<行|HANG2>字的原文是：更早的工具结果已压缩，需要的话重跑一遍。
- [p2-08] 注意，这<行|HANG2>提示上没有磁盘地址——本版教学实现的关键事实。
- [p2-09] 它赌的是可重放：活还能再跑一遍，不是存档还找得回来。

> 画面：顺序力学卡——「先落盘再压条」ok 绿勾 vs 「先压条再落盘」deny 红叉（破坏＝永久丢失）。角标：`顺序不能换`。回溯：§一·M-7（README 引语「budget 必须在那之前把完整内容落盘」）

- [p2-10] 所以顺序才不能换：压条子是破坏性替换，原文字一压就没。
- [p2-11] 搬仓库必须赶在它前面，把完整内容先送上磁盘。
- [p2-12] 先抄地址，再扔东西——破坏才不等于永久丢失。

> 画面：找不到的路演示（「教学版」徽标限定）——落盘过的取货条随大结果一起滑出窗口 → 取货条本身被压成通用提示；右侧磁盘仓库原件仍在（dim 灰置，无路径连线），deny 红「无路可达」标注。回溯：§一·M-2（已在 L3 落过盘的大结果滑出窗口同样被压成通用提示、指针随之消失、磁盘文件仍在）

- [p2-13] 这个赌注有输的时候，教学版里就能看到。
- [p2-14] 已经搬进仓库的大结果，连同它的取货条，一起滑出了最近窗口。
- [p2-15] 取货条一压，就变成那<行|HANG2>没有地址的通用提示。
- [p2-16] 磁盘上的原文还在，台面上却已经没有路能找到它。

> 画面：archify compact-entries（lifecycle，全屏独占）——三条常用入口＋应急车道（拒收后触发／保尾五条／只救一次）；尺子不准小卡（字符估算刻度偏差）。角标：`compact`、`[auto compact]`/`[reactive compact]`、`estimate`。回溯：§一·M-5（reactive：保尾 5 条／重试上限 1 次／异常外抛）、M-6（compact 工具：第 9 个工具／回执／开新一轮）、M-7（字符数估算）

- [p2-17] 压缩的入口不止一个。
- [p2-18] 自动：每轮调用模型前先过一遍预处理，超了才动手。
- [p2-19] 主动：工具清单里专门备了一个压缩工具，模型自己可以请。
- [p2-20] 调用它，这一轮到此为止，拿压缩后的上下文开新一轮。

- [p2-21] 还有应急通道：接口已经拒收了，才触发。
- [p2-22] 它反而温和些，保留最近五条原文，只总结更早的历史。
- [p2-23] 但只补救一次，再失败就直接抛异常，不无限循环。
- [p2-24] 为什么总得留一条应急？因为尺子不准。
- [p2-25] 估算拿字符数当用量；内容涨得比压缩动手还快，接口照样拒收。

> 画面：官方对照卡（官方文档页样＋中文摘要三行）；子代理侧间小工位一闪（无收台工）。角标：`/compact`、`subagent`。回溯：§一·官方文档对照 23/24/25/26【官】＋M-7（子代理不参与压缩）

- [p2-26] 官方文档确认：接近上限会自动压缩，手动触发是同一套机制，阈值还能自己调。
- [p2-28] 官方也讲同一套次序：先清旧的工具输出，再摘要——只是不给各层起名字。
- [p2-29] 顺带一句：子代理不参与压缩，它有自己的台面，轮数有上限。

## P3 压缩即遗忘

- [p3-01] 台面腾出来了，代价也到账了。
- [p3-02] 摘要留得住目标，留不住口味。

- [p3-09] 对模型当下的推理来说，细节已经不在上下文里了。

## P4 登记簿与扉页

> 画面：工坊右缘登记簿物件开张（mech 绿）；一文件一记忆卡——头部（名字／说明／类型）＋正文；同名即同文件动效。角标：`.memory/`、`name / description / type`。回溯：§二·M-1（存储不变式／slug 化同名同文件）

- [p4-01] 工坊的右手边，添了一本登记簿。
- [p4-02] 一条记忆，簿里一个文件：头部记名字、说明、类型，正文写内容。
- [p4-03] 文件名从名字派生，同名就是同一个文件，天然去重。
- [p4-04] 它不放台面上：压缩管不着，会话清空也带不走。

> 画面：LottieEmphasis page-flip 扉页翻页脉冲；archify memory-ledger（architecture，全屏独占）——写一页 → 扉页全量重排（索引条目逐行重生成）。角标：`MEMORY.md`。回溯：§二·M-1（索引从全部文件全量重建；索引派生物／文件事实源）

- [p4-05] 登记簿的扉页是张目录，一<行|HANG2>一条，写名目和一句话说明。
- [p4-06] 这张扉页不是手写的。
- [p4-07] 每写一页，扉页就从所有文件从头重排一遍。
- [p4-08] 索引是派生物，文件才是事实源。

> 画面：archify four-memory-types（dataflow，全屏独占）——四问卡：你是谁／怎么做事／正在发生什么／东西在哪找。角标：`user / feedback / project / reference`。回溯：§二·M-2（四类表格逐字）＋官方文档对照 12【官】（四类口径一致）

- [p4-10] 记忆分四类，按回答什么问题划分。
- [p4-11] 你是谁，是偏好；怎么做事，是反馈。
- [p4-12] 正在发生什么，是项目动态；东西在哪找，是线索。

> 画面：archify two-layer-loading（dataflow，全屏独占）——双轨：扉页常驻垫纸（前缀锁定＋缓存命中动画）／正文按需注入当前轮（拷贝拼接，真实对话列表原样）。角标：`system prompt` / `user turn`、`<relevant_memories>`。回溯：§二·M-3（索引常驻 SYSTEM）＋M-5（按需注入当前 user turn／拷贝不污染／缓存动机）

- [p4-15] 扉页目录常驻垫纸，每一轮都摊开在开头。
- [p4-16] 正文按需进当前轮：开工前挑出相关几页，拼进这一次的请求。
