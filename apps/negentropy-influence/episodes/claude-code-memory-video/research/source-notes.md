## 一、s08 Context Compact —— 上下文总会满，要有办法腾地方

### 定位与标语
- 【二】标语「上下文总会满，要有办法腾地方」；Harness 层「压缩——干净的记忆，无限的会话」。

### 问题（原文，轨 A）
> 【一】「读了一个 1000 行的文件，又读了 30 个文件，跑了 20 条命令。每条命令的输出、
> 每个文件的内容，全都堆在 messages 里。窗口满了，API 直接拒收（prompt_too_long）。」

### 机制【一】四级腾位（便宜的先跑，贵的后跑——README 核心设计原则）
1. **裁中段**：消息超 **50 条** → 保留头部 **3 条**（初始任务）+ 尾部 **47 条**（当前工作），
   中间裁掉留一行占位符；唯一边界条件：不许把「请求」和「回执」拆开。
2. **旧结果占位**：只保留最近 **3 条**工具结果的完整内容；更旧且超 **120 字**的替换为一行
   「Earlier tool result compacted. Re-run if needed.」
3. **大结果落盘**：最后一条用户消息里的结果总量超 **200KB** → 按大小排序从最大的开始落盘，
   上下文只留标记 + 前 **2000 字**预览。
4. **全文摘要**：前三层跑完仍超阈值 → 先把完整对话写进转录文件（保底），再请模型写摘要
   （保留目标/发现/已改文件/剩余工作/用户约束五类信息），**全部旧消息换成这一张摘要**。
   连败 **3 次**熔断。
- **应急通道**：API 已经拒收后的抢救——保留最近约 **5 条**原始消息、只摘要更早历史；
  重试上限 **1 次**，再失败就抛出（完整恢复逻辑在 s11，本集不展开）。
- ★ **顺序不可换（本集第一深挖点·正确性论证）**：落盘必须先于占位——占位会把旧的大结果
  换成一行字，落盘若在后，就再也找不到原文可存了。README 原话：「顺序不能换。」
  （编号线：budget → snip → micro，README 明示。）

### 生产版对照【三】
- 真实执行顺序五步（`query.ts:379-468`）：budget → snip → **collapse**（教学版无）→ … auto；
  教学版顺序与 CC 的前三步一致（课程作者核对过）。
- 裁中段在 CC 仅主线程启用、实现不在开源仓库（feature gate），接口可见；3/47 是简化参数。
- 摘要 prompt 的两条硬性纪律：**首尾各一遍「只回文字，绝不许调工具」**；先在分析标签里
  理思路、再在摘要标签里出正式摘要，分析段在格式化时被剥掉。
- ★ **压完还往回捞（本集第二深挖点）**：compact 后自动重新附加最近读过的文件——最多
  **5 个文件、每个 5K、总预算 50K**（`compact.ts:122-124`）；未变化的文件重读返回占位桩
  （`FILE_UNCHANGED_STUB`），靠 readFileState 缓存判定。
- 阈值不是字符估算而是精确 token：`contextWindow − maxOutputTokens − 13000`（`autoCompact.ts:62`）。
- 还有两条教学版没展开的机制：contextCollapse（独立上下文管理系统）、sessionMemoryCompact
  （compact 前先试用已有会话记忆做轻量摘要，不调模型——s09 回收讲）。
- 时间型微压缩：每 **60 分钟**一轮（`timeBasedMCConfig.ts`）——一句带过。

## 二、s09 Memory —— 压缩会丢细节，要有一层不丢的

### 定位与标语
- 【二】标语「压缩会丢细节，要有一层不丢的」；Harness 层「记忆——跨压缩、跨会话的知识积累」。

### 问题（原文，轨 A）
> 【一】「『用 tab 缩进不要用空格』可能被简化成『用户有代码风格偏好』。而且新开一个会话，
> 连摘要也没了。」——本集最痛的一句，作 P3→P4 转折。

### 机制【一】不进碎纸机的本子
- **存储就是文件系统**：一个记忆一个 Markdown 文件（frontmatter 三字段：name / description /
  type），外加一个索引文件（一行一条链接）常驻基本设定。**没有数据库。**
- 四类记忆【一】：user（你是谁：「用 tab 不用空格」）/ feedback（怎么做事：「别 mock 数据库」）/
  project（在发生什么：「这次重写是合规驱动」）/ reference（去哪儿找：「那个 bug 在 Linear INGEST」）。
- **取：两条路径**——索引常驻（每轮可见清单）；按需注入：把最近对话+记忆目录一起发给模型
  做一次**旁路小问**，挑出真正相关的，**最多 5 条**；拿不准就别挑；旁路失败降级为关键词匹配。
- **写：每轮结束后提取**——对话告一段落时（模型停下且无工具调用），从**最近 10 条对话**提取
  新偏好/约束/事实；先查已有记忆防重复；确实没有新东西就返回空。
- **整理：攒 10 份触发合并**——让模型去重、合并矛盾、淘汰过时。

### 生产版对照【三】（本集第三深挖点）
- 挑记忆的就是 **Sonnet 本身**（`findRelevantMemories.ts`）——不是向量相似度；指令原话
  「根据名称和描述选出真正有用的（最多 5 个）。不确定就不要选。」
- ★ **提取发生在轮末、取的是压缩前快照**：课程作者说产品里由停机钩子 fire-and-forget 触发
  （`stopHooks.ts:141-155`），forked agent 执行、受限权限、最多 5 回合、不进对话——
  「先抢救、再碎纸」的时间铰链（教学版同样取 pre_compress 快照【一】）。
- ★ **「做梦」（Dream）四道闸**（`autoDream.ts`）：距上次合并 ≥ **24 小时**；扫描节流；
  自上次以来改过 ≥ **5 个会话记录**；**文件锁**（没有别的进程正在合并；锁的修改时间兼作
  「上次合并时间」，崩溃后 **1 小时**自动过期）。教学版简化为「攒 10 份」。
- 索引约束：最多 **200 行 / 25KB**；注入预算：每文件 **200 行 / 4096 字节**、每会话总 **60KB**；
  扫描上限 **200 个**文件按修改时间降序。
- sessionMemoryCompact 阈值三件套：≥10K token、≥5 条文本、≤40K token 才不调模型（`56-61`）。
- 存储位置：`~/.claude/projects/<项目>/memory/`（按项目分目录）。

## 三、跨章主线

- 两章是一个问题的两半：**桌面上的会丢（压缩有损），登记簿里的不丢（文件无损）**。
- 时间线咬合：轮末提取取压缩前快照 → 压缩碎纸 → 索引常驻 + 按需捞回。
- 系列锚：环在本集出场于「压缩瞬间」——环照转，桌面被换掉一茬纸（不变 vs 可弃的对照）。

## 六、站点可视化文字规格（供 Remotion 概念重建）

1. **Compact Layers（s08）**：四级操作梯从矮到高（裁中段→占位→落盘→摘要），每级标注代价
   （0 API×3 → 1 API）；顺序箭头锁死。
2. **Window Fill（s08）**：玻璃容器被色块灌满至「拒收」墙；腾位后液面下降。
3. **Memory Overview（s09）**：桌旁一本登记簿（只进不出）+ 索引页常驻；碎纸机在旁但
   永远轮不到登记簿。
4. **Memory Subsystems（s09）**：取（旁路小问）/ 写（轮末提取）/ 整（做梦合并）三子系统。

## 七、口播禁用清单（本集）

1. 绝对行数 / 200KB / 13000 / 60KB 等精确常量不进口播（「一大批」「限量的」+ 角标精确值）。
   「50 条保头 3 尾 47」「最近 3 条」「120 字」「2000 字预览」「5 条记忆」「10 份合并」
   「24 小时」「5 个会话」「1 小时过期」属可记忆量，可保留。
2. 不出现他集标题与顺序词；「上一集那张桌子」禁用——本集自行一句重立「一张会塞满的桌子」。
3. 英文标识符不进口播（snip/micro/budget/compact/Dream/FILE_UNCHANGED_STUB → 中文白话 +
   角标）；「做梦」一词的英文原名只进角标。唯一例外 Claude Code。
4. 【三】断言（Sonnet 挑记忆 / 停机钩子时机 / 四道闸 / 回捞预算 / 摘要 prompt 纪律 /
   精确 token 公式）必带归属句。
5. 排版陷阱：`2026 年` 类空格年禁写；「行」（一行/xíng）多音字场景待试听后按协议标注。
