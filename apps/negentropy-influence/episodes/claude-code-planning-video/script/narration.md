## P0 五个失败现场

> 画面：系列片头 HarnessStack 五层栈自底向上落板，第二层点亮呼吸后缩为顶边常驻条；五失败分格蒙太奇（丢计划/淹没/全带/打架/崩溃）；末拍全景图首亮。回溯：§1 失败现场表；§2 定位与全景

- [p0-01] 能用工具的循环跑起来了，新的问题也跟着来了。
- [p0-02] 任务一长一变复杂，它会用五种方式失灵。

- [p0-03] 第一种，丢计划。
- [p0-04] 十步的重构任务，两三步一做，就开始即兴发挥。
- [p0-05] 计划只写在开头那句话里，工具结果一涌进来，就把它挤出去了。

- [p0-06] 第二种，过程淹没主线。
- [p0-07] 修一个缺陷，读三十个文件、聊六十轮，消息涨到一百二十条。
- [p0-08] 大半是追踪过程，跟最终目标没关系。

- [p0-09] 第三种，知识全带太贵。
- [p0-10] 三份规范六千五百<行|HANG2>全塞进指令，改个颜色也整包带着。
- [p0-11] 第四种，指令越堆越多，互相打架。
- [p0-12] 第五种最干脆：接口一过载，程序直接崩。

- [p0-13] 五种失败，病根是同一个。
- [p0-14] 模型每轮能看到的，就是发给它的那串消息列表，也叫上下文。
- [p0-15] 它看到的，和它此刻需要的，错位了。
- [p0-15b] 上下文是模型唯一的记忆，又是稀缺资源：塞多了稀释注意力，塞少了缺信息。
- [p0-15c] 更麻烦的是，模型自己看不见自己的忘性。

- [p0-16] 修法不是换更聪明的模型，而是改供给。
- [p0-16b] 这层管的东西，<行|HANG2>话叫视野：模型每一轮看到的全部内容。
- [p0-17] 在循环的五个固定位置，挂上五个装置。
- [p0-18] 计划要看得见，大过程要挪出去，知识要按需进场。
- [p0-19] 指令要按实况拼装，管线断了要分类自愈。
- [p0-20] 接下来，五个挨个拆开看。

> 角标：TodoWrite / Subagent / Skill Loading / System Prompt / Error Recovery（装置名对应五挂点）

## P1 计划回到视野

> 画面：全景图回照挂点①高亮后放大；工序卡钉上台面边（三态渲染）；计数器刻度环；类型注解任务五轮走查；拆清零消融对比（红/绿）。回溯：§3 M1；D1

- [p1-01] 先修丢计划。
- [p1-02] 给模型一个待办工具，让它把步骤列成带状态的清单。

> 角标：todo_write

- [p1-03] 三种状态：待办、进行中、已完成。
- [p1-04] 这个工具不做任何实际工作，不能读文件，也不能跑命令。
- [p1-05] 它给的不是执行能力，是规划能力。

- [p1-06] 但模型干得起劲，会忘了更新清单。
- [p1-07] 循环里挂一个计数器：连续三轮没碰待办，下一轮开头就注入一条提醒。
- [p1-08] 提醒以用户消息的身份进消息流，跟着历史走，不常驻。

- [p1-09] 拿一个任务走一遍。
- [p1-10] 输入：给一批文件补类型注解，再加注释，最后加入口守卫。
- [p1-11] 第一轮，模型先交出三项计划，计数器随即清零。
- [p1-12] 第二轮改文件，第三轮跑测试，第四轮修失败，计数器涨到三。
- [p1-13] 第五轮开头，提醒注入，模型回头看清单，把第一项标成完成。

- [p1-14] 这套提醒可靠吗？拆开看。
- [p1-15] 拿掉「更新即清零」这一<行|HANG2>，同样的任务，提醒从零次变成一次误报。
- [p1-16] 模型明明更新过计划，还是被唠叨了。
- [p1-17] 复位和置位同等重要，这是拆装实测的结论。
- [p1-17b] 顺带交代：三轮这个数是教学发明，教程作者拆过源码，说那边没有固定轮数。

- [p1-18] 边界也要说清：清单存在内存里，进程一退就没了。
- [p1-19] 它管计划可见，不管任务持久——那是别层装置的事。
- [p1-20] 计划留住了，大过程还在往主线上灌，下一个装置接它。

## P2 大过程挪出去

> 画面：全景回照挂点②；主线/副台双泳道时序（fresh messages 特写）；回执一页；门禁卡+共享盘意象；SUB_TOOLS 工具表无 task；查测试框架走查；19↔2 标尺消融。回溯：§4 M2；D2

- [p2-01] 第二种失败，过程淹没主线。
- [p2-02] 人遇到这种事，会开个新终端去追，追完把结论写进笔记。

- [p2-03] 程序给模型同样的能力：一个任务工具，把一件事整段委托出去。
> 角标：task

- [p2-04] 被委托的子代理，拿到一段全新的消息列表，自己跑自己的循环。
- [p2-05] 跑完只交回最后一句话，中间读了什么、做了什么，全部丢弃。

- [p2-06] 像请一位外包顾问：自带笔记本记过程，最后只交一页结论。
- [p2-07] 但他刷的是公司的门禁卡，交付物留在公司共享盘。
- [p2-08] 类比到此为止——顾问是另一个人，子代理是同一段程序的另一场对话。

- [p2-09] 所以「隔离」这个词要掰直：隔离的是记忆，不是权限。
- [p2-10] 消息史不共享，安全钩子照跑，文件改动保留。
- [p2-11] 危险命令在副台上，同样会被拦下。

- [p2-12] 那能不能委托之后再委托？干脆不给这个能力。
- [p2-13] 子代理的工具表里没有任务工具，链条到这一层就断。
- [p2-13b] 副台还有一道保险：跑满三十轮就强制收工。
- [p2-14] 指令里也写了不要再委派，但那只是双保险。
- [p2-14b] 最后一句话若是停在半截的，程序向前回溯，找回最近一条完整结论。

- [p2-15] 走一遍：让子任务去查，这个项目用什么测试框架。
- [p2-16] 子代理开新列表，两轮：先读配置文件，再看测试目录。
- [p2-17] 最后只回一句结论，主线从一条消息变成两条。
- [p2-18] 同一件事不隔离，八轮过程全灌主线，消息涨到十九条。
- [p2-19] 十九比二，这就是隔离的价值。
- [p2-20] 副台折掉了过程，接下来轮到知识进场。

## P3 知识按需进场

> 画面：全景回照挂点③；工具柜抽屉（标签 vs 手册）两级装置；SQL 规范走查（目录→点名→全文进场）；注入位置生命周期（指令区常驻/消息流可裁）；128→5981 标尺消融。回溯：§5 M3；D3

- [p3-01] 第三种失败，知识全带太贵。
- [p3-02] 每个任务需要的知识不一样，全塞指令区就是白花钱。
- [p3-03] 解法是两级：目录常驻，全文按需。

- [p3-04] 目录这级：每个技能一张标签，写名字和一句描述。
- [p3-05] 标签常驻指令里，教程作者估算，每个只要上百个 token。
- [p3-06] token，模型的计字单位，先记个粗略印象就行。
- [p3-07] 抽屉里的手册，等你点名要了才整本取出，作者估算每本约两千个。

- [p3-08] 走一遍：技能目录里，躺着一份数据库规范。
> 角标：load_skill / SKILL.md

- [p3-09] 启动时扫描所有抽屉，标签进目录，模型每轮都看得见自己有什么技能。
- [p3-10] 模型说要这份规范，点名加载，登记名单按名字命中。
- [p3-11] 全文作为一条工具结果进消息流，这一轮才付全价。

- [p3-12] 位置决定命运：目录在指令区，每轮常驻。
- [p3-13] 全文在消息流里；这份列表有容量上限，窗口一满要腾地方，它可能先被裁掉。
- [p3-14] 裁掉也不慌——目录还在，再点一次名就能取回。
- [p3-14b] 注册表还有两个边界行为：两个技能声明同一个名字，后放的会静默覆盖先放的。
- [p3-14c] 运行期新放的技能，旧注册表也看不见，这是拿安全换来的，不是坏法。

- [p3-15] 拆掉两级试试：把全文直接塞进指令区。
- [p3-16] 一份技能，系统指令从一百二十八字符，涨到五千九百八十一。
- [p3-17] 放大约四十七倍，而且每一轮都要带。
- [p3-18] 结论一句话：常驻的只能是索引，不是知识本体。
- [p3-19] 知识管住了，指令自己却越滚越大，下一个装置管它。

## P4 指令按实况拼装

> 画面：全景回照挂点④；垫纸=运行时产物；分段货架（identity/tools/workspace/memory）按真实状态拼装；README 对话走查（三段→命中→四段）；确定性键示意；5 组装/0 命中标尺消融。回溯：§6 M4；D4

- [p4-01] 第四种失败，指令堆积打架。
- [p4-02] 每加一个能力就堆一段，换项目要重写，改一处怕碰坏别处。
- [p4-03] 翻转思路：指令别当文档写，要当运行时拼装的配置。

- [p4-04] 像每日菜单：招牌菜永远印，时令菜看今天有没有货，现场拼一页。
- [p4-05] 食材没变，就直接用昨天打印好的那页——这就是缓存。
- [p4-06] 类比到这里：它不覆盖分段维护，也不覆盖服务端那层缓存。

- [p4-07] 实现分两步：先分段，再按真实状态拼。
- [p4-08] 身份、工具、工作区，永远在；记忆段，看那个记忆文件在不在。
- [p4-09] 判断依据全是可查的系统状态，不在消息里搜关键词。
- [p4-09b] 分段还有个好处：各段独立维护，改工具段不碰身份段。

- [p4-10] 走一段对话：用户问，读一下说明文档。
- [p4-11] 状态里没有记忆文件，拼出三段。
- [p4-12] 紧接着再问一句，状态没变，缓存命中，直接返回。
- [p4-13] 用户让模型建了记忆文件，下一轮状态变了，重组装成四段。

- [p4-14] 缓存的键有讲究，把全部状态按固定顺序拼成一串字——同一份状态，永远拼出同一串字。
- [p4-15] 不用程序自带的编号方法——那套编号换次运行就变，还可能报错。

- [p4-16] 把键弄脏试试：往里掺一个每轮都变的成分。
- [p4-17] 同样连问五次，正常只组装一次，命中四次。
- [p4-18] 键被污染后，五次全部重组装，命中零次。
- [p4-19] 缓存的前提，是键确定。
- [p4-20] 还要分清：这层缓存省的是本地拼串，跟服务端的前缀缓存是两码事。
- [p4-20b] 前缀缓存补一句：让开头一段保持不变，服务端才能按开头复用。
- [p4-21] 四个装置管好了该看什么，最后一个管管线断了怎么办。

## P5 断了分类自愈

> 画面：全景回照挂点⑤；分诊口包住模型调用步；三路径分诊地图（截断/超限/瞬态）；账本 RecoveryState 翻页；429/529 双序列走查；8 次 vs 1 次标尺消融。回溯：§7 M5；D5

- [p5-01] 第五种失败最干脆：接口一过载，程序直接崩。
- [p5-02] 生产环境里，接口错误是常态，不是缺陷。
- [p5-03] 最后一个装置，把模型调用那一步整个包住，就地分诊。

- [p5-04] 像修打印机：没墨换墨盒再打，卡纸抽纸重打，连续断电才换备用机。
- [p5-05] 没有人对着断电的机器猛按打印键。
- [p5-06] 类比缺一块：打印机靠人分诊，这里靠代码按错误信号自动分诊。

- [p5-07] 三条恢复路径，各管一类错误。
- [p5-08] 输出被截断？第一次不保存半截，直接把上限从八千提到六万四，原样重发。
- [p5-09] 还截断，才保存半截并注入续写提示，至多三次。

- [p5-10] 上下文超限？应急压缩，只留最后五条消息，而且只允许一次。
- [p5-10b] 已经压过还超限，就直接退出，再压一次也不会更小。

- [p5-11] 限流或过载？指数退避，实测三连等：半秒多、一秒、两秒半。
- [p5-12] 连续三次过载，就切换备用模型。

- [p5-13] 走两段实测序列。
- [p5-14] 第一段：遇到限流，等半秒多重试，又限流，等一秒，然后成功。
- [p5-15] 第二段：连续三次过载，前两次各等一段，第三次切换模型再等一段，成功。
- [p5-16] 全程零人工介入。
- [p5-16b] 退避的等待里还要加一点抖动，免得一群请求挤在同一秒集体重试。

- [p5-17] 分诊口旁边还有一本账：升级用过没有，续写几次，压缩试过没有。
- [p5-18] 每一项都在回答：这一招还剩几次。
- [p5-19] 拆掉记账试试：同样连续超限，正常压缩一次就止损退出。
- [p5-20] 拆掉后反复压缩八次，每压一次都在丢消息。
- [p5-21] 不记账的恢复，会吃掉自己的病人。
- [p5-22] 五个装置到齐，回到全景收个总。

## P6 五条规律

> 画面：五规律金句条快闪（每条一拍）；开放争议双栏；护栏卡三行；系列五层身份卡+下期卡；工坊灯牌收暗。回溯：§10 规律与争议；§11 边界

- [p6-01] 五个装置背后，是同五条工程规律。
- [p6-02] 注入位置决定生命周期和成本。
- [p6-03] 判定只认真实状态，不做内容猜测。
- [p6-04] 隔离是过程级的有损压缩。
- [p6-05] 恢复资源有限，必须记账。
- [p6-06] 结构防线优于语言嘱咐。

- [p6-07] 留一个真开放的争议。
- [p6-08] 教学版给子任务全新上下文，图的是正确。
- [p6-09] 教程作者拆过真实产品的源码，按他的分析，那边构造缓存友好的前缀，图的是成本。
- [p6-10] 两派账本不同，都对——这是选址问题，不是对错问题。

- [p6-10b] 还有一对取舍：知识放消息流，省钱但会被裁掉。
- [p6-10c] 常驻指令区，稳定但每一轮都要花钱。
- [p6-10d] 没有免费午餐，只能按使用频率分档。

- [p6-11] 也有护栏要交代。
- [p6-12] 三轮提醒是教学发明；提醒到底提不提高完成率，没有对照实验。
- [p6-13] 那些篇幅估算，只是教程作者的口径，没给测量方法。
- [p6-14] 数字要分开看：退化倍数是拆装实测，估算数只当量级参考。
- [p6-14b] 顺带一个判断：把重试的耐心放大十倍，不会更稳，只会更糟，账本纪律管的就是这个。

- [p6-15] 循环没变，变的是挂在它身上的供给。
- [p6-16] 视野错位，就一个一个修正。
- [p6-17] 下期，聊聊哪些该丢，哪些不能丢。
