## P0 它没有「昨天」

> 画面：系列同款终端。任务进行中，最初的清单滚出可视区；走秒芯片持续跳动。
> 角标：TodoWrite · "An Agent Without a Plan Drifts Off Course"

- [p0-01] 你交给它一个大活，它干了三步，就忘了自己来干嘛。
- [p0-02] 根源有点吓人：它每来一轮，都把你们说过的话从头重读一遍——它没有昨天。
- [p0-03] 这一集拆管它视野的五样装置。其中一样，刚刚被官方收回去。
- [p0-04] 全部内容平铺在桌上，谁新谁旧全凭距离，最初那张任务单被越挤越远。
- [p0-05] 于是问题来了：它这一轮能看见什么，是它自己说了算吗？
- [p0-06] 答案：不是。有一整套装置，在替它安排视野。
- [p0-07] 写下来的清单，另开的副桌，按需翻开的目录，每轮重拼的垫纸，一张补救梯。
- [p0-08] 五样装置，一样一样拆开看。

## P1 把清单钉在桌上

> 画面：一张亮面桌子成为主舞台（系列环在桌后）。清单卡「啪」地钉进桌面。
> 角标：`todo_write` · 三态 pending / in_progress / completed

- [p1-01] 第一样东西最不起眼：一张写下来的清单。
- [p1-02] 干活之前，先把步骤一条条列出来，每条标一个状态：没开始、干着、干完了。
- [p1-03] 状态只有这三种，不多不少。干一步挪一格，桌子上的进度看得见摸得着。
- [p1-04] 这套做法听起来土得掉渣，土到你会怀疑它是不是真有用。
- [p1-05] 然后奇迹发生了——注意，这个工具本身，什么都不执行。
- [p1-06] 它不能读文件，不能跑命令，唯一的功能就是把清单写下来、摆到它眼前。
- [p1-07] 可正因为清单挂在对话里，每一轮重读的时候，它都会被再看见一次。
- [p1-08] 你以为它忘了，其实是那张纸被几十条工具输出顶到了视野之外。
- [p1-09] 把纸钉回眼前，注意力就回来了。就这么简单，也就这么管用。
- [p1-10] 加这个工具要改几处代码？两处。注册表里添一行，分发表里挂一行。
- [p1-11] 循环本身一行没动——这是我们这一集反复要数的事实。
- [p1-12] 有位作者的句话说得很准：这个工具不增加任何执行能力，
- [p1-13] 它增加的，是规划能力。
- [p1-14] 但这件装置刚刚被官方收了回去——新的模型上，清单工具默认不再安装。
- [p1-15] 官方理由很直白：这些模型自己就能记住要干什么。押注押到期了。
- [p1-16] 清单背后那套更重的任务系统——带依赖、能锁、落盘——那套以后单拆，先记一句：
- [p1-18] 把计划写下来，本身就是一种能力。而且是装在循环外面的能力。
- [p1-19] 一个什么都不执行的工具，成了长活不跑偏的关键——这种反差，后面还会遇到几次。

## P2 另开一张副桌

> 画面：主桌右侧滑出一张小桌（自带缩小克隆环），脏活全摊在副桌上；干完只带回一张回执卡。
> 角标：`task` tool · 全新 messages[] · 只回传结论

- [p2-01] 第二样，管的是另一种失控：活太脏，会把桌子整个占满。
- [p2-02] 比如追一个缺陷，要读三十个文件、翻六十轮对话。
- [p2-03] 等你找到问题在哪，桌上已经堆了一百多条记录，绝大部分是中间过程。
- [p2-04] 这些纸每一轮都被重读一遍，跟目标无关，但一直占着位置、一直计着费。
- [p2-05] 你自己遇到这种事会怎么办？开一个新终端去翻，翻完关掉，把结论记回本子上。
- [p2-06] 它也一样：另开一张干净的副桌，派一个分身过去干。
- [p2-07] 副桌上是一份全新的对话记录，干干净净，只有一句任务说明。
- [p2-08] 分身在那边自己跑自己的循环，读文件、改代码，跟主桌互不打扰。
- [p2-09] 主桌上你看不到那三十个文件的任何一行，只看得见它带回的一张回执。
- [p2-10] 干完，只把最后那条结论带回主桌。中间过程全部丢掉。
- [p2-11] 注意丢的是什么：写过的文件、改过的代码都还在硬盘上——丢的只是纸，不是活。
- [p2-12] 纪律第一条：教学版不许分身再派分身；官方放开了——最多三层，同时二十个。
- [p2-14] 第二条：分身每次动手之前，照样要过那几道闸门。
- [p2-15] 隔离的是视野，不是权限。它看不见你俩的对话，但它一样不能为所欲为。
- [p2-16] 官方文档后来证实了真实产品里的那个反转，
- [p2-17] 是这一集最反直觉的地方：产品里有一种分叉模式，动机根本不是隔离，
- [p2-18] 是为了省钱——命中缓存。
- [p2-19] 什么意思？对话按字数花钱；同样的开头算过一遍，短时间内第二遍近乎免费。
- [p2-20] 分身如果从头建立自己的桌面，前缀全变了，每一段都得原价重新算。
- [p2-21] 所以那套机制反着来：把父亲桌上的东西几乎原样搬给分身，让前缀保持一致。
- [p2-22] 「几乎」是有严格定义的：系统提示、工具表、模型、消息前缀、思考配置，
- [p2-23] 五样东西必须一字不差，缓存才会命中，钱才真的省下来。
- [p2-24] 隔离是搂草打兔子，省钱才是真心话。
- [p2-25] 还有更诚实的：隔离其实是半拉的。有位作者说，分身会继承父亲读过的文件，
- [p2-26] 免得同一个文件读两遍。桌是分开了，有些抽屉还是共用的。
- [p2-27] 分身要弹审批窗，也会冒泡弹到父亲的屏幕上，还是你来点头。
- [p2-28] 派出去慢慢干的玩法以后单说。
- [p2-28a] 官方还给分身套了三个上限，像三只笼子：同时在场最多二十个，
- [p2-28b] 每个有自己的轮数上限，还有整份上下文的配额——烧完就收工。
- [p2-28c] 放得开，也拴得住。副桌再多，也翻不出这三只笼子。
- [p2-29] 副桌这一样，记住一句：脏活不占主桌。
- [p2-30] 而它值得记住的第二句是：省钱和隔离，常常是同一个设计的两种说法。

## P3 目录卡与垫纸

> 画面：桌角一叠薄目录卡（~100 token 标价），旁边书架上厚手册（~2000 token）；
> 拉开手册时计价器跳字。随后四段垫纸逐轮拼装。
> 角标：`load_skill` · ~1% 上下文预算 · PROMPT_SECTIONS

- [p3-01] 第三样，管的是知识。规范、手册、风格指南，这些它干活前该知道的东西。
- [p3-02] 最笨的办法是把所有手册全贴进它的基本设定里。几百上千行，每轮都跟着计费。
- [p3-03] 你改一个颜色值，它在重读整个数据库规范——百分九十九的内容跟你无关。
- [p3-04] 解法是两级：桌角常驻一叠目录卡，每张卡就一行：这份手册叫什么、管什么。
- [p3-05] 一张卡的价钱，大约是整本手册的二十分之一。桌角摆一排，也不心疼。
- [p3-06] 真要用到哪本，再把整本拉上桌——而且整场常驻，压缩后还会重注入。
- [p3-07] 教学版的讲法很直白：目录常驻，内容按需。
- [p3-08] 官方口径：目录预算有硬顶——
- [p3-08a] 常规状态的这份纸，两三万字；极简模式整个两行。同一个人，两种铺法。
- [p3-08b] 官方还给了句实在话：清单超过两百行，它就开始不老实读了。
- [p3-09] 大约是窗口的百分之一，再设一个绝对上限，超了就砍。
- [p3-10] 还有个安全细节：取手册只认目录里登记过的名字，不走文件路径，防的就是目录穿越。
- [p3-11] 第四样东西，管的是桌面上那张最大的纸——它的基本设定本身。
- [p3-12] 你跟它说的每一句话之前，都垫着这么一张纸：你是谁、你在哪、能干什么。
- [p3-13] 从第一行代码起，这张纸就是写死的。能力越加越多，纸越写越长。
- [p3-14] 换个项目要重写整张纸，改一段可能跟别处打架，而且每轮都全文计费。
- [p3-15] 真实的做法：把这张纸拆成几段——身份、工具清单、工作目录、相关记忆。
- [p3-16] 每一轮，按当场的真实状态重新拼一次。状态变了，纸跟着变。
- [p3-17] 关键在「真实状态」四个字：工具就查实际注册了哪些，记忆就查文件存不存在。
- [p3-18] 不去猜消息里出现了什么关键词。猜关键词，是给幻觉开门。
- [p3-19] 状态没变，拼出来的纸一字不差，那就直接用上一次拼好的——拼本身也不重复花钱。
- [p3-20] 有人拆过它的源码——产品里这张纸常规状态有两三万字，
- [p3-21] 而极简模式整个就两行。同一个人，两种铺法。
- [p3-22] 他还说了个特别讲究的细节：所有段落里，只有一段永远不许进缓存——
- [p3-23] 外接工具的说明段。因为外接的服务随时会掉线，缓存它就是在缓存一个谎言。
- [p3-24] 你看，连「哪段纸可以复用」都是被精确设计过的。
- [p3-25] 这张垫纸，每轮都在拼，但它拼得比谁都勤俭。
- [p3-26] 目录、手册、垫纸——这三样都在回答同一个问题：这一轮，什么该进它的眼睛。

## P4 桌边的补救梯

> 画面：桌子右侧挂下一张三级补救梯；每级对应一类错误。等待条 0.5s→1s→2s→…→32s 封顶生长。
> 角标：max_tokens / prompt_too_long / 429·529 · min(500×2^n, 32s) + jitter

- [p4-01] 第五样，管的是意外。活干到一半出岔子，是生产的常态，不是事故。
- [p4-02] 第一种岔子：话说到一半，额度用完了，句子断在半空。
- [p4-03] 处理得很有章法。第一次，直接把额度上限放大八倍，原封不动重试同一个请求。
- [p4-04] 注意是原封不动：半句话先不存下来，就当无事发生，加够额度再来一遍。
- [p4-05] 放大只有一次。再断，才保存半句话，塞一条续写提示：从断掉的半个词接着说。
- [p4-06] 续写最多三次，三次还断就收手。有人拆过源码，把那条提示原文抄了出来，
- [p4-07] 特别有工程品味：别道歉，别复述你刚才在干嘛，直接接着说，把剩下的活切小点。
- [p4-08] 第二种岔子：桌上太满，装不下了，服务那边直接拒收。
- [p4-09] 先压一轮——把旧纸换成摘要腾地方；压完还装不下，就承认装不下，退出。
- [p4-10] 压过一次还压第二次没有意义：纸不会越压越小，该退就退。
- [p4-11] 第三种岔子最有意思：不是你的问题，是服务那边过载或者限流了。
- [p4-12] 最笨的反应是立刻重试——服务都趴了，你重试一百遍也是趴，还帮着踩了两脚。
- [p4-13] 等多久？不是拍脑袋。半秒、一秒、两秒、四秒——每次翻倍，封顶三十二秒。
- [p4-14] 这样最长的等待也就半分钟，而服务通常已经喘过气来了。
- [p4-15] 再撒一点随机抖动，免得全世界卡住的服务，同一秒一起冲回来把它再撞趴下。
- [p4-16] 对方要是好心理了个「稍后再来」的字条，就按字条上的时间等，比公式更快。
- [p4-17] 连着三次都过载呢？换人。切到备用模型，把没干完的活清一清，先干点小的。
- [p4-18] 有人分析过，产品里的恢复路径有十几种，教学版挑了最常见的三种讲；
- [p4-19] 他还提了一个很冷静的设计：续写要是连着几次都没写出新东西，
- [p4-20] 系统就直接判定——再续也没有产出，停。不恋战，也是一种能力。
- [p4-21] 出错不是终点。这话写在章首，也确实是这套系统的性格。
- [p4-21a] 官方还有个兜底的后悔药：改动可以回退到前面的检查点——
- [p4-21b] 不过它只看文件改动，跑过的命令改过的外部状态，不在里面。
- [p4-22] 你会发现每一级补救都带着上限：升一次、续三次、等三十二秒、换一次人。

## P5 桌子换了五样，环没动

> 画面：五样装置在桌上归位成一组；环从桌后浮到前景（系列锚第二次出场），桌子淡为线稿。
> 角标：五章增量全部为「外挂」· while 骨架未换（实测 @ 67a9126c）

- [p5-01] 收个尾。这一集的五样东西摆在一起看：
- [p5-02] 钉在桌上的清单，另开的副桌，按需翻开的目录，每轮重拼的垫纸，桌边的补救梯。
- [p5-03] 它们管理的是同一件事：这一轮，模型能看见什么。
- [p5-04] 清单负责「别忘」，副桌负责「别堵」，目录负责「别贪」，
- [p5-05] 垫纸负责「别写死」，梯子负责「别断」。
- [p5-06] 别忘、别堵、别贪、别写死、别断——五句话合起来，就是视野管理。
- [p5-07] 你会发现一个熟悉的形状：这些装置没有一样是写进循环里的。
- [p5-08] 清单是一个工具，副桌是一次调用，目录是一张注册表，
- [p5-09] 垫纸是一次拼装，梯子是一层包裹。全部挂在循环外面。
- [p5-10] 循环自己呢？我把这几章的代码逐一比过：
- [p5-11] 加催更计数、加派活工具、加目录扫描、加一层试错包裹——每一处都是外挂，
- [p5-12] 那句「不停问模型」的骨架，一个字没换。
- [p5-13] 视野越管越细，桌子越换越讲究，桌子后面那个循环纹丝不动。
- [p5-14] 所以它干活越来越稳，不是它变聪明了。
- [p5-15] 是有人替它把视野管了起来。
- [p5-16] 而管视野这件事，本身就是一门可以被看懂的手艺。

## P6 落点与信源

> 画面：一句话合同金句卡 → 信源卡（官方文档+取数日期 / 第三方源码分析已逐处标注）→ 系列身份卡 → 渐黑。
> 渐黑窗口从末 beat 总时长推导（红线四）。

- [p6-01] 视野是安排出来的。安排它的，不是模型自己。
- [p6-02] 这句话对人也成立：你的注意力在哪，多半也不是你自己定的，
- [p6-03] 是你桌上摆了什么、谁在什么时候塞了张纸给你。
- [p6-04] 五样零件里，清单那件刚被收回去——零件押的是「模型记不住」的赌注。
- [p6-05] 模型变强，赌注就过期。官方留了句自省的话：常问自己，可以停掉哪一件。
- [p6-06] 桌子会换，零件会瘦，那个循环一直没停过。
- [p6-07] 本片机制依据官方文档，取数2026年8月，以官方最新表述为准。
- [p6-08] 涉及产品内部的部分，为第三方源码分析，片中已逐处标注。
- [p6-09] 下期，拆管记忆的那一层：桌面太满怎么收拾，什么必须留下。下期见。
