## P0 它没有「昨天」

> 画面：系列同款终端。任务进行中，最初的清单滚出可视区；走秒芯片持续跳动。
> 角标：TodoWrite · "An Agent Without a Plan Drifts Off Course"

- [p0-01] 你交给它一个大活。它闷头干了三步，回头一看，忘了自己是来干嘛的。
- [p0-02] 根源有点吓人。它每跑一轮，都把你们说过的话从头重读一遍。它没有昨天。
- [p0-03] 今天要拆的是五样装置，管的全是它的视野。其中一样，刚被官方收回去了。
- [p0-04] 问题出在桌上。内容全平铺，谁新谁旧全凭距离。最初那张任务单被越挤越远。
- [p0-05] 它看见什么，它说了算吗？
- [p0-06] 不算。是有人替它安排的。
- [p0-07] 钉住的清单，另开的副桌，按需翻的目录，每轮重拼的垫纸，还有一张补救梯。
- [p0-08] 官方把 Harness 定义成四件：循环、工具、上下文管理、护栏。
- [p0-09] 今天补的就是上下文管理的前半：这一轮，它到底能看见些什么东西。

## P1 把清单钉在桌上

> 画面：一张亮面桌子成为主舞台（系列环在桌后）。清单卡「啪」地钉进桌面。
> 角标：`todo_write` · 三态 pending / in_progress / completed

- [p1-01] 第一样东西最不起眼，说白了就一张纸。一张自己写下来的清单。
- [p1-02] 干活之前，先把步骤一条条列出来，每条标一个状态：没开始、干着、干完了。
- [p1-03] 状态就这三种，不多不少。干一步挪一格，桌子上的进度看得见摸得着。
- [p1-05] 怪就怪在这儿了。这个工具本身，什么都不执行。
- [p1-06] 它不能读文件，不能跑命令。它唯一干的那件事，就是把清单摆到自己眼前。
- [p1-07] 可清单是挂在对话里的。每一轮从头重读的时候，它都会被再看见一次。
- [p1-08] 你以为它忘了。其实是那张纸，被几十条工具输出顶到了视野之外。
- [p1-09] 把那张纸钉回它眼前，注意力就回来了。就这么笨，也就这么管用。
- [p1-10] 加这个工具，要改几处代码？两处。注册表里添一行，分发表里挂一行。
- [p1-11] 循环本身，一行没动。
- [p1-12] 有位作者的一句话说得特别准：这个工具不增加任何执行能力，
- [p1-13] 它增加的，是规划能力。
- [p1-14] 但这件装置刚刚被官方收了回去。新的模型上，清单工具默认不再安装。
- [p1-15] 理由说得很直白：这些模型自己就能记住要干什么。这一注，到期了。
- [p1-15a] 那规划这件事就没了吗？没有。它升级成了一道门。
- [p1-15b] 这道门叫计划模式。先只看不动手地探索，再把计划写出来给你过目。
- [p1-15c] 计划没批，改文件的动作一律拦住。它想动手，得先说服你。
- [p1-15d] 批准那一下你有三个选择：交给自动闸门、逐条人工点头，或者再想想。
- [p1-15e] 清单是写给它自己看的。计划，是写给你看的。
- [p1-16] 清单背后还藏着一整套任务系统：带依赖、能上锁、能落盘。这个以后单说。
- [p1-18] 把计划写下来，本身就是一种能力。而且是装在循环外面的能力。
- [p1-19] 什么都不执行的工具，成了长活不跑偏的关键。这种反差，今天还有几次。

## P2 另开一张副桌

> 画面：主桌右侧滑出一张小桌（自带缩小克隆环），脏活全摊在副桌上；干完只带回一张回执卡。
> 角标：`task` tool · 全新 messages[] · 只回传结论

- [p2-01] 第二样，管的是另一种失控。活太脏了，会把整张桌子占满。
- [p2-02] 比如说，追一个缺陷，要读三十个文件、翻六十轮对话。
- [p2-03] 等你找到问题在哪，桌上已经堆了一百多条记录。绝大部分，是中间过程。
- [p2-04] 这些纸每一轮都被重读一遍。跟目标没关系，但一直占着位置，一直计着费。
- [p2-05] 换成你会怎么办？开个新终端去翻，翻完关掉，把结论记回本子上。
- [p2-06] 它的办法也一样。另开一张干净的副桌，派一个分身过去干。
- [p2-07] 副桌上是一份全新的对话记录，干干净净，只有一句任务说明。
- [p2-08] 分身在那边自己跑自己的循环，读文件、改代码，跟主桌互不打扰。
- [p2-09] 主桌上你看不到那三十个文件的任何一行。中间过程全丢，只带回一张回执。
- [p2-11] 丢的是什么？写过的文件、改过的代码都在硬盘上。丢的是纸，不是活。
- [p2-12] 纪律第一条：玩具版不许分身再派分身。成型的这套放开到三层，同时二十个。
- [p2-14] 纪律第二条。分身每次动手之前，照样得过那几道闸门。
- [p2-15] 隔离的是视野，不是权限。它看不见你俩的对话，但它一样不能为所欲为。
- [p2-16] 官方文档后来证实了 Claude Code 里的一个反转。
- [p2-17] 这是今天最反直觉的一处。它内部有一种分叉模式，动机根本不是隔离。
- [p2-18] 是为了省钱。命中缓存。
- [p2-19] 什么意思？对话按字数花钱。同样的开头算过一遍，短时间内第二遍近乎免费。
- [p2-20] 分身要是从头建自己的桌面，前缀全变了，每一段都得按原价重新算一遍。
- [p2-21] 所以分叉模式反着来。把父亲桌上的东西几乎原样搬过去，前缀就保持一致。
- [p2-22] 「几乎」是有严格定义的：系统提示、工具表、模型、消息前缀、思考配置。
- [p2-23] 差一个字就白算。五样全对上，缓存才认账。
- [p2-24] 隔离是搂草打兔子。省钱才是真心话。
- [p2-25] 隔离其实还是半拉的。有人读源码读出来，分身会继承父亲读过的文件，
- [p2-26] 免得同一个文件读两遍。桌是分开了，可有些抽屉还是共用的。
- [p2-27] 分身要弹审批窗，也会冒泡到父亲的屏幕上。还是你来点头。
- [p2-28] 至于派出去慢慢干的那种玩法，以后单拆。
- [p2-28a] 官方还给分身套了三个上限，像三只笼子。头一只：同时在场最多二十个。
- [p2-28b] 另两只：每个分身自己的轮数上限，和整份上下文的配额。烧完就收工。
- [p2-28c] 放得开，也拴得住。副桌再多，也翻不出这三只笼子。
- [p2-29] 记住一句：脏活不占主桌。
- [p2-30] 还值得记住第二句。省钱和隔离，常常是同一个设计的两种说法。

## P3 目录卡与垫纸

> 画面：桌角一叠薄目录卡（~100 token 标价），旁边书架上厚手册（~2000 token）；
> 拉开手册时计价器跳字。随后四段垫纸逐轮拼装。
> 角标：`load_skill` · ~1% 上下文预算 · PROMPT_SECTIONS

- [p3-01] 第三样，管的是知识。规范、手册、风格指南，这些它干活前该知道的东西。
- [p3-02] 最笨的办法，是把手册全贴进它的基本设定里。几百上千行，每轮都跟着计费。
- [p3-03] 你改一个颜色值，它却在重读整个数据库规范。百分之九十九的内容跟你无关。
- [p3-04] 解法是分两级。桌角常驻一叠目录卡，每张卡就写一行：叫什么名，管什么事。
- [p3-05] 一张卡的价钱，大约是整本手册的二十分之一。桌角摆一排，也不心疼。
- [p3-06] 真要用到哪本，再把整本拉上桌。而且是整场常驻，压缩之后还会补回来。
- [p3-07] 目录常驻，内容按需。
- [p3-08] 官方口径：预算有硬顶。
- [p3-08b] 文档里还有句实在话。清单太长，超过两百行，它就开始不老实读了。
- [p3-09] 硬顶有多硬？大约是窗口的百分之一，还另设了绝对上限，超了就砍。
- [p3-10] 还有个安全细节：取手册只认登记过的名字，不走文件路径，防的是目录穿越。
- [p3-11] 第四样，管的是桌面上最大的那张纸。就是它的基本设定本身。
- [p3-12] 你跟它说的每一句话之前，都垫着这么一张纸：你是谁、你在哪、能干什么。
- [p3-13] 一个最简单的版本，是从第一行起就写死。能力越加越多，纸就越写越长。
- [p3-14] 换个项目要重写整张纸，改一段可能跟别处打架，而且每轮都得全文计费。
- [p3-15] 真做起来是拆成好几段：身份、工具清单、工作目录、还有相关的记忆。
- [p3-16] 每一轮，都按当场的真实状态重新拼一次。状态变了，纸也跟着变。
- [p3-17] 关键在「真实状态」四个字：工具查实际注册了哪些，记忆查文件在不在。
- [p3-18] 它不去猜消息里出现了什么关键词。猜关键词，就是给幻觉开门。
- [p3-19] 状态没变，拼出来的纸一字不差，直接用上回的。连拼都不重复花钱。
- [p3-20] 有人拆过它的源码，说这张垫纸常规状态两三万字，极简模式就剩两行。
- [p3-21] 更大的反转来自官方：2026年7月，这张纸删掉八成以上，评测不掉分。
- [p3-21a] 纸能写多长，取决于模型有多不需要你替它写。
- [p3-22] 读源码的人还说了个讲究的细节。所有段落里头，只有一段永远不许进缓存。
- [p3-23] 外接工具的说明段。外接的服务随时会掉线，缓存它就是在缓存一个谎言。
- [p3-24] 你看，连「哪一段纸可以复用」都是被精确设计过的。
- [p3-25] 这张垫纸每轮都在拼，可它拼得比谁都勤俭。
- [p3-26] 目录、手册、垫纸，三样都在回答同一个问题：这一轮，什么该进它的眼睛。

## P4 桌边的补救梯

> 画面：桌子右侧挂下一张三级补救梯；每级对应一类错误。等待条 0.5s→1s→2s→…→32s 封顶生长。
> 角标：max_tokens / prompt_too_long / 429·529 · min(500×2^n, 32s) + jitter

- [p4-01] 第五样，管的是意外。活干到一半出岔子，这是生产的常态，不是事故。
- [p4-02] 第一种岔子：话说到一半，额度用完了，句子就断在半空。
- [p4-03] 处理得很有章法。第一次，把额度上限放大八倍，原封不动重试同一个请求。
- [p4-04] 注意，是原封不动。断掉的那半句先不存，加够额度再来一遍。
- [p4-05] 放大只有一次。再断才保存半句话，塞条续写提示：从断掉的地方接着说。
- [p4-06] 续写最多三次，三次还断就收手。有人拆过源码，把那条提示原文抄了出来。
- [p4-07] 很有工程品味：别道歉，别复述刚才在干嘛，直接接着说，把剩下的活切小点。
- [p4-08] 第二种岔子：桌上太满，装不下了。服务那边直接拒收。
- [p4-09] 先压一轮，把旧的纸换成摘要腾地方。压完还装不下，就承认装不下，退出。
- [p4-10] 压过一次再压第二次，没意义。纸不会越压越小，该退的时候就得退。
- [p4-11] 第三种岔子最有意思：不是你的问题，是服务那边过载或者限流了。
- [p4-12] 硬冲没用，先等一等：半秒、一秒、两秒往上翻倍，封顶三十二秒。
- [p4-13] 再撒一点随机抖动，免得全世界的重试都挤在同一秒冲回来。
- [p4-14] 对方要是留了张「稍后再来」的字条，那就听字条的。
- [p4-17] 连着三次都过载呢？换人。切到备用模型，把没干完的活清一清，先干点小的。
- [p4-17a] 它什么时候不重试？
- [p4-17b] 证书对不上，第一次就报错。那是要你去修的，退避一百遍也一样。
- [p4-17c] 更微妙的是另一类。话说了一半、工具已经发出，这时候出错，不能原样重发。
- [p4-17d] 重发一次，动作就跑两遍。
- [p4-17e] 它的做法是保住已经产出的，插一条「没写完」的标记，从断点接着来。
- [p4-17f] 顺带给个刻度：默认最多重试十次，上限是十五次。
- [p4-19] 拆源码的人还提到个冷静的设计。续写要是连着几次都没写出新东西，
- [p4-20] 系统就直接判出来：再续也没产出，停。不恋战，也是一种能力。
- [p4-21] 出错不是终点。这就是这套系统的性格。
- [p4-21a] 官方还留了个兜底的后悔药。改动可以回退到前面的检查点。
- [p4-21b] 不过它只看文件改动。跑过的命令、改过的外部状态，都不在里面。
- [p4-22] 你会发现每一级补救都带着上限：升一次、续三次、等三十二秒、换一次人。

## P5 桌子换了五样，环没动

> 画面：五样装置在桌上归位成一组；环从桌后浮到前景（系列锚第二次出场），桌子淡为线稿。
> 角标：五段增量全部为「外挂」· while 骨架未换（实测 @ 67a9126c）

- [p5-01] 收个尾。五样摆一起看。
- [p5-02] 钉住的清单，另开的副桌，按需翻开的目录，每轮重拼的垫纸，一张补救梯。
- [p5-03] 它们管的其实是同一件事：这一轮，模型到底能看见什么。
- [p5-04] 清单负责「别忘」，副桌负责「别堵」，目录负责「别贪」，
- [p5-05] 垫纸负责「别写死」，梯子负责「别断」。
- [p5-06] 别忘、别堵、别贪、别写死、别断。这五句合起来，就是视野管理。
- [p5-07] 你会发现一个熟悉的形状。这五样，没有一样是写进循环的。
- [p5-08] 清单是工具，副桌是调用，目录是注册表，垫纸是拼装，梯子是包裹。
- [p5-09] 我逐一比过这些增量代码。加的全是外挂。那句「不停问模型」一个字没换。
- [p5-13] 视野越管越细，桌面越换越讲究，后面那个循环纹丝不动。它干活越来越稳。
- [p5-14] 不是它变聪明了。
- [p5-15] 是有人替它把视野管了起来。
- [p5-16] 而管视野这件事，本身就是一门可以被看懂的手艺。

## P6 落点与信源

> 画面：信源卡（官方文档+取数日期 / 第三方源码分析已逐处标注）→ 一句话合同金句卡 → 五格层进度条 → 渐黑。

> 渐黑窗口从末 beat 总时长推导（红线四）。

- [p6-07] 本片机制依据官方文档，取数2026年8月，以官方最新表述为准。
- [p6-08] 涉及内部实现的部分，为第三方源码分析，片中已逐处标注。
- [p6-01] 视野是安排出来的。
- [p6-02] 安排它的，不是模型自己。
- [p6-03] 这话对人也成立：你的注意力在哪，多半是桌上摆了什么、谁塞了张纸给你。
- [p6-04] 五样零件里，清单那件刚被收回去。它押的是「模型记不住」这一注。
- [p6-05] 模型变强，赌注就过期。官方留了句自省的话：常问自己，可以停掉哪一件。
- [p6-06] 桌子会换，零件会瘦，可后面那个循环一直没停过。
- [p6-09] 下期：它会忘，而且忘得有章法。但有一样东西，它永远不许忘。下期见。
