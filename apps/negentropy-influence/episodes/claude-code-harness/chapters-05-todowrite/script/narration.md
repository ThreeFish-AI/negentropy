## P1 一个不干活的工具

> 画面：三通道框架图三卡并列——身份规则（固定文本块）、对话记录（滚动条）、工具清单（表）；规划蓝清单卡从对话记录上方点亮

- [p1-01] 模型每轮看到什么？身份规则、对话记录、工具清单——就这三样。
- [p1-02] 解法不绕：把计划写成清单，摆进对话记录，变成每轮都看得见的文本。

> 画面：待办清单卡特写（规划蓝）：三态图例点火（待办空心 / 进行中高亮 / 完成打勾）；「零执行能力」反差帧——清单卡两手空空（无文件图标、无命令图标）

- [p1-03] 装置分两半。前一半，待办清单工具。
- [p1-04] 模型传入一份清单，每条标三态：待办、进行中、完成。
- [p1-05] 系统把清单存进内存——计划从脑子搬进了程序。
- [p1-06] 有意思的是，这个工具什么都不干：读不了文件，跑不了命令。
- [p1-07] 它增加的不是执行能力，是规划能力。
> 画面：工具对照表增一行（待办工具→待办处理器），承前集装置视觉；环体〔M-001〕旁注「循环不改」
- [p1-08] 又是两处改动：一条定义、一<行|HANG2>注册；循环，一<行|HANG2>没改。

> 画面：计数器特写（提醒紫）：0→1→2→3 递进刻度；数到 3 时紫色脉冲，一条提醒消息条插入对话流尾部

- [p1-09] 后一半，一个专盯清单的计数器。
- [p1-10] 这轮调用里出现待办工具，计数清零；没出现，加一。
- [p1-11] 数到三，下轮调用前，往对话里插一条提醒：更新你的待办。
- [p1-12] 插完清零，接着数；两半拼齐，跑一遍看看。

## P2 三步任务走一遍

> 画面：走查舞台（Animated State Trace）：消息条与清单卡双轨并置；任务卡落下（命名风格白话：全小写、下划线相连）；建单动画——三条清单卡入场、首条高亮进行中

- [p2-01] 拿教学版的演示走一遍——为讲清机制搭的简化版——还是那三步：改下划线命名，跑测试，写报告。
- [p2-02] 模型先建清单：重命名、跑测试、写报告，首条标进行中。
- [p2-03] 清单进了对话，第一步开工。

> 画面：顺利段（t2–t4）快进：改文件、更新清单（首条打勾、次条高亮、计数清零）；测试失败消息条放大，注意力光圈被吸住，清单卡离场渐暗，计数器 1→2→3 爬升特写

- [p2-04] 第一步改完，更新清单：首条完成、次条进行中，计数清零。

## P3 拆掉提醒试试

> 画面：左绿右红消融同屏——左「提醒在位」：11 轮全亮、三步全完成、漂移 0、收尾；右「拆掉提醒」：轮数耗尽、只剩两步、漂移 7、没收尾（红色旋转帧）；数字动态条 + 工况角标

- [p3-01] 教学原型复刻全程：十一轮，三步全完成，一条提醒，零跑偏。
- [p3-02] 拆掉提醒再跑：三步只剩两步，轮数耗尽，没收尾。

> 画面：可见区视窗回放慢镜——清单文本条被挤出窗外变灰；漂移环：同一个格式化动作循环播放、计数器跳到 7

- [p3-03] 更扎眼的是漂移：七个重复的格式化动作，全在原地打转。
- [p3-04] 被吸住的那几轮一过，清单出了可见区，模型顺着惯性漂走。
- [p3-05] 提醒不是客套，是把计划顶回眼前的唯一外力。

> 画面：阈值三档并列动态条（工况角标）——默认 3：提醒 1 次·消息 23 ↔ 阈值 1：提醒 6 次·消息 28·任务照常完成 ↔ 阈值 999：提醒 0·与拆掉逐项相同

- [p3-06] 把阈值改成一轮没碰就提醒：任务照常完成，代价是六次提醒、更啰嗦的对话。
- [p3-07] 改成九百九十九——等价于没有提醒，漂移照旧。

> 画面：规律金句卡（衬线体）「可见性即影响力」；示意帧：更大的脑形图标依旧看不见视窗外的文本

- [p3-08] 背后一条规律：可见性即影响力——在场才有影响，被稀释等于缺席。
- [p3-09] 换更聪明的模型也没用：信息不在场，再聪明也看不见。
- [p3-10] 那真实产品里，这个提醒长什么样？

> 角标：nag_threshold · episode A / experiment 1
