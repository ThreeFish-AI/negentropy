## P0 大模型的行动瓶颈

> 画面：系列片头装置之后冷启动——终端窗口中央一条写好却无人按下的命令行，光标孤闪；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一个会写命令、却永远在等你按回车的模型。
- [p0-02] 你让它列目录、跑脚本，它能写出正确的命令。
- [p0-03] 但输出完文字，一切就停住了。

> 画面：用户头像在「模型—终端—模型」之间来回搬运箭头，搬运次数计数器疯涨

- [p0-05] 复制、粘贴、按回车，贴回输出，下一条命令才出来。
- [p0-06] 每一个来回，你都成了它和电脑之间的人肉搬运工。

- [p0-08] 把这段搬运交给程序自动跑，这个驱动外壳，工程上就叫 Harness。
- [p0-09] 答案简单得出奇：一个循环，把执行结果喂回给模型，给它接上一双手。

## P1 Agent Loop 核心机制

> 画面：陶土橙环体放大占屏，五步循环沿环依次点亮；消息列表在侧边逐条堆叠

- [p1-01] 看环上的这五个站牌，拆开来看，正好五步。
- [p1-02] 核心代码只有三十<行|HANG2>，只认一个信号：模型要不要调工具。
- [p1-03] 先把这个最小的循环看清楚。

- [p1-04] 第一步，把你的需求存入对话记录。
- [p1-05] 第二步，程序带上对话与工具清单，调用模型。

- [p1-06] 第三步，接收回答存入记录，同时检查有没有工具调用。
- [p1-07] 工具调用，就是模型明确说：请执行该操作，参数已就绪。

- [p1-08] 第四步，照单执行，在真实环境跑出结果。
- [p1-09] 第五步，把执行结果包成工具消息塞回对话，回到第二步。

> 画面：消息角色标签特写——assistant「我要调工具」之后紧跟一条 user「这是你要的结果」，角色色块对比闪两下

- [p1-10] 注意看角色标签：工具结果，是以用户的身份塞回去的。
- [p1-10b] 机制完全自洽：凡不是模型自己产出的内容，都算输入。

- [p1-12] 只要模型不再开口要工具，循环平稳退出。
- [p1-13] 分工就此立住：模型管决策，程序管执行。

> 角标：tool_use · tool_result · Harness

## P2 任务执行与回喂走查

> 画面：走查实例——购物清单卡片，牛奶<行|HANG2>落进清单；消息列表五条逐格生长，环体同步转三圈、每圈高亮不同段

- [p2-01] 光说骨架不直观，我们带入一个具体例子走一遍。
- [p2-02] 比如你说：帮我在清单里加一<行|HANG2>牛奶，再念给我听。

- [p2-03] 第一轮，模型发起写文件请求，备好路径和牛奶内容。
- [p2-03b] 程序在磁盘执行写入，把清单更新的结果喂回去。
- [p2-04] 第二轮，看到写入结果，模型接着发起读文件请求。

- [p2-05] 程序执行读取，把清单的最新文字再次喂回去。
- [p2-06] 第三轮，看到完整清单，模型直接给出文字回答。

- [p2-07] 这次没有工具调用，绿色出口开启，循环平稳退出。
- [p2-09] 三次调用、两次执行，每次决策都精确踩在喂回的结果上。

## P3 流式工况与判据抉择

> 画面：判据对比帧——左「收尾字段」迟到（数据流逐字到达，字段标记滞后闪红），右「内容块」已就位；网络流传输动画特写

- [p3-01] 骨架有了，但每圈转完，凭什么判断该继续还是该停？
- [p3-03] 一版查收尾字段：看 API 返回的结束原因标记。
- [p3-04] 另一版查内容：看回答里有没有工具调用块。

- [p3-05] 一次性返回全部内容时，两版几乎没区别。
- [p3-06] 可一旦进入真实生产必用的流式传输，立刻见高下。

- [p3-07] 流式状态下，文字像打字机一样逐字到达。
- [p3-08] 模型要调工具，工具内容块在前半段就已就位。

> 画面：火警调度台插曲——听筒台听到「着火 · 地址」两词到位即派车；边界标记「补派 ✓ / 第二回 ✗」

- [p3-09] 就像紧急出警：听到灾情和地址，车就该立刻派出去。
- [p3-10] 不等电话收尾；更何况接警能补派，循环错过可没有第二回。

> 画面：消融对比同屏——左红「收尾字段判据」多轮中断、工具调用静默丢弃；右绿「内容块判据」多轮全跑通、调用全落地

- [p3-11] 字段若还没刷新就提前做判断，程序很容易误判为已经结束。
- [p3-12] 实测证明：把判据换回收尾字段，别的代码全都不动。
- [p3-13] 多轮任务就会提前中断，模型要的工具调用被静默丢弃。
- [p3-14] 教训一句话：面对流式工况，认内容事实，不认派生字段。

> 角标：stop_reason vs tool_use

## P4 Claude Code 源码对照

> 画面：基线标尺——三十与一千七百多两根悬殊柱；State 字段环外圈点亮两三个代表，退出路径族逐条亮起

- [p4-01] 真实的 Claude Code 怎么做？
- [p4-02] 负责主循环的文件，足足有一千七百多<行|HANG2>。

- [p4-04] 内核完全一致：同样不信收尾字段，改立一个继续运行的开关。
- [p4-04b] 流式接收中只要检测到工具调用块，开关就立刻拨通。

- [p4-05] 教学版只管对话列表；生产版的状态对象，十个字段各管一类。
- [p4-06] 退出路径也不止一条：超长、报错、中止、轮次上限，各有处置。

- [p4-07] 这些多出来的逻辑，全是系统面对不确定性时的保险丝。
- [p4-07b] 真保险丝熔断即断路；这里的保护多数还能重试、还能续跑。
- [p4-08] 三十<行|HANG2>骨架是恒定核心，一千七百多<行|HANG2>全在外层守护它。

> 角标：query.ts · needsFollowUp · State
