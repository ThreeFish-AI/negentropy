## P0 写死的开场说明

> 画面：系列片头装置之后冷启动——一段灰色的提示长文本卡居中（角标 System Prompt）；右侧两格状态小窗：工具表新亮一行、记忆文件图标亮起，长文本卡毫无反应（「状态变了它不知道」视觉先现）；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一份写死的开场说明——工具新了，它不提；记忆有了，它不认。
- [p0-02] 每轮开工，装置先递一段说明：你是谁、有什么工具、守什么规矩。
- [p0-03] 它叫系统提示——和消息、工具表，构成模型每轮看到的全部。

> 画面：「欠债清单」逐条点亮（警示红描边）：不分段 / 不看状态 / 不缓存；一条越积越长的提示条，每轮计费计数器跟着跳

- [p0-04] 教学代码里，它欠了一屁股债。
- [p0-05] 最早是一<行|HANG2>写死的字符串；后来挪进函数，也只在启动时拼一次。
- [p0-06] 债在结构上：不分段、不看状态、不缓存——状态变了，它纹丝不动。
- [p0-07] 加一个能力多一段，换项目整段重写，新指令还可能跟旧的打架。
- [p0-08] 更亏的是，系统提示每轮计费，带着用不到的段落白交钱。

> 角标：System Prompt · system prompt / messages / tools

## P1 分段、拼装、缓存

> 画面：分段主视觉首亮（section 紫）——提示长文本卡拆解成四块分段卡（角标段名 identity / tools / workspace / memory），各自独立可点亮

- [p1-01] 解法三步：分段，按状态拼装，缓存。
- [p1-02] 第一步，分段：拆成四块按主题维护——身份、工具、工作目录、记忆。
- [p1-03] 块与块互不牵连：改工具块，身份块一个字不用动。

> 画面：状态清单卡（装配蓝）入场：工具表两行 + 记忆文件有无；拼装流箭头从清单指向分段卡——拼或不拼，清单说了算

- [p1-04] 第二步，按状态拼装：每轮调用模型前，先查一份状态清单。
- [p1-05] 清单记的是真实状态：注册了哪些工具、记忆文件有没有内容。
- [p1-06] 哪段拼、哪段不拼，全看这份清单——不在消息里搜关键词。
- [p1-06b] 比如记忆文件还是空的，记忆段就不拼进来。

> 画面：缓存徽标（确认绿）挂上拼装流出口：状态清单没变 → 原样返回；比对键文本条逐字展开；环体〔M-001〕上「调用模型前」时点高亮一次

- [p1-07] 第三步，缓存：状态清单没变，直接返回上次拼好的结果。
- [p1-08] 怎么判断没变？把清单排成一段固定格式的文字，当比对键。
- [p1-09] 为什么不直接给清单算一枚指纹？自带的指纹函数有两个坑。
- [p1-09b] 程序一重启，指纹就变；一层套一层的数据，压不成指纹。
- [p1-10] 到这里，说明不再是写死的手稿，而是按状态现拼的配置。

> 角标：PROMPT_SECTIONS · identity / tools / workspace / memory · assemble_system_prompt · get_system_prompt · context · json.dumps(context, sort_keys=True) · hash

## P2 一句闲聊，一个文件

> 画面：走查舞台（装配蓝）——磁盘格空（无记忆文件）→ 状态清单记「无记忆」→ 三块分段卡滑入拼成提示条，字符计数器跳到 113

- [p2-01] 拿原型走一遍：开机第一次取说明——磁盘上还没有记忆文件。
- [p2-02] 状态清单记下无记忆，拼出三段：身份、工具、工作目录，一百一十三字符。
- [p2-03] 紧接着再取一次，状态没变——缓存命中，原样返回。

> 画面：闲聊消息条落入（文字气泡「我对写这个模块毫无记忆」）；分段卡纹丝不动（描边呼吸一下即止）

- [p2-04] 这时用户闲聊一句：「我对写这个模块毫无记忆」。
- [p2-05] 提示纹丝不动——「提到记忆」，不是状态。

> 画面：磁盘格亮起：记忆文件落盘并写入内容 → 状态清单翻新 → 缓存徽标闪断（失效）→ 四块分段卡拼装，计数器跳到 154

- [p2-06] 直到磁盘上真的落下记忆文件，还写进了内容。
- [p2-07] 状态清单变了，缓存失效，重拼：四段，一百五十四字符。
- [p2-08] 记忆段到场，因为它真的有货了。
- [p2-09] 那，要是判据不看状态，改看话术呢？

> 角标：update_context · get_system_prompt · MEMORY.md · --episode D

## P3 看状态，不看话术

> 画面：左红右绿消融同屏——左「关键词判据」：消息气泡里「记忆」二字高亮，空记忆分段卡被误拼进提示条，计数器 113→147（警示红）；右「状态判据」：同一句闲聊扫过，提示条恒稳 113（确认绿）

- [p3-01] 破坏实验来了：把判据从「查状态」，改成「猜关键词」。
- [p3-02] 新规则：消息里一出现「记忆」这样的字眼，就拼记忆段。
- [p3-03] 还是那句闲聊，话音刚落——空的记忆段，当场被误拼了进去。
- [p3-04] 误注入从零变一，提示从一百一十三字符跳到一百四十七。

> 画面：提示条特写轻微抖动 ↔ 恒稳帧并列；「每轮都要看」的回环虚线绕住提示条

- [p3-05] 麻烦在哪？一句随口闲聊，就撬动了模型每轮要看的说明。
- [p3-06] 这条判据的差异，放到真实系统里，就是提示的稳定性。

> 画面：判据卡定格：看状态 ✓ / 看话术 ✗；远处另一套分段卡阵列（七块）淡入预告

- [p3-07] 教训一句话：段加载，看状态，不看话术。
- [p3-08] 判据站稳了；可同一套机制，还有另一套拼法。

> 角标：--experiment 4 · keyword matching

## P4 两套拼法

> 画面：左右等高双栏（同为绿框，不判优劣）——左：分章版四段卡 + 进程内缓存徽标；右：集成版七段卡阵列 + 「每轮重建」印章 + 四样动态小卡（当前时间/技能目录/记忆/外部服务器名）持续刷新

- [p4-01] 另一套在集成版：七个固定段，每轮重建，不设本地缓存。
- [p4-02] 七段之外，另拼当前时间、技能目录、记忆、外部服务器名。
- [p4-03] 任何一个状态变了，提示就跟着变。

> 画面：左栏缓存徽标放大：省的是「重复拼字符串」的本地开销（小计数卡弹出又收起）

- [p4-04] 哪套对？都对，目标不同。
- [p4-05] 四段版的缓存，省的只是本地重复拼字符串的开销。

> 画面：拉远——真实 CC 层：一条分界线把提示条切成「静态段｜动态段」两截，静态段挂全局缓存徽标；体量对比条：两三万字节 vs 一百五十字符（差两个数量级标尺）

- [p4-06] 真实的 Claude Code 呢？
- [p4-07] 拆解过 Claude Code 源码的同学们应该知道：真正护的是另一层。
- [p4-08] 接口级的缓存——每轮计费，就发生在这一头。
- [p4-08b] 切一条分界线：静态段命中全局缓存，不因动态内容失效。
- [p4-09] 体量也悬殊：标准形态两三万字节，极简形态只剩一百五十来个字符。
- [p4-10] 同一套装置，相差两个数量级。

> 角标：PROMPT_SECTIONS（七键）· assemble_system_prompt · SYSTEM_PROMPT_DYNAMIC_BOUNDARY · prompt cache · CLAUDE_CODE_SIMPLE
