## P0 干不完的活

> 画面：系列片头装置之后冷启动——一枚橙色环体〔M-001〕居中，上方压下一张四模块大任务卡（认证/数据库/接口/测试）；环体内消息条越堆越高、最早的目标卡被挤出顶边；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一个代理干不完的活——多开几个就好？麻烦，恰恰出在这个直觉上。
- [p0-02] 课上的例子：重构后端——认证、数据库、接口、测试。
- [p0-03] 一个代理顺着做，修到接口时，认证的细节早被挤出了记忆。
- [p0-04] 这份记忆有个名字：上下文窗口，一次装得下的对话额度。

> 画面：子代理小卡从环体侧面弹出又缩回（用完即走）；一排灰色队友剪影虚位以待，其中一枚点亮成品红（队友预告）

- [p0-05] 现成的帮手是子代理：一次性的，干完就回一句结论。
- [p0-06] 中途不能问、不能改、不能等，也不记得这支队伍。
- [p0-07] 这里的活，要的是一直在线、随时说话的队友。
- [p0-08] 最容易想到的组法，恰恰是错的那种——错在哪？

## P1 一人一只信箱

> 画面：直觉帧——四个代理共用同一条对话消息列，一条工具结果消息（红色渗染）同时漫进四个气泡，各自的目标卡被冲花

- [p1-01] 最容易想到的组法：共用同一段对话记录，谁都看得见全部。
- [p1-02] 当场就崩：建数据库的队友吐出一串中间结果，灌进了写接口那个队友的推理里。

> 画面：拆解帧——共用消息列断开成四段独立对话；一只湛蓝信箱文件特写亮出（文件名角标），「追加一行」逐字落格、「整摞取走」清空动画

- [p1-03] 所以第一件事：对话不共享，要传话，递信。
- [p1-04] 每个代理一只信箱，主代理也有——就是磁盘上的普通文件。
- [p1-05] 发消息，是往对方文件里追加一<行|HANG2>字。
- [p1-06] 读消息，是把整摞信一次取走；取走，文件就删。
- [p1-07] 取走即空，这叫消费式收信：一条消息，恰好被处理一次。
- [p1-08] 信箱立好了，就差会用它的人。

> 角标：MessageBus · .mailboxes/{name}.jsonl · read_inbox

## P2 拉起队友

> 画面：主代理橙环两侧并行亮起两枚品红同款环体（队友线程）；每枚环体贴两张小卡：角色设定、四件工具（消息历史角标）

- [p2-01] 第二件事：主代理<调|DIAO4>一件工具，拉起队友。
- [p2-02] 队友是另起的一条并行执行流，和主程序同时跑。
- [p2-03] 它自带角色设定、消息历史，和一小套工具。
- [p2-04] 工具只有四件：跑命令、读文件、写文件、发消息。
- [p2-05] 教学版给它限了十轮，怕它停不下来。

> 画面：对照条——左「子代理：一次性，用完即走」右「队友：一直活着，随时收信」；主代理工具计数条 11→14 跳格（新增三件工具卡滑入）

- [p2-06] 跟子代理一比就清楚：一次性的，管的是互不干扰；一直活着的，管的是随时递话的协作。
- [p2-07] 主代理添了三件：拉队友、发消息、查信箱——从十一件<长|ZHANG3>到十四件。

> 画面：走查舞台——后端项目任务卡落下；两枚品红环体并行转动（alice 敲命令行、bob 写文件，名牌进视觉层）；两条总结信先后飞入中央信箱

- [p2-08] 走个例子：接了个大活，搭后端——组队。
- [p2-09] 拉起第一个队友建数据库，再拉一个写接口客户端。
- [p2-10] 两人同时开工：一个建表，一个写客户端。
- [p2-11] 各干各的，互不打扰；干完，总结发回主代理信箱。
- [p2-12] 信到了门口——主代理，怎么看见它？

> 角标：spawn_teammate · spawn_teammate / send_message / check_inbox · range(10)

## P3 取走即空

> 画面：主代理橙环特写——环体转完一轮停顿，视线切到信箱文件；每秒一次的湛蓝探测脉冲扫过信箱，「只看不取」标签闪现

- [p3-01] 第三件事：主循环每<转|ZHUAN4>完一轮，就看一眼信箱。
- [p3-02] 有信，就把队友消息注入对话历史，模型看见才能反应。
- [p3-03] 还有个每秒一拍的探测：只看有没有信，不取。
- [p3-04] 一有动静，就唤醒新一轮——不用等用户开口。

> 画面：双入口示意——查信箱工具卡与主循环各伸一只手伸向同一信箱；先到者把整摞信抱走，慢一步的抓空（警示红）

- [p3-05] 这里有条铁律：取走即空，读取只能有一个口。
- [p3-06] 可教学版自己埋着两个口：查信箱的工具能读，主循环也能读。
- [p3-07] 谁先读，信归谁；慢一步的，扑空。

> 画面：左红右绿消融同屏——右「入口统一」：两单关机信对号落定、状态翻成办成（确认绿）；左「放工具直读」：一条回音被工具卡抱走、状态格永远卡在「待处理」，信箱再查清零（警示红）

- [p3-08] 实测说话：演到关机——队友要停工，主代理等回音。
- [p3-09] 拆掉统一入口放工具直读：回音被读走，关机永远停在待处理。
- [p3-10] 再查信箱：零条。信没了，事也没了下文。
- [p3-11] 入口统一时呢？两个队友、两单关机，全部办成、落定。
- [p3-12] 教训一句话：消费式信箱，必须配单点入口。

> 角标：inbox_poller · peek · check_inbox · consume_lead_inbox

## P4 真实的队伍

> 画面：拉远——真实产品拓扑全景：主代理橙环居中、多枚品红环体环绕，每枚环体旁一只带锁扣的湛蓝信箱；一条审批请求从队友信箱冒泡升向主代理、再落回（品红→橙→品红回路）；「实验特性·默认关」开关卡收尾

- [p4-01] 那真实的 Claude Code 呢？
- [p4-02] 拆解过 Claude Code 源码的同学们应该知道：真队伍，也是一人一只文件信箱。
- [p4-03] 写信还加文件锁：撞上了就重试，最多十次。

> 画面：权限冒泡四步链——队友环体上弹出一枚审批请求泡（品红），升入主代理信箱；主代理环侧亮出审批卡、用户按下批准；回执泡沉回队友环体、工具放行（确认绿）

- [p4-04] 还有一件，教学版整个省掉了：权限冒泡。
- [p4-05] 队友碰到要批的动作，比如删个文件：请求就像气泡，冒进主代理信箱；用户批完，结果发回去。
- [p4-06] 审批提示统一出现在主代理会话——官方文档也这么写。
- [p4-07] 官方还交代：这套团队机制还是实验特性，默认不开。

> 角标：~/.claude/teams/{team}/inboxes/ · proper-lockfile · teammateMailbox.ts · permission_request / permission_response
