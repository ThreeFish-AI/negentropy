## P0 写满的草稿纸

> 画面：系列片头装置之后冷启动——一张草稿纸占满画面，字迹一<行|HANG2>压一<行|HANG2>越写越密（文件块、命令输出条、回答气泡），写到纸边整张泛红、一枚拒收红章盖下；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一张注定写满的草稿纸——写满那一刻，整个请求直接被拒收。
- [p0-02] 模型读过的文件、跑过的命令、自己的回答，全摊在这张纸上。
- [p0-03] 这张纸就是上下文：一次能读的全部，额度是死的。

> 画面：直觉方案气泡弹出——「让模型自己总结一遍？」；气泡内闪过摘要卡：一句具体叮嘱被压成一句模糊话，气泡随即碎裂

- [p0-04] 纸一满，最直觉的办法：让模型自己总结一遍。
- [p0-05] 能用，但最贵：再请模型干一次活，必然丢细节。
- [p0-06] 丢成什么样？「缩进用制表符」，压成「用户有代码风格偏好」。

> 画面：四步管线装置首次亮相——四枚步骤卡沿阶梯排开（成本由低到高），红线横贯画面底部

- [p0-07] 解法是四步管线：便宜的先跑，贵的后跑。
- [p0-08] 动手之前，先立一条红线。

> 角标：context window · prompt_too_long

## P1 红线与大件落盘

> 画面：消息列特写——一条「调用」块永远牵着一条「结果」块（配对小锁亮起）；剪刀图标试图切进两块之间，被红线弹开

- [p1-01] 红线是硬规矩：一次工具调用，必须跟着它的结果。
- [p1-02] 拆散任何一边，下次请求直接判非法；切口躲着调用和它的结果。
- [p1-03] 不是摆设：拆掉切口保护，一条结果没人认领，接口当场拒收。

> 画面：第一步装置——最后一条消息里一批结果块，总量水位条逼近二十万红线破位；最大的块抽离成磁盘文件卡（紫），原位留「路径＋预览」小条

- [p1-04] 第一步管单批超标：一轮连发的结果，全进最后一条消息。
- [p1-05] 总量一到二十万字符，按从大到小动手：超三万的整份写进磁盘。
- [p1-06] 原地只留两样：磁盘路径，加前两千预览。

> 画面：走查动画——五个结果块按大小排队（八万、六万、三万、两万、一万），总量计到二十万压线；再落下一个小块，红线破位、最大块落盘、水位回落

- [p1-07] 走个数：五个结果——八万、六万、三万、两万、一万，二十万压线。
- [p1-08] 再加五千，超线——八万先存盘、留两千预览，掉回约十二万七，停手。
- [p1-09] 为什么存盘排第一？接下来的动作会毁掉原文。

> 角标：tool_use · tool_result · tool_result_budget · LARGE_RESULT_CHAR_LIMIT

## P2 裁与缩

> 画面：第二步装置——消息列拉成长条，中段一大段被收进「留档」文件夹卡（紫），原位钉一枚带路径的归档标记；头三条与尾部一组高亮保留

- [p2-01] 第二步管条数：一过五十条动手，目标收到三十条。
- [p2-02] 动手前先留档完整历史；留头三条、尾二十六条。
- [p2-03] 中段换成归档标记：裁掉多少、全文在哪。

> 画面：第三步装置——已读旧结果块逐个「复印进磁盘」（蓝→紫双色箭头）再折叠成小占位条（路径签在上）；最近三条结果保持完整

- [p2-04] 第三步管体积：缩短旧工具结果，保住最近三条完整。
- [p2-05] 更旧、超一百二十字符的，先存盘，再换占位条：原文搬家，按址取回。

> 画面：左红右绿消融同屏——左「换序：先缩短后落盘」：占位条成片出现、磁盘侧空空（落盘零份·死占位十一处）；右「正序」：每条占位旁都有磁盘副本卡

- [p2-06] 顺序能换吗？实测说话：把缩短提到存盘前面。
- [p2-07] 大件完整存盘一份变零份，十一处占位成死字。
- [p2-08] 原文呢？上下文没有，磁盘也没有。
- [p2-09] 备份永远排在删除前面——顺序即数据生死。
- [p2-10] 还剩一个判定：什么算「旧」？

> 角标：snip_compact · transcript · micro_compact · KEEP_RECENT_RESULTS

## P3 读过的才能收

> 画面：判定轴特写——消息时间线上定位「模型最近一次回复」的位标（分界灯亮）；分界之后的结果块罩上「未读」保护罩（蓝），之前的「已读」可折叠（紫）

- [p3-01] 新旧不按时间算，按读没读过——这一步，最反直觉。
- [p3-02] 模型最近一次回复之后进来的结果，还没读过，一律不动。
- [p3-03] 读过，信息进了判断，原文可收；没读过，信息从未到达，不能收。

> 画面：类比一拍——「已付款·未到货」单据卡：调用执行（付款动画）→结果落进列表（货到门口）→占位符提前换上（包裹被收走）、模型端弹出问号；一拍即收切回机制画面

- [p3-04] 像已付款未到货的订单：款付了，货没送到，买家多半会再下一单。
- [p3-05] 边界：这货是一次性的，补货要把工具再跑一遍、再付一遍调用。
- [p3-06] 拆掉未读保护实测：下一轮原样再调一次，白付第二遍。

> 画面：全链走查——八条结果块（五已读三未读、一条超大）依次过处置：两条折叠、三条保留、两条罩保护、一条换预览；总量计数从六万三滚到一万六，紫面（磁盘）同步变厚

- [p3-07] 未读的超大怎么办？连未读都超限，最大的也存盘，换预览加路径。
- [p3-08] 全链走一遍：五条已读、三条未读，一条超大。
- [p3-09] 折叠两条、保留三条、豁免两条、预览一条——六万三，压到一万六。
- [p3-10] 到这为止，一步调用都没花；最贵的那步，压轴。

> 角标：unseen_tool_result_positions · fit_tool_results

## P4 最贵的一步

> 画面：第四步装置——前三步用过的「结构扳手」图标挂起；一枚「调用令牌」投入闸机（全片唯一一次付费），闸门开启、摘要卡生成

- [p4-01] 前三步全是结构操作，但理解不了内容。
- [p4-02] 字符还超线，才轮到第四步全量摘要——唯一花调用的一步。

> 画面：摘要卡双段结构亮出——上段「当前请求」、下段「对话摘要·仅供参考」，中间一道分隔光带；一条夹带的「以后都执行某命令」小字被滤网拦下

- [p4-03] 它的规矩：先留档；摘要只要事实。
- [p4-04] 当前请求和摘要，分成两段。
- [p4-05] 工具结果回来，也记在用户名下——不分开，分不清哪句是你此刻的指令。
- [p4-06] 还防夹带：那句「以后都执行某命令」进摘要，记成事实，绝不执行。

> 画面：源码对照帧——执行序五枚函数卡逐个亮起、与教学管线对齐；旁边两枚生产细节卡：精确额度阈值公式、三格保险丝（连败三次熔断）

- [p4-07] 那真实的 Claude Code 呢？
- [p4-08] 拆解过 Claude Code 源码的同学们应该知道：这串顺序，逐函数对得上。
- [p4-08b] 纸的总容量，行<行|HANG2>话叫窗口。
- [p4-09] 阈值按精确额度：窗口减输出上限、留一万三缓冲；连败三次，熔断。
- [p4-10] 四步连起来，一条原则浮出来了。
