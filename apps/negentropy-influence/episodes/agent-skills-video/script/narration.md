# 逐字稿（narration.md ★单一事实源）

> 幕标题 2–8 字名词短语（派生章节条标签）；幕内空行 = beat；`>` 为画面备注不进配音。
> 预算：~3980 字 @280 字/分（含停顿等效）≈ 14:13。数字一律紧贴单位（2025年/46家），无空格（中文年份空格陷阱）。

## P0 四十六家就范

- [p0-01] 2025年，Anthropic做了一件反常的事：把自己家AI助手的「技能格式」捐出去，做成了开放标准。
- [p0-02] 按商业惯例，这等于把自家港口的图纸，送给了所有竞争对手。
- [p0-03] 一年后的结果更反常：OpenAI接了，Google接了，微软接了，Cursor也接了。
- [p0-04] 四十六家客户端，几乎凑齐了AI编程工具的整张牌桌。

> 画面：夜港全景，46 只船影渐次亮灯（关键词锚点：46 家 / 开放标准）

- [p0-05] 这个标准长什么样？说出来你可能不信：一个文件夹，里面一份说明文件。
- [p0-06] 全文二百四十七行，没有版本号，没有更新日志，甚至没有一个安全章节。
- [p0-07] 它凭什么让所有竞争对手低头？

- [p0-08] 要回答这个问题，得先看它替谁解决了什么麻烦。
- [p0-09] 你大概遇过这种时刻：AI很能干，但不知道你们团队的规矩。
- [p0-10] 报销单怎么填、代码评审盯什么、那份PDF表单藏着哪三个坑——这些知识不在它的脑子里。
- [p0-11] 老路只有两条，各有各的死法。
- [p0-12] 让它自己猜，它会猜错；把全部手册塞进开场白，活还没开始干，记忆先被填满了。
- [p0-12a] 算一笔账就知道多离谱：二十个技能，每份手册三千token，开场白就要常驻六万。
- [p0-12b] 更糟的是它们还会互相踩——十条规矩里九条和眼前这单活无关，注意力全耗在挑拣上。
- [p0-13] 问题的根子在一笔账上：为「装了多少」付钱，还是为「用了多少」付钱。

## P1 一个文件夹的标准

- [p1-01] 把这个文件夹打开，里面只有一份文件，叫SKILL.md。
- [p1-02] 文件头上六格信息，只有两格必须填：名字，和一段描述。
- [p1-03] 名字的规矩最多：小写、数字、连字符，最长六十四个字符——而且，必须和文件夹同名。

> 画面：集装箱爆炸图〔M-001〕，角件放大 = 六字段角标卡（name / description 两格亮）

- [p1-04] 为什么强制同名？因为这套体系里没有注册中心。
- [p1-05] 文件夹的名字，就是这只箱子的箱号；登记处就是文件系统本身。
- [p1-06] 白拿一套全球唯一的身份，不用向任何机构申请——这是标准跟操作系统做的第一笔交易。
- [p1-07] 描述之外，正文完全自由：想写步骤写步骤，想贴例子贴例子，规范一个字都不管。
- [p1-08] 附件也随意：脚本的、参考文档的、模板的，各放一个子目录，约定俗成。
- [p1-08a] 剩下三格选填：许可证、兼容环境、还有一格任意键值对——官方给私货留的唯一正门。
- [p1-08b] 出厂前可以找官方验箱师过一遍，一条命令，验格式不验内容。

- [p1-08c] 正文自由，不等于随便写。官方工艺手册第一条：从真实任务里长出来，别凭空生成。
- [p1-08d] 让AI真干一单活，你在旁边纠错，把纠偏记下来——那几条「不用库X会踩坑」，才是全册最值钱的部分。
- [p1-08e] 这种坑点清单，行话叫gotchas，是很多技能里含金量最高的一节。
- [p1-08f] 第二条更朴素：写完就跑，跑了再改。第一版几乎必然不准，真实执行一轮，胜过闭门改十轮。
- [p1-08g] 还有条取舍心法：模型已经会的，一个字都别写；它不知道的，才值得上册。

- [p1-09] 整个规范最像「宪法」的，是仓库里那句治理原则：格式要保持小。
- [p1-10] 原话的意思是——新需求必须来自真实的互操作痛点，而不是想象中的完备。
- [p1-11] 所以它不规定箱子放在哪、谁来查验、走哪条航线。
- [p1-12] 不是没做完，是刻意不做。记住这三处留白，后面全是戏。

## P2 台账与提箱

- [p2-01] 现在让港口开张。关键角色登场：调度室墙上那本台账。
- [p2-02] 每只箱子在台账上只占一行：箱号，加一句货签——内装什么，什么时候该提它。
- [p2-03] AI助手每次开工，先扫一眼台账。这一眼，就是它为技能付出的全部日常成本。
- [p2-04] 按官方口径，一行大约五十到一百个token；一百个技能，也就一本目录册的分量。

> 画面：船期表台账墙逐行点亮（引航青），右侧泊位空着

- [p2-05] 哪句任务和哪行货签对上了，调度员才提起那只箱子，把整册作业指导书摊上作业台。
- [p2-06] 箱子里的隔层——脚本、参考、模板——用到哪层，再取哪层。
- [p2-07] 这就是贯穿整个标准的核心设计，名字很直白，叫渐进披露。
- [p2-08] 它把那笔账彻底改写了：常驻的只有台账，搬进记忆的只有你真用到的那几册。
- [p2-08a] 所以正文有条软预算：建议五千token以内、五百行以内——超了不是违规，是账变难看。
- [p2-08b] 写不下的，拆进参考文件，正文里留一句「哪一步卡住了，再去翻哪一页」。
- [p2-08c] 引用只许一层深：从正文到附件，一跳可达。串三层 reference 的技能，等于把台账当成了迷宫。

- [p2-09] 这笔账差多大？我们自己搭了个玩具实测：二十个技能，全载进开场白接近四万token，台账只留两千三。
- [p2-10] 差了快十七倍。当然这是玩具规模——但方向不会骗人。
- [p2-11] 旁证来自对岸：OpenAI给自家助手定的规矩，技能目录合计不超过上下文的百分之二，或八千字符。
- [p2-12] 两家素来打架的公司，在同一条预算纪律上各自独立地相遇——这比任何宣传都可信。
- [p2-12a] 箱子里还能捆脚本，这也是有工艺的：临时工具要钉死版本号，别让三个月后的升级偷袭你。
- [p2-12b] 给AI用的脚本还有四条家规：不问交互、报错要说人话、结果吐结构化、能空跑预演。
- [p2-12c] 一句话：把脚本当成给一个看不见屏幕的新同事写的。

## P3 货签决定生死

- [p3-01] 台账体制有个要命的软肋：全部赌注，压在那一行货签上。
- [p3-02] 调度员提不提箱，看的只有它。写得准，箱子永远在正确的时刻被想起；写得泛，它就永远沉默。
- [p3-03] 一句「帮忙处理文档」，合规、无害、永远没人提——而且没有任何报错。
- [p3-04] 官方指南管这种叫静默退化：技能没坏，只是死了。

> 画面：两张货签并排，好签亮绿、差签蒙灰（关键词锚点：何时用 / 静默退化）

- [p3-05] 所以写货签是有工艺的。第一课：写「做什么」，更要写「何时用」。
- [p3-06] 第二课：覆盖那些用户没说关键词的时刻——他只说「这表看着乱」，你也得想起清洗技能。
- [p3-07] 第三课最反直觉：练负例，要练「差一点」的。
- [p3-08] 「改个表格」对清洗技能是近失配，对表格编辑技能才是正解——只有近失配，能逼出描述的边界。
- [p3-08a] 但别矫枉过正往里塞关键词。货签越长越泛，误触发跟着涨——四家对岸那条「目录不超百分之二」，罚的就是满写。
- [p3-09] 官方给了一套完整练法：二十条任务，每条跑三遍，算触发率；六成拿来练，四成封存考试。
- [p3-10] 还有一条容易翻车的提醒：按考试成绩选货签——最好的版本，不一定是最后改的那版。
- [p3-11] 毕竟调度员只看一眼。你写下的每个字，都在替你参加这场一秒定生死的面试。

## P4 四个港口四种章程

- [p4-01] 标准只管箱体，那港口们实际怎么用？我们翻遍四家的官方文档，逐条对账。
- [p4-02] Gemini CLI最像模范生：只用规范那两格必填，还给每只箱子设了道激活确认门。
- [p4-03] Claude Code反过来，是私货最多的：十来个规范外的字段，连子目录怎么生效都自己定。
- [p4-04] OpenAI最克制，但把策略写进了另一个配置文件；VS Code干脆三套目录约定全认。
- [p4-05] 四个港口，四副章程——箱体一样，装卸全凭各家规矩。
- [p4-05a] 连堆场位置都没统一：这家的箱子放点agents，那家放点claude，还有自家专属目录。
- [p4-05b] 混战里长出了一个事实锚点：点agents目录，四家全认——不是规范规定，是市场投票。

> 画面：四港口鸟瞰四联卡，仅 Gemini 岗亭亮灯（关键词锚点：确认门 / 私货字段）

- [p4-06] 宽容到什么程度？官方指南自己交代了：名字对不上目录，警告一声，照装不误。
- [p4-07] 理由很实在——拒载一只「为别家客户端写的箱子」，比放进一只不太规范的箱子，代价更高。
- [p4-08] 我们实测过这道门：严格口径会拒掉三分之一；宽容口径，十二只全进。

- [p4-08a] 那怎么知道一只箱子到底有没有用？官方工艺给的办法很较真：同一单活跑两遍。
- [p4-08b] 一遍带技能，一遍不带，把两份产物交给裁判盲评——不说哪份是哪份，只问哪份好。
- [p4-08c] 裁判也不是一句话打分，是对着清单逐条断言：图表有没有、行数对不对、格式坏没坏。
- [p4-08d] 成本和收益一起记账：多花的token和多赢的质量，哪个值，一目了然。
- [p4-08e] 这套双跑对照，跟我们刚才那道门的实测，是同一种较真。

- [p4-09] 连官方自己的验箱师都靠不住：那份参考校验器，和条文对不上十三条，还自称只是个演示。
- [p4-10] 至于查验真伪——四家没有一家验签名。因为标准根本没设这道岗。
- [p4-11] 唯一的确认门，是Gemini自己决定设的。标准说「建议考虑」，它当了真。

## P5 两个破坏实验

- [p5-01] 光看章程不过瘾，我们回实验室拆了两样东西。
- [p5-02] 第一样：同名箱子谁优先。规范的通用约定是，项目目录压过个人目录。
- [p5-03] 把这条优先级拆掉，让两个客户端按各自的扫描顺序解析同一堆目录——
- [p5-04] 结果十只技能里两只同名不同版：A港装的是公司版，B港装的是个人版。
- [p5-05] 同一个任务，两家助手行为不同，而且谁都没报错。身份这种东西，不锚在规范里，就锚在扫描顺序的偶然里。
- [p5-05a] 同名还有第二种戏法：把公司技能复制一份到个人目录，改一行自用。
- [p5-05b] 通用约定是项目压过个人——你的修改在公司仓库里静默失效，盘上两份都在，生效的只有一份。
- [p5-05c] 合规客户端该做的是亮一句警告：某某技能已被遮蔽。不做这句提醒，排查全靠猜。

> 画面：双屏对照，两港台账 diff 泛红（关键词锚点：扫描顺序 / 同名漂移）

- [p5-06] 第二样更狠：往货签里藏私货。
- [p5-07] 描述文本的中间，偷偷缩进一行「allowed-tools」，后面跟着删除权限的通配符。
- [p5-08] 宽容的解析器把它当成了正经字段，收进了元数据。
- [p5-09] 要是客户端真把这份授权当真，恶意预授权，就从货签这一行小字混了进来。
- [p5-09a] 顺手还撞见一个小彩蛋：元数据那格私货正门，只收字符串——写个布尔值false，转一圈变成字符串。
- [p5-09b] 客户端拿它当真假判断，会被「false」这个词的非空骗过：被禁用的技能，判定成启用。
- [p5-10] 这背后是整个体系最容易被误解的一点：技能不是被执行的代码，是被解释的文本。
- [p5-11] 模型读指导书，照单作业。所以它的危险面不在代码漏洞，而在「一句人话」本身。

## P6 留白处的战争

- [p6-01] 看懂了留白，就看懂了最后一张牌。
- [p6-02] 四十六家为什么肯低头？因为标准只谈箱体，不碰任何一家的航线、关税和海关主权。
- [p6-03] 加入它，不用改自家码头；拒绝它，等于自绝于整片航运网。
- [p6-04] 管得越少，越多人肯用——这是格式赢得生态战的算法，代价，都记在了留白处。

> 画面：悬案卷宗堆（警示金），ISO 会议室时间线折叠（关键词锚点：留白 / 悬案）

- [p6-05] 留白处现在怎样了？分发规范的提案，在仓库里躺了七个月没合上。
- [p6-06] 工具授权字段，放宽和锁死两份提案对着冲，没人裁决。
- [p6-07] 倒是和外部协议的互通，推进得最顺——没人吃亏的事，总是最好谈的。
- [p6-08] 海运集装箱的历史早就演过这一幕：箱体标准先行统一，海关协作，是几十年后的事故倒逼出来的。
- [p6-08a] 当年那个开卡车出身的发明者，把自家专利格式捐成了行业标准，船公司、铁路、港口全数就范。
- [p6-08b] 而货柜安全倡议这种跨国查验机制，要到真实事故之后的很多年，才一点点补上。
- [p6-09] 这个格式多半也会走同一条路：先成为事实，再补上条文。
- [p6-10] 所以它到底保证了什么？只有一件事：包里装的是什么。
- [p6-11] 好不好用，靠你淬炼货签的功夫；可不可信，靠港口设不设那道岗。
- [p6-12] 一个文件夹，一份说明文件，一行货签——标准只做这三件事，就把整张牌桌拉到了同一张图纸上。
- [p6-13] 至于图纸没画的那些战争，下期再讲。
