## P1 一个文件夹的答案

> 画面：目录索引卡解体为文件树：一个文件夹，内含 SKILL.md + scripts/ references/ assets/ 三个虚影子目录；六字段卡贴逐枚钉上。

- [p1-01] 答案的全部家当，就是一个文件夹。
- [p1-02] 里面放一份 SKILL.md，开头几行是它的档案卡，这种纯文本格式叫 YAML。
- [p1-03] 必填的只有两项：名字，和一句功能描述。
- [p1-04] 名字一到六十四个字符，只能用小写字母、数字和连字符。
- [p1-05] 而且必须和所在文件夹的名字，一模一样。

- [p1-06] 描述不超过一千零二十四个字符，说清两件事：做什么，什么时候用。
- [p1-07] 其余字段全部可选：开源协议、兼容性说明、扩展元数据、工具白名单。
- [p1-08] 正文没有格式限制，操作指引想怎么写就怎么写。
- [p1-09] 旁边还可以放三个子目录：脚本、参考文档、静态资源——都不是必须。
- [p1-10] 换句话说，技能在哪里，身份就在哪里：路径即身份。

> 画面：walkthrough 起点：终端敲出 mkdir pdf-report，SKILL.md 两行元数据逐字打出（Animated State Trace 起步）。

- [p1-11] 我们拿一个真实例子走全程：写一个拆财务报表的技能。
- [p1-12] 建文件夹，名字叫 pdf-report，元数据里名字也写它。
- [p1-13] 描述一行：解析复杂财务报表与资产负债表。
- [p1-14] 再补半句：纯文本提取，请用内置读取工具。
- [p1-15] 正文写下解析步骤，脚本目录放一个解析脚本。
- [p1-15b] 几步下来，一个技能就绪。

> 画面：名字绑定视觉：文件夹标签与 name 字段用同色金线互锁；Git 流水带（clone 即安装）；随后分裂成 A/B 两块色版（X1 消融位）。

- [p1-16] 名字绑定目录名，看着像小事，其实是治理智慧。
- [p1-17] 文件系统天生自带层级，门牌号天然唯一，中心化注册表都不用建。
- [p1-18] 技能可放项目里共享，也可放个人全局；约定项目级覆盖用户级，互不打架。
- [p1-19] Git 顺手就能当版本分发渠道，克隆即安装。

- [p1-20] 可要是拆掉这条优先级呢？实验 X1 动了它。
- [p1-21] 两个扫描策略不同的客户端，解析同一批技能。
- [p1-22] 十个技能里，两个同名技能各加载了不同版本。
- [p1-23] 同一个任务，两家给出两种行为，复现都做不到。
- [p1-24] 身份不锚定规范，就会被扫描顺序的偶然性决定。

## P2 三级账本

> 画面：disclosure-lifecycle 图（archify 逐章回放主场）——目录卡只留一行金线摘要；第二张卡翻面展开；第三张侧栏抽卡。

- [p2-01] 真正的巧思，在记账方式上。
- [p2-02] Agent Skills 把知识拆成三级，按使用付费。
- [p2-03] 第一级，目录常驻：会话启动时，只加载每个技能的名字加描述。
- [p2-04] 一项大约五十到一百个 token。
- [p2-04b] 全部加起来，也就两千上下。
- [p2-05] 就拿刚才的 pdf-report 来说，目录里只多了薄薄一行。
- [p2-06] 这行摘要，就是它在你上下文里的全部房租。

- [p2-07] 第二级，正文整载：模型判断任务命中了它，才读全文。
- [p2-08] 你问「帮我拆这份 PDF 报表」，模型扫一遍目录，描述对上了。
- [p2-09] 这才把解析步骤整篇读进来——官方建议控制在五千 token 以内。
- [p2-10] 第三级，按需调阅：执行到具体分支，才去读参考文档、跑脚本。
- [p2-11] 解析脚本此刻才运行，吐出一张科目余额表。
- [p2-12] 用不到的参考资料，从头到尾没进过上下文。

- [p2-13] 而且三级各自独立：正文读了，不代表资源也要跟着进门。
- [p2-14] 一句话：固定的安装成本，变成了动态的使用成本。

> 画面：账本标尺（useCount 双柱+基线虚线）：左柱爬至 39,222，右柱停在 2,321，中缝弹出 16.9×。

- [p2-15] 这笔账有工程实测托底：二十个常规规模的技能。
- [p2-16] 全部正文装进开场白：三万九千二百二十二个 token。
- [p2-17] 只挂目录：两千三百二十一。
- [p2-17b] 相差十六点九倍。
- [p2-18] 开场只背一行目录，干活的力气全花在刀刃上。
- [p2-19] 省下的每一格注意力，都还给了正事。

- [p2-20] 这不是哪一家的执念。
- [p2-21] OpenAI 的客户端设了硬预算：目录不超过单次可读长度的百分之二，或八千字符。
- [p2-22] 超限就自动裁剪描述。
- [p2-23] 竞争对手在同一件事上达成共识：护住注意力，就是护住执行力。

## P3 一句话的路由

> 画面：路由靛信号流：用户气泡→模型读目录→description 高亮闪动→命中脉冲落到 pdf-report 卡；旁边浮出「哑火/抢戏」两枚灰败小卡。

- [p3-01] 设计上的巧思不止记账一处；第二个，是把「什么时候用」也交了出去。
- [p3-02] 客户端不写正则、不配关键词，把整份目录直接交给模型。
- [p3-03] 模型读懂你的意图，自己决定调哪个技能。
- [p3-04] 也就是说，那一句描述，几乎承担了路由决策的全部。

- [p3-05] 写不好，只有两种下场。
- [p3-06] 该触发时哑火：你明明在拆报表，它却装没看见。
- [p3-07] 不该触发时抢戏：你随口问个概念，它也要跳出来跑一遍。
- [p3-08] 抢戏的代价是双重的：白费一次调用，还可能带偏答案。

- [p3-09] 好在官方指南给了一套工程化写法，一共三条。
- [p3-10] 第一条，用命令口吻起手，把使用时机写成明确条件。
- [p3-11] 比如「当用户想要解析结构化报表时使用」，而不是堆形容词。
- [p3-12] 第二条，防守近失配：把看起来相关、其实不归它管的事写清楚。
- [p3-13] pdf-report 描述里那句「纯文本提取请用内置工具」，就是干这个的。
- [p3-14] 第三条，拿数据说话：备二十组有代表性的提问，多轮测命中率。

- [p3-15] 再按六比四分成训练组和验证组，防止为几个特殊用例过拟合。
- [p3-16] 有人会想：把一千零二十四个字符全堆满关键词，命中率不就最高？
- [p3-17] 恰恰相反，目录是模型的注意力底噪，堆得越满，路由越钝。
- [p3-18] 一根字符串的路由，也能调成高信度的工程。

## P4 46 家的默契与分歧

> 画面：governance-layers 图（archify 逐章回放主场）：规范/指南/生态三层面板；客户端阵列 46 格点亮；四条 PR 战线拉扯动画。

- [p4-01] 到这里，画面都很和谐。
- [p4-01b] 真实世界呢？
- [p4-02] 截至二〇二六年九月的统计，官方名录收录了四十六家主流客户端。
- [p4-03] 但支持，不等于支持得一模一样。

- [p4-04] Gemini CLI 最贴规范，只严格读取名字和描述两个字段。
- [p4-05] Claude Code 在规范之外，加了十几个私有字段：上下文分叉、钩子、路径。
- [p4-06] OpenAI 保持克制，却在目录旁边配了专属策略文件。
- [p4-07] 各家扫描的目录也不一样：项目级、用户级，还有自家专属路径。
- [p4-08] 扫描哪儿、信什么、怎么命名，规范只定底线，细节各自发挥。

- [p4-09] 同名技能撞车，约定是项目级覆盖用户级。
- [p4-10] 规范还叮嘱：覆盖发生时打印警告，让开发者知情。
- [p4-11] 实验 X5 拆掉了这条警告：有效技能一个没少，但有一处覆盖悄悄生效。
- [p4-12] 模型加载的是哪一版，用户无从知晓——丢的不是数据，是知情权。

- [p4-13] 另一个分歧更根本：格式有瑕疵的技能，到底要不要拒收？
- [p4-14] 严格派说，脏配置会污染上下文；宽容派说，警告即可，别拦着生态。
- [p4-15] 实验 X2 拿十二只技能做了正面对比。
- [p4-16] 严格口径拒载四只，其中有一只，是为别人客户端写的扩展字段。
- [p4-17] 跨平台可用的技能面，当场损失三分之一。
- [p4-18] 换成宽容口径：十二只全部载入，一只不拒。

- [p4-19] 还有更隐蔽的坑：规范把元数据限定成纯文本的键值对。
- [p4-20] 有人写入开关式的 true，读出来变成文字「false」。
- [p4-21] 客户端一判断：字符串有值，等于真。
- [p4-22] 被禁用的技能，就这么被启用了。

- [p4-23] 标准仓里挂着几十条开放提案，吵的正是这些。
- [p4-24] 分发与版本机制悬而未决；字段的松紧之争长期拉锯。
- [p4-25] 一句话：生态先跑起来，条文再追认。

## P5 被解释的文本

> 画面：X4 消融主场：SKILL.md 元数据区放大——缩进伪字段逐行渗入（红），allowed-tools/Bash(rm:*) 泄漏高亮；右半绿色对照：正常单行描述；p5-13「四家」角标列全名单：Claude Code / Codex / Gemini CLI / VS Code Copilot（取数 2026-09-26）。

- [p5-01] 现在说安全，先问一个本质问题。
- [p5-02] 技能正文的执行者，不是操作系统，是大模型本人。
- [p5-03] 它是被阅读、被解释的提示词，不是被运行的机器码。
- [p5-04] 就算带了脚本，也只是正文写着：需要时，请运行这个脚本。
- [p5-05] 模型的阅读理解，就是这套系统的执行环境。

- [p5-06] 所以它的风险形态，和传统插件完全不同。
- [p5-07] 防线要防的不是越权渗透，而是提示词注入——恶意文字被当成指令执行。
- [p5-08] 实验 X4 复现了一次：在描述字段里，借换行和缩进伪造配置。
- [p5-09] 宽容解析照单全收，伪造的工具授权混进了元数据。
- [p5-10] 客户端若把它当成已批准的权限来读，恶意授权就成立了。

- [p5-11] 教训很硬：不可信的文本通道，绝不能当权限控制的输入源。
- [p5-12] 解析必须认准独占一行的字段，滤掉特殊字符。
- [p5-13] 而现状是：四家主流客户端，没有一个做数字签名或防篡改校验。
- [p5-14] 默认提供激活确认界面的，只有 Gemini 一家。
- [p5-15] 加载前把技能名字、用途、能碰的目录，摆到用户眼前。
- [p5-16] 其余的，默认信任工作区里的一切。

## P6 规律、争议与边界

> 画面：五条规律卡连翻；三大争议牌竖起；尾幕目录卡回归终态（金线呼吸〔M-003〕），底部边界护栏卡五枚。

- [p6-01] 回到开头的问题，答案完整了。
- [p6-02] 五条规律值得带走：身份锚在文件系统上；成本按使用付费。
- [p6-03] 路由由语义质量决定；核心资产是被解释的文本；互操作压倒完备。
- [p6-04] 五条其实是一条：管得足够少，才能被足够多人接受。

- [p6-05] 当然，这套标准也有三个吵不完的争议。
- [p6-06] 比如模型自主还是人工点名，信任真空又由谁补位。
- [p6-07] 路由之争的现状，是绝大多数客户端双通道并存：既能自动触发，也能点名调用。
- [p6-08] 而信任真空最麻烦：安全责任被全额推给了客户端。

- [p6-09] 假如哪个技能包夹带了私货，眼下没人拦——要等这样一次真实事件，才倒逼出标准防线。
- [p6-10] 末了，还得交代五件这套材料没有证明的事。
- [p6-11] 收益数字全是自建测算，没有权威基准；语义路由没做严格对照。
- [p6-12] 采纳名单不等于实现深度；安全防线依旧脆弱；极简治理能否长期演进，也未经验证。

- [p6-13] 下次往开场白里堆规则之前，不妨先想想这本账。
- [p6-14] 目录常驻，正文按需——把固定的安装成本，变成动态的使用成本。
- [p6-15] 至于那些拆组件的实验，仓库里有完整脚本，欢迎复现。
