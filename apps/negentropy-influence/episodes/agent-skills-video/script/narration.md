## P0 四十六家之谜

- [p0-01] 先看一棵目录树。每个文件夹，是一份教AI干活的说明书。
- [p0-02] 就这么简单：一个文件夹，一份SKILL.md，两行必填信息。
- [p0-03] 截至2026年9月底，四十六家客户端登记采纳了这套格式，正面竞争的对手，也在名单上。
- [p0-04] 它没有注册中心、没有审核、没有版本号。凭什么？

> 画面：`.agents/skills/` 文件夹树展开六文件夹〔M-003〕→ 46 家登记名单墙（角标：取数 2026-09-30）

- [p0-05] 先看它要装的知识有多特别：你家的规矩。
- [p0-06] 团队约定、工具细节、踩过的坑——这类工序知识，模型记不住。
- [p0-07] 它有两个要命的属性：每次会话都得重新在场；塞进上下文——它一次开工能看到的全部内容——就有代价。

- [p0-08] 路线一，让模型自己猜。不可靠，也没法复现。
- [p0-09] 路线二，把手册全塞进开场白。塞得越多，指令彼此稀释，模型反而越笨。
- [p0-10] 账单还按装了多少知识涨，不是按用了多少涨。

- [p0-11] Agent Skills把这笔账整个反过来：常驻的只留一行，用到的才付钱。
- [p0-12] 怎么做到的？答案的前一半，钉在每个技能的门牌上。

## P1 包裹与门牌

- [p1-01] 标准只钉三件事：一个文件夹、一份SKILL.md、一张六字段属性卡。
- [p1-02] 六个字段里，必填的只有两个：name和description——叫什么、干什么的。
- [p1-03] 其余四个，license、compatibility、metadata、allowed-tools，全是可选，一个都不用记。
- [p1-04] 说明书正文零格式限制。官方原话：写任何有助于完成任务的内容。

> 画面：六格属性卡，两格高亮必填〔M-004 门牌版式〕→ 引语卡（规范原文）

- [p1-05] 最省事的一笔是身份：技能叫什么，不由任何机构分配。
- [p1-06] name必须与文件夹名逐字一致——像门牌必须跟户口登记名一致。
- [p1-07] 标准不设发牌机构，文件系统本身就是登记处。
- [p1-08] 参考实现，就是按标准写出来的示范代码，它还做了一层归一。
- [p1-08a] café的两种Unicode写法，归一后算同一个名字；中文名，也合法。

- [p1-09] 这条规矩看着松。拆掉试试。
- [p1-10] 玩具原型装了六个技能。把名字必须等于目录名这条拆掉，改信属性卡里的名字。
- [p1-11] 结果：目录从六行变成五行，合并周报这个技能静默蒸发——没有任何告警。
- [p1-12] 对照组：官方校验器当场报错，指名道姓。
- [p1-13] 身份不设机构，蒸发起来连一声都不吭。

> 画面：X1 消融对比（左绿：校验器报错行 / 右红：菜单卡一行无声消失）〔M-001 菜单卡打点〕

- [p1-14] 登记是免费的。但每次开工，读它的账从哪里算起？

## P2 一页菜单

- [p2-01] 这套记账方式，像一家餐厅的菜单。
- [p2-02] 每道菜在菜单上只占一行：菜名，加一句话介绍。这一行常驻，不占厨房。
- [p2-03] 客人自己看菜单点菜。点了，厨房才为这道菜开火。
- [p2-04] 菜谱之外的备料手册放后厨架上，做到这步才去翻。
- [p2-05] 落到规范里，就是三级记账：目录、正文、资源。

> 画面：餐厅菜单三级示意 → **archify full**：lifecycle 目录+激活

- [p2-06] 第一级，目录，就是那页菜单：name加description，会话启动就常驻。
- [p2-06a] 每个技能约一百个token，账单的计数单位。
- [p2-07] 第二级，正文：任务对口才整份读入，建议不超过五千token。
- [p2-08] 第三级，资源：附带文件，执行到需要那一刻，才去读。
- [p2-09] 我们的原型实测：六个技能，目录块一共约四百五十四个token常驻。

- [p2-10] 原型一口气跑了五项任务，先看第一句：帮我把这周五和小李的换班在系统里提交。
- [p2-11] 目录行对上号，换班技能的正文整份读入，账上添一笔。
- [p2-12] 正文说提交前要核对审批名单——翻出那份参考文件，再加约九十七个token。
- [p2-13] 这一轮五项任务下来，五份正文共加约六十二。常驻合计约六百一十三，没被点到的技能，始终只占一行。

> 画面：〔M-002 账本条〕454 → +62 → +97 → 613 计数器推进；〔M-005〕任务单射入菜单卡

- [p2-14] 真实客户端把账硬化成预算门：Codex规定，技能目录最多占上下文窗口的百分之二。
- [p2-14a] 上下文窗口，就是它一次开工能看到的那块地盘。
- [p2-15] 窗口未知时上限八千字符；超限先截短每条description。
- [p2-16] 指南算的是明白账：装二十个技能，不等于预付二十份正文。

- [p2-17] 拆掉按需性会怎样？激活时，把资源全部预载。
- [p2-18] 常驻从约六百一十三涨到约六百九十四。涨幅，约百分之十三。
- [p2-19] 涨幅恰好等于一份从没被读过的说明书——换班技能包里那份管提交的脚本，整轮任务都没轮到它。
- [p2-20] 按需不是锦上添花的优化，它就是成本模型本身。

> 画面：X4 消融（账本条红侧跳 694，基线标尺亮出 submit.py）→ **archify full**：lifecycle 执行+压缩

- [p2-21] 长对话聊到后面，客户端会把早期内容压一压腾地方——这时，已激活技能的正文，不许被裁走。
- [p2-22] 拆掉这条保护再试：技能正文留存零份，任务策略悄悄失效——报错信号，无。
- [p2-23] 点过的菜不撤桌，是防静默退化的保险。
- [p2-24] 菜单护住了钱包。可菜名后头那句话，凭什么决定哪道菜被点上？

## P3 一句招牌

- [p3-01] 每个技能什么时候被用，靠的全是description那一句话。
- [p3-02] 它像店门口的招牌：说清卖什么、什么情况该进来。
- [p3-03] 客户端把每个技能的名目登记进目录，模型每轮拿任务跟它比对。
- [p3-04] 觉得对得上，整份说明书读进来。判断完全交给模型——多数实现不做关键词匹配。
- [p3-05] 这是全片最薄也最致命的约定：上限一千零二十四字符，独扛全部路由。

> 画面：〔M-004 招牌版式〕description 特写 → **archify full**：lifecycle 激活

- [p3-06] 一句话扛路由，两头的失败模式都得自己防。
- [p3-07] 写窄了，该来的客人路过没进——该触发，没触发。
- [p3-08] 写宽了，不该进的也进来问——误触发。
- [p3-09] 最难防的是近失：话题沾边，实际要干别的。
- [p3-10] 更新Excel预算表里的公式，对一个处理CSV表格文件的技能就是近失——看着像，其实不是。

- [p3-11] 官方给了一套招牌测试法，四步。
- [p3-12] 第一步出题：约二十条真实请求，一半该触发一半不该，正例沿四个维度变化措辞。
- [p3-13] 第二步跑分：每条跑三次，触发过半算数。判定很实在——SKILL.md是否真的被读入。
- [p3-14] 第三步防背题：请求六四分成训练、验证两组。改招牌只看训练集，拿验证集选版本。
- [p3-15] 第四步收敛：约五轮通常够。卡住就换结构，别死磕措辞。

- [p3-16] 反面教材叫背题王：把失败样例的关键词抄进招牌——等于把店调成只认识那二十张脸。
- [p3-17] 一句如实的边界：模型自行判断凭什么够可靠？官方文档没说；跨客户端是否一致，也没人公开测过。
- [p3-18] 招牌挂好了。可各家门口的规矩，谁说了算？

## P4 门口的规矩

- [p4-01] 客户端拿到包裹，五步走完一生：发现、解析、披露——把那页菜单亮给模型看——激活、长会话管理。
- [p4-02] 发现要扫两个域：项目级和用户级。同名时项目压住用户，还要告警。
- [p4-02a] 门牌不必全城唯一，扫到哪条街，算哪条街的。
- [p4-03] 解析按宽容原则：名字对不上、超长，警告照载；解析不了，才跳过。
- [p4-04] 包裹里还能带工具：scripts目录放脚本。引用纪律只有一条。
- [p4-04a] 说明书里指路，只指同层或下一层的文件，不往上翻、也不提倡绕远。

> 画面：五步生命周期横条推进（发现/解析/披露/激活/长会话）

- [p4-05] 给agent——替你干活的AI——写的脚本，有十条军规。
- [p4-05a] 头一条是硬的：禁止交互提示——没人应答的环境里等输入，等于永久挂起。

- [p4-06] 平时AI每动用一件工具，都要你点头一次。
- [p4-06a] allowed-tools，用这个技能的那一回合免点头——这是Claude Code文档的定义。
- [p4-06b] 注意——从网上代码库装来的技能，可以给自己预先授权；装之前，先看它给自己列了什么。

- [p4-07] 互操作靠一个约定目录：扫它，别家装的技能自动可见。
- [p4-08] 实测不对称：Codex原生只用它，VS Code的教程也用它。
- [p4-09] 发起方Claude Code的文档，列的却是自家一整套体系，没提这个约定。
- [p4-10] 互操作不是统一路径，是别人肯多扫你一眼。

> 画面：三家客户端扫目录对照（Codex 四级 / VS Code 教程 / Claude Code 自家体系）

- [p4-11] 再拆一条：目录块的转义。
- [p4-12] 目录块不是死数据，是一段会被照着执行的文字。
- [p4-12a] 所以name和description要转义——把可能冒充格式记号的字符，改写成只当文字看的写法，这是唯一边界。
- [p4-13] 我们的实验：一行恶意description夹带闭合标签，伪造出一个不存在的技能。注入，从零变成一。
- [p4-14] 而location字段，官方实现至今不转义。留白，留给客户端。

> 画面：X3 注入演示（目录块文本层：左绿转义拦截 / 右红伪行混入高亮；角标：location 不转义）→ **archify full**：lifecycle 注入防御

- [p4-15] 同一件事，官方交出了两份答案。这就说到它的两张面孔。

## P5 交警与年检

- [p5-01] 规范自带官方校验器，定位像车辆年检。
- [p5-02] 装载像交警路面执法：车牌样式不对，警告一句照放行——先保路上通。
- [p5-03] 校验器是年检：多一个没登记的字段就打回——保的是完全合规。
- [p5-04] 两轨并行不悖。年检还是自愿的：校验器打回的技能，宽容客户端照样跑。

> 画面：**archify full**：dual-track 校验轨道+装载轨道

- [p5-05] 读一遍源码，能数出规范、参考实现、客户端三方之间的六处分歧，最直观的一条在字段上。
- [p5-06] 规范说六个字段；校验器白名单，多一个打回。
- [p5-07] 同一家厂商：上传面只收六字段，多一个一键报错；本地面收二十个。
- [p5-08] 必填字段也各说各话：规范说name必填；Claude Code说name可选，不填的话默认取目录名。

> 画面：**archify full**：dual-track 扩展三家

- [p5-09] 把年检的门装到店门口会怎样？我们试了。
- [p5-10] 六字段白名单挪用到装载路径：带扩展字段的技能整体消失，装载面六分之一没了。
- [p5-11] 出厂检验的门，不能当店门。严格保纯净，宽容保连通。

- [p5-12] 标准怎么管住复杂度？答案近乎冷酷：加易删难，拿不准就不加。
- [p5-13] 代价看得见：截至2026年9月底，五十一条公开修改建议在排队，代码主线已经冻结了一个多月。
- [p5-14] 等不及的功能从侧门长出来——各家私有扩展，绕开规范自己生长。
- [p5-15] 门关得越久，侧门越多。互操作的裂缝，就是这么慢慢长出来的。

- [p5-16] 把五条规律摆在一起，答案自己会浮出来。

## P6 刻意做小

- [p6-01] 全片拆完，五条规律收拢。
- [p6-02] 成本按使用付费：常驻的只有目录一行。
- [p6-03] 路由压在那一句话招牌上：跟着模型走，不跟着客户端走。
- [p6-04] 身份借文件系统：不设发牌机构，竞对才敢押注。
- [p6-05] 技能是被解释的文本，不是被执行的代码：格式因此做得小。
- [p6-06] 最后一条，互操作压倒大而全。每个新要求，都是每家做客户端的永久成本。

> 画面：**archify full**：dual-track 守门哲学 → 五规律卡墙逐张点亮（回扣菜单/招牌/门牌/文本/留白）

- [p6-07] 所以它不是没做完，是刻意不做。
- [p6-08] 管得越少，越多人敢用。截至九月底，四十六家登记采纳的，就是这份克制。
- [p6-09] 分发、信任、版本，全留给生态——那是一场还没打完的战争，不展开。

- [p6-10] 三句如实的护栏：四十六家是自报登记，没有第三方复核。
- [p6-11] 同一个技能包在不同客户端，行为可能不同——扩展字段互不兼容，描述还可能被截短。
- [p6-12] 信任与防篡改，基本缺席。装别人的技能之前，allowed-tools先看一眼。

- [p6-13] 回到开场那个问题：一个文件夹，凭什么成为标准？
- [p6-14] 现在你能用机制回答它，一个比方都不用。
- [p6-15] 顺手也能自己写一个：建个文件夹，填对两行——你的规矩，从此可携带。
- [p6-16] 下期再见。
