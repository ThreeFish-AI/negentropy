## §1 它要解决什么问题

**主旨综述**：「模型能干」与「把活干对」之间隔着一层工序上下文——法务审查的流程口径、数据管道的团队约定、内部 API 的调用坑位。这层知识有两个致命属性：每次会话都要重新在场（模型不会替你记住），以及塞进上下文就有代价（占额度、互相抢注意力）。两条老路都死：让模型猜，不可靠、不可复现；把手册塞进开场白，成本随「装了多少知识」增长而非「用了多少知识」增长，且指令越多彼此稀释越严重。Agent Skills 据此给出五条设计规格，分别锚定后续各机制章。

**核心机制与数字**：
- 五条设计规格 → 机制映射（230 §1 表）：成本按使用付费 → 三级渐进披露（§4）；身份去中心 → name 必须等于目录名（§3）；路由一句话 → description 独扛触发（§5）；格式极小可被竞对采纳 → 六字段+大量留白（§3、§11）；知识可携带 → 文件夹即包、git 即半层分发（§6）。
- 关键原句：「成本随『装了多少知识』增长而非『用了多少知识』增长，且指令越多彼此稀释越严重」[1]。

**风险与边界**：「每次会话都要重新在场」与「塞进上下文就有代价」是两条老路都死的前提，口播不得省略其一。§1 规格表的「通俗版」列全部是港口系类比——本集禁用，须换菜单/门牌/招牌体系重述（见类比登记表）。

**可入视频的叙事素材点**：「两条老路都死」正反对比开场；五条规格逐条揭晓的骨架（每条钩住一个机制章）；白话主线句「模型缺的不是聪明而是『你家怎么干活』的工序知识」（230 文首 TIP）。

## §2 全貌解剖

**主旨综述**：230 把整个标准切成五层：格式契约（唯一权威源 specification.mdx：目录结构/六字段/身份规则/三级渐进披露/一层深引用/校验入口）、客户端契约（实现指南，建议而非强制）、创作方法论（四篇官方指南）、证据链（46 家登记/仓史 145 提交/三家客户端实测/规范↔实现分歧/原型实验）、领域坐标（vs MCP、vs CLAUDE.md 类常驻记忆、vs 传统插件）。再给一条因果脉络链（观察→归因→设计规格→机制→证据闭环）与按价值排序的五个焦点，并就地定义三个背景词。

**核心机制与数字**：
- 五层表 + 因果脉络链 [230 §2]；证据链层含「46 家登记数据 / 仓史 145 提交节奏 / 三家客户端口径实测」[230 §2 表]。
- 五个焦点（按价值排序）：①三级渐进披露（经济学核心）②description 路由与触发评测法 ③规范↔实现的边界 ④创作方法论四支柱 ⑤治理哲学。
- 三个背景词就地定义：token（模型读写的计件单位，每轮看到的文字总量有硬上限，塞进去的每段文字互相抢注意力）、system prompt（每轮都在场的开场文字，技能目录常驻其中）、frontmatter（文件开头两行 `---` 之间的属性卡）[230 §2]。

**风险与边界**：实现指南是建议层非规范——客户端行为是「建议的形态」不是「标准的强制」。§2 表中「港口怎么用包裹」措辞属港口系，口播改「客户端怎么用包裹」。

**可入视频的叙事素材点**：五层表即开篇全景视觉坐标（Map-First）的高亮结构；三个背景词可做就地教学三连卡。

## §3 格式契约：文件夹即包裹，目录名即身份

**主旨综述**：一个技能就是一个文件夹，里面必须有 `SKILL.md`：开头是 frontmatter 属性卡（六个约定字段），后面是写给模型读的说明书——正文零格式限制，规范原文只有一句「写任何有助于 agent 完成任务的内容」。最省事的一笔是身份规则：技能叫什么名字不由任何机构分配，直接借用操作系统的目录树——name 必须逐字等于父目录名，改名挪文件夹就是另一个身份。quickstart 的 roll-dice 例不到 20 行端到端跑通，反向走查则演示校验器对名实不符立即报错。

**核心机制与数字**：
- 六字段表 [1]：`name` 必填，1–64 字符，Unicode 小写字母/数字/连字符，不首尾连字符、无连续连字符，**必须逐字等于父目录名**；`description` 必填，1–1024 字符，应同时说「做什么+何时用」；`license` 可选；`compatibility` 可选，1–500 字符；`metadata` 任意 string→string 映射（客户端私有扩展的标准去处）；`allowed-tools` 可选、**实验性**。
- 三个约定俗成子目录：`scripts/`（可执行代码）、`references/`（按需加载的参考文档）、`assets/`（模板、图、数据）[1]。
- quickstart：`.agents/skills/roll-dice/SKILL.md`，「整个技能不到 20 行」；问「Roll a d20」→ 正文整份读入 → `<sides>` 替换成 20 → 返回 1–20 的随机数 [1]。
- 反向走查：name 写 `roll-dice-x` 而目录叫 `roll-dice`，官方校验器报「Directory name 'roll-dice' must match skill name 'roll-dice-x'」[2]。

**风险与边界**：NFKC 归一（`café` 两写法视为一致；中文名「技能」、俄文名「навык」都是合法 name）是**参考实现**的行为，规范未提（§8 分歧 5）——口播须归属 skills-ref，不得说成规范条文。

**可入视频的叙事素材点**：门牌比方（含 230 自带失配句）；roll-dice 具象输入流转（「Roll a d20」→ `<sides>`=20 → 命令执行 → 随机数）是 Animated State Trace 的现成素材；校验器报错原文可上角标。

## §4 渐进披露：装多少技能，只为用过的付钱

**主旨综述**：整个格式的经济学核心，像一家餐厅的菜单：每道菜在菜单上只占一行，这一行常驻不占厨房；客人（模型）自己看菜单决定点哪道，点了厨房才为这道菜开火占灶；菜谱之外的备料手册放后厨架子上，做这道菜要用到才去翻。落到规范是三级记账：目录（name+description 常驻）、正文（激活整读）、资源（按需）。装 20 个技能不等于预付 20 份正文；已激活技能在上下文压缩时列为不可裁剪的保护内容。原型实测给出全链路账本，破坏实验 X4 证明拆掉按需性常驻 +13%。

**核心机制与数字**（全部 230 原样口径）：
- 三级表 [1]：目录「每技能约 50–100 token」，会话启动常驻；正文「建议 <5000 token、正文 <500 行」，激活时整读；资源按需。
- 明账：「装 20 个技能不等于预付 20 份正文——只有当轮对话真正用到的技能才占用正文额度」[1]。
- 反面账：「按每份正文约 3000 token、装 20 份估算即约 6 万 token 常驻（本篇推断示意算式，3000 为取值于规范建议上限内的示意值）」——口播必须带「示意估算」口径。
- 真实客户端硬化：Codex 规定「初始技能目录最多占模型上下文窗口的 2%、窗口未知时 8000 字符，超限时先截短各技能的 description，技能很多时可能省略部分技能并给出警告」[4]。
- 压缩保护：指南要求把已激活技能内容列为「不可裁剪的保护内容」，否则「模型会继续干活但悄悄失去专门指令，性能退化且没有任何报错」；建议激活去重 [1]。
- 原型实测账本（实际运行日志，chars/4 近似口径）：「6 个技能的目录块共 454 token 常驻；一轮五项任务共激活 5 份正文 +62、按需读 1 份参考文件 +97，常驻合计 613」；X4 拆按需性后「常驻从 613 涨到 694（+13%）」「tier3 97→0、tier2 62→240」，涨幅恰好等于从未被读到的 scripts/submit.py 的体量。

**风险与边界**：~50–100 / <5000 是规范/指南的估算与建议值，材料未给实测方法（§12-2）；chars/4 是同口径相对比较的近似换算（「约四个字符折一个 token」）。

**可入视频的叙事素材点**：餐厅菜单三拍动画（菜单一行/点菜开火/后厨手册）；账本动态标尺（454 → +62/+97 → 613 → X4 694）；「中途清理桌面也不许把它收走」的压缩保护画面；配图 agent-skills-std-lifecycle（图一句话结论：「四步生命周期里只有目录是常驻成本，正文与资源都在『用上』那一刻才记账，压缩环节是唯一的例外保护点」）。

## §5 路由：一句话决定技能何时被启用

**主旨综述**：技能什么时候被用起来，靠的全是属性卡里那句 description——像店门口的招牌：一句话说清「卖什么、什么情况该进来」。客户端把每个技能的 name+description 登记进目录块（注入 system prompt 或专用工具描述），模型每轮拿任务与这句话比对，觉得对得上就整份读入；判断完全交给模型自主，多数实现不做 harness 侧的关键词匹配或触发器。写窄漏触发、写宽误触发，官方给了一套四步的「招牌测试」评测法，防的就是把招牌调成只认识熟客的脸。

**核心机制与数字**：
- description「1024 字符的硬上限」[1]；写法四原则：祈使句（「当…时使用」）、对用户意图而非内部实现、宁可写 pushy、保持简洁 [1]。
- 评测法 [1]：出题「约 20 条真实用户请求，一半应触发、一半不应」，最有价值的负例是「近失」（例：「更新 Excel 预算表里的公式」对 CSV 分析技能），正例沿措辞正式度、领域点名与否、细节多少、单步/多步四轴变化；跑分「每条跑 3 次算触发率（模型行为非确定），阈值 0.5」，「触发」的判定是 SKILL.md 是否真的被读入；防背题「请求集按 60/40 分训练/验证」「绝不把失败查询的关键词抄进描述」；收敛「约五轮通常够；卡住时换描述的结构而非继续微调」。

**风险与边界**：230 如实登记——「材料没有给出『模型自行判断为何足够可靠』的依据，也没有跨客户端触发一致性的实测」；「Codex 明言超预算时会截短 description」[4] 再引入口径差。这五点入 §12「材料没有证明的事」。

**可入视频的叙事素材点**：招牌比方 + 写窄/写宽双向失败动画；近失负例是最佳具体例；「把招牌调成只认识这 20 个人的脸」防背题金句；背题王（见类比登记表）。

## §6 客户端契约：扫描、宽容、注入、放行

**主旨综述**：实现指南（建议层）给出五步生命周期：发现、解析、披露、激活、长会话管理。发现至少扫项目级与用户级两个作用域，同名时项目级压用户级并告警；解析按宽容原则装载——名字不符或超长警告照载，description 缺失或 YAML 完全不可解析才跳过；披露时被禁用技能应整条隐藏、一个技能都没有时整块省略；激活有普通读文件与专用激活工具两条通道；长会话管理做压缩豁免、激活去重与可选子代理委派。`.agents/skills` 约定的实测口径不对称：互操作靠「别人多扫我」而非统一路径。

**核心机制与数字**：
- 五步生命周期 [1]；「至少扫两个作用域——项目级（随仓库走）与用户级（跨项目）」，「同名时项目级压用户级、并告警」；扫描边界指南举例「深度 4–6 层、约 2000 个目录」，跳过 `.git`/`node_modules` [1]。
- 宽容装载分级：名字与目录不符或超长→警告照载；description 缺失或 YAML 完全不可解析→跳过并记日志；坏 YAML 建议包裹引号重试 [1]。
- 激活双通道 + 用户侧「`/技能名` 式显式调用」+ 技能目录加入权限白名单（否则读附带文件每步弹确认框）[1]。
- `.agents/skills` 不对称实测：Codex 原生只用它（「项目链 CWD→仓库根 + 用户 `$HOME` + 管理员 `/etc/codex/skills` + 系统内置」四级）[4]；VS Code 教程也用它 [1]；Claude Code 文档列自家一整套位置体系（`.claude/skills` 企业/个人/项目/嵌套、插件内 `skills/`、claude.ai 账号同步），「全文未提 `.agents/skills`」[3]——互操作实际靠「别人多扫我」（指南也称一些实现会兼容扫描 `.claude/skills`）达成。

**风险与边界**：指南是建议而非强制；「项目级技能可能来自不可信仓库，指南建议挂信任门」[1]。

**可入视频的叙事素材点**：quickstart 的 VS Code 场景走查（技能放 `.agents/skills/` → 聊天面板 `/skills` 确认在列 → 「Roll a d20」→ 许可放行 → 随机数；「工具调用可靠性随模型而异，模型可能不跑命令自行作答，可换模型重试」[1]）；「空目录块会让模型困惑」；「别人多扫我」互操作金句。

## §7 资源层与脚本：包裹里的工具怎么带

**主旨综述**：引用纪律：SKILL.md 里引用文件一律用相对技能根目录的路径且保持一层深——浅引用意味着确定的一跳。工具带法分两种：一次性命令直接引用现成工具（六大通道各配一句示例），自含脚本放进 scripts/ 并内联声明依赖。指南用整节给出 agent 友好脚本十则，第一条是硬要求：禁交互提示——agent 跑在非交互 shell，等待输入等于永久挂起。allowed-tools 的完整语义出自 Claude Code 文档：回合内免审批、下一条用户消息即失效，且仓库技能可以给自己授宽权限——用前先审。

**核心机制与数字**：
- 「保持一层深」（`references/REFERENCE.md` 可以，长链不建议）[1]。
- 六大通道：`uvx`/`pipx`（Python 包隔离执行）、`npx`/`bunx`（npm）、`deno run npm:`（带权限旗标）、`go run pkg@version` [1]；自含脚本：Python 用 PEP 723 的 `# /// script` 块配 `uv run`，Deno `npm:`/`jsr:` 导入天然自含，Bun 自动装包，Ruby 用 `bundler/inline` [1]。
- agent 友好脚本十则（浓缩）[1]：禁交互提示（硬要求）；`--help` 就是接口文档；报错带「错在哪/期望什么/下一步试什么」；结构化输出（数据 stdout、诊断 stderr）；幂等；输入用闭合集；破坏性操作给 `--dry-run`；退出码区分失败类型；危险默认要显式确认旗标；输出尺寸可控（「指南举例 1–3 万字符」超阈值会被截断，大输出默认给摘要或落盘）。
- 该写脚本的信号：「多次运行各自重新发明同一逻辑（画图、解析、校验）」[1]。
- allowed-tools（Claude Code 文档完整定义，规范只标「实验性」）：「调用该技能的那个回合内，所列工具免审批可用，下一条用户消息即失效；它不缩小可用工具池，也不受工作区信任门管」；安全提醒：「仓库里签入的技能可以给自己授予宽工具权限，用前先审它的 `allowed-tools`」[3]；语法 `Bash(git:*)` 即 Claude Code 权限规则写法，规范例句借用而「未在标准内定义语法」[3]。

**风险与边界**：allowed-tools 完整语义须归属 Claude Code 文档（规范只标实验性）；供应链专题在 230 §12 属 Out-of-Scope（只如实记录规范内留白，不做深挖）——口播涉安全时以此边界收口。

**可入视频的叙事素材点**：十则清单卡（首条「等待输入=永久挂起，这是硬要求」最抓人）；「多次运行各自重新发明同一逻辑」的重复劳动画面；allowed-tools 自授宽权限的安全警示（角标归属 Claude Code 文档）。

## §8 校验与双轨：同一官方面孔的严格面与宽容面

**主旨综述**：规范指定 `skills-ref validate` 为官方校验入口（检查 frontmatter 合法与命名约定），参考实现自带 validate / read-properties / to-prompt 三命令。同一官方面孔的两面像交警路面执法与车辆年检：客户端装载是路面执法——车牌样式不对、车长超标，警告一句照放行，先保路上通；官方校验器是年检——多一个没登记的字段就打回，保的是完全合规。两轨目标不同、并行不悖，且年检自愿、无强制联动。重读源码锚定规范↔参考实现↔客户端三方六处分歧，分歧 1（字段面：上传收六、本地收二十）正是三个争议的实证底座。

**核心机制与数字**（六处分歧全部可定位钉点源码 [230 §8 表]）：
1. 未知字段：规范字段表未禁止第七个字段、指南建议宽容装载 vs 校验器六字段白名单一律报错 [2]；claude.ai 上传/打包只收六字段、多一键硬错 [3]；Claude Code 本地收 **20 个字段**（规范 6 + 扩展 14）[3]。
2. 文件名大小写：指南「名为 exactly `SKILL.md`」[1] vs 参考实现大写优先、兼收小写 `skill.md`（`find_skill_md`）[2]。
3. 空目录块：指南「无技能时应整块省略」[1] vs `to_prompt` 空列表仍输出空 `<available_skills>` 块 [2]。
4. 注入面：`to_prompt` 对 name/description 做 `html.escape`（转义），**location 字段不转义**——路径含特殊字符的注入面留给客户端 [2]。
5. 归一化：规范未提 Unicode 归一 vs 校验器对 name 与目录名做 NFKC 归一后再比对 [2]。
6. 必填字段：规范 name 与 description 必填 [1] vs Claude Code name 可选（默认取目录名）、description 仅「推荐」（缺省取正文第一行）[3]。

**风险与边界**：分歧表是「读任何开放标准的通用视角」素材，但每条都须带两面口径，不得只讲一面。

**可入视频的叙事素材点**：双轨治理面配图 agent-skills-std-dual-track（图一句话结论：「规范只钉六字段与目录形状，装载面宽容、校验面严格、扩展面各家自理，三条轨道各自服务连通性、纯净度与功能诉求」）；六分歧翻牌动画；金句「同一厂商在『上传面』收六字段、在『本地面』收二十字段」。

## §10 动手实验室

**主旨综述**：原型 agent_skills_lab4.py——纯标准库、469 行、确定性，「模型」由关键词匹配器替身，回答的是机制自洽而非模型聪明；token 为 chars/4 近似口径。复刻全链路：发现（项目/用户双域、同名项目压用户、宽容装载、目录名身份）→ 目录块（XML、转义）→ 激活（整读正文、去重）→ 按需资源 → 压缩保护，外加镜像 skills-ref 的严格校验器。12 assert 全绿之上，X1–X5 五次破坏性实验各拆一个核心约束，实测退化全部有日志为证。

- 破坏性实验三件套（实测退化均为实际运行日志）[230 §10 表]：
  - **X1** 拆「name=目录名」（装载改按 frontmatter 名建档）：「目录 6→5；『合并周报』技能静默消失、任务 no-match，无任何告警」——身份不借文件系统，名字漂移等于技能蒸发。

## §11 底层规律与核心争议

**主旨综述**：把前面各章的机制与证据收拢成五条底层规律，每条各管一个维度——成本结构、信号路由、身份、执行模型、治理边界——合起来回答「这个格式为什么长这样、生态为什么愿意长这样」；再讲三个仍悬而未决的争议：严格还是宽容、关门哲学与功能排队、互操作约定与私有目录。规律与争议互为表里：规律解释设计取舍，争议登记标准自己都还没裁决的张力。

**核心机制与数字**：
- 规律 1 · 成本按使用付费：常驻成本与使用成本分离；没有它「装机量=常驻成本且指令互相稀释」[1]；生态硬化=Codex 的 2%/8000 预算门 [4]。
- 规律 2 · 一根字符串的路由：「何时用」的全部信号压在 ≤1024 字符的 description 上，由模型自主比对、「实现方不做关键词引擎」[1]；路由若由客户端各自实现，同一技能包行为随客户端分化、可携带性死亡；反面：抄关键词=背题王 [1]。
- 规律 3 · 身份借文件系统：无中心发牌，标准才能无主、竞对才敢押注；重名从全局仲裁降维成本地优先级 [1]；反面：X1 拆除后技能静默蒸发。
- 规律 4 · 被解释的文本，不是被执行的代码：执行权与安全责任留在模型和客户端；若技能是代码，沙箱/权限/签名就得成为格式第一公民，格式做不小 [1]；反面：X3 注入实测。
- 规律 5 · 互操作压倒完备（互操作＝各家产品彼此直接通用）：标准刻意只钉六字段与目录形状，分发/信任/版本/执行留白——「每个新要求都是所有实现方的永久成本」[1]；CONTRIBUTING「加易删难…拿不准宁可不加」[1]；反面：若规范强制统一目录路径，固守私有路径的客户端即无法合规。
- 争议 1 · 严格还是宽容：同一官方两面下注（校验器白名单 [2] vs 指南宽容装载 [1] vs Claude Code 二十字段 [3]），标准自己未裁决。
- 争议 2 · 关门哲学与功能排队：复杂度成本全体承担、收益提案方独享（账本不对称）；「51 条 PR」=排队待合并的公开修改建议；官方「宁缺」的代价是功能以客户端私有扩展旁路生长（「Claude 的 model/hooks/context、Codex 的 openai.yaml 策略文件」[3][4]），长期反噬互操作面；「main 冻结 52 天而 51 条 PR 排队是实证」[5]。
- 争议 3 · 互操作约定与私有目录：`.agents/skills` 在非发起方中扩散（VS Code [1]、Codex [4]），发起方固守自家位置体系（文档零提约定目录 [3]）——互操作由「宽容多扫」而非「统一路径」达成，是规律 5 在目录层的重演。

**风险与边界**：五条规律是 230 的综合提炼（评判层），口播引用可归属「精读结论」而非规范原文；三个争议是开放张力，不得讲成已有定论。

**可入视频的叙事素材点**：五规律×五维度收拢图（全片骨架级结构）；「互操作＝各家产品彼此直接通用」定义句；账本不对称（成本全体承担、收益提案方独享）的治理叙事。

## §12 适用边界

**主旨综述**：成立条件：研究对象为格式规范（钉 69ef37e9）、官方七篇指南、skills-ref 参考实现与登记口径的生态现状；「把工序知识打包、给模型按需加载」的场景收益最大（团队约定、工具细节、领域流程）；本地客户端与云沙箱均适用（发现机制不同、生命周期相同）。Out-of-Scope 四项：供应链专题深挖、MCP 集成与协议级提案细节、46 家客户端逐一盘点（抽样三家定形态）、任何模型的路由准确率评测。另有五条「材料没有证明的事」，是全片理性收尾的护栏。

**核心机制与数字**：
- 「材料没有证明的事」五条 [230 §12]：①「46 家支持」是自报登记（「今日即可发现并执行」门槛与 logo审核 [1]），无第三方复核兼容深度；②三级 token 口径（~50–100、<5000）是估算与建议值，无实测方法或跨模型实测数据 [1]；③「description 路由有效」无跨客户端触发一致性实测，「模型判断为何足够可靠」无依据，Codex 超预算截短描述 [4] 引入口径差；④「跨产品复用」实际程度未证明（同名冲突各家自裁、扩展字段互不兼容六字段 [2] vs 二十字段 [3]、描述可能被截断 [4]）；⑤信任与完整性基本缺席（指南仅两处建议级文字 [1][3]；实测三家客户端文档均未提及签名或完整性校验）。

**风险与边界**：本节即边界护栏卡的原料——成立工况与 Out-of-Scope 两侧都要上画面；「46 家」表述须带自报口径。

**可入视频的叙事素材点**：尾幕边界护栏卡（C 型素材映射契约第 5 条）；五条「没证明」清单逐条打钩收尾，防全片过度承诺。

## §13 用户自测与费曼研讨套件

**主旨综述**：230 文末配三道自测题：费曼题要求不用本篇任何比方、纯机制语言解释「为什么这个标准只有六个字段，却值得 46 家客户端（包括几家互为竞争对手的厂商）采纳」——把「留白」与「采纳」的因果链讲完整；决策题给团队引入技能包前应做的对照实验（验证「真增量」、识别不做对照最可能高估什么）；争议研讨题把观众放进标准守门人位置，按 CONTRIBUTING 门槛与「互操作压倒完备」裁决一条「给规范加版本字段」的 PR。

**风险与边界**：题目是开放研讨，没有标准答案——用作互动素材时不得给出唯一解。

**可入视频的叙事素材点**：费曼题可直接化为结尾互动问句（「关掉视频，你能不用任何比方把它讲一遍吗」）；决策题的「最可能高估什么」可做开放式收尾钩子。
