## 贯穿请求（全片 Worked Example）

**用户在对话里问 Agent：「上季度华东区的重复购买率是多少？」**

- 涉及的真实对象：指标定义「重复购买率」（definitions 注册表一行）、订单表与客户表、用户（运营专员，能看订单域、不能看客户手机号）、核准问答对（题库里已有「重复购买率」的验证查询）。
- P0 抛出这个请求可能出的三种错；P2–P6 各在对应组件里走一遍；P7 完整走完读管线 7 段；P8 对账现状。

## 六段两环（§9）

| 段 | 名称 | 一句白话 |
|---|---|---|
| L1 | 采集登记 | 每条记录带来源入账；三项入账校验：鉴权、只收完整交付、对象可解析 |
| L2 | 校验与裁决 | 结构校验（外键/成环/聚合）+ 语义裁决（冲突交人裁决） |
| L3 | 装配执法 | 每轮重新装配、权限实时求值、持久层只存指针 |
| L4 | 应答锚定 | 三条出路：命中核准答案 / 按定义现算 / 明确告知缺口 |
| L5 | 沉淀与回写 | 会话与错答写回成新资产 |
| L6 | 衰减退役 | 失效对象有删除路径并留记录 |
| 验证环 | L4 → L2 | 答错的结果回去修定义 |
| 进化环 | L5 → L2 | 使用数据沉淀成新规则 |

G1–G7（只点名、不逐条念）：G1 执法点绑定 / G2 注册期校验与运行期校验互不替代 / G3 裁决权不自动化 / G4 治理与验证分开落位 / G5 指针不副本 / G6 退役路径必备 / G7 闭环可观测。

## 两条管线（目标态，非仓库现状）

**纳管管线（写入）**：Ingest 登记指针 → Normalize 归一（章节路径、内容模块、非文字元素、分级摘要；不调用 LLM）→ Classify 治理字段分类 → Tier 分级（L0 ≤256 字符 / L1 ≤4000 字符 / L2 只存指针）→ Tag/Index 打标、向量化、分配 ctx:// 地址 → 目录条目。

**读管线（读取）**：ContextRequest → ① Resolve 主体与可见性 → ② Plan 意图与各域预算 → ③ Retrieve 精确查询 + 召回并行 → ④ Fuse RRF 融合 + 信任重排 → ⑤ Guard 五项检查（可见性/作用域/效力/PII/指令越权，拦下的进 dropped/overrides 留痕）→ ⑥ Compose 按 token 预算裁剪 → ⑦ Emit 组装 ContextBundle（每项带 uri@version）。

接头：纳管产出的目录条目，就是读管线 Retrieve 取用的对象。
