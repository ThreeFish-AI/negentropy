## P0 越干越脏的对话

> 画面：系列片头装置之后冷启动——主对话消息列表面板占屏：消息条一条条堆高（读文件结果一屏屏刷过），最早的目标卡被不断挤出画面顶部；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一个越干越脏的对话：活干完了，中间过程还全留在里面。
- [p0-02] 课上的例子：查一个问题，读三十个文件、聊六十轮，涨到一百二十条。
- [p0-03] 大半是顺藤摸瓜的过程，理清就没用，却一直占位。

> 画面：聊天群既视感——消息流刷屏，一条旧「约定」气泡不断下沉变暗；「换更强模型」开关拨动，刷屏速度分毫不变

- [p0-04] 像聊天群刷屏：约定还在记录里，注意力只在最新一段。
- [p0-05] 人还能翻回去；模型没有这个动作——越长，目标越没分量。
- [p0-06] 换更聪明的模型也修不好：信息不在场，再聪明也看不见。
- [p0-07] 出路只有一条：让脏活，根本不进这个对话。

## P1 一间新会议室

> 画面：两间会议室剖面图首次亮出——左侧主会场（钢蓝描边、消息条整齐），右侧新会议室弹出（紫描边、暂时空置）；「谈完只带结论回去」的单向箭头预演一次

- [p1-01] 课上打了个比方：给子任务开一间会议室，谈完只把结论带回主会场。
- [p1-02] 机制上，主代理的工具表多了一件：派活的工具。

> 画面：子代理装配动画——全新消息列表空降，只有一张任务描述卡落底；「独立系统提示」标签贴上；五件工具卡依次入位

- [p1-03] 派单下去，程序拉起子代理：全新对话，只有这段描述。
- [p1-04] 一套自己的循环；独立的系统提示就一句：直接干活，别再往下派。
- [p1-05] 工具是基础五件：跑命令、读文件、写文件、改文件、找文件。

> 画面：工具列特写——派活卡缺席（空槽虚线）高亮；「30 轮」计数环亮起

- [p1-06] 唯独没有派活那件——递归深度，锁死在一层。
- [p1-07] 还有兜底：最多三十轮，到点没结论，就地收场。

> 画面：回流动画——子代理内部消息条快速堆高后整体淡出（清空），一条结论卡沿单向通道飞回主会场，落成两条新消息；环体〔M-001〕上「执行」段外侧亮起「派活→回流」支线

- [p1-08] 跑完只交回一条文本结论——作为派活结果，落进主对话。
- [p1-09] 中间几十轮？整体丢弃：这间会议室，用完就清空。
- [p1-10] 账面这么干净，真跑一遍呢？

> 角标：task · SUB_SYSTEM · SUB_TOOLS · range(30)

## P2 派一次活

> 画面：走查舞台——指令气泡落下「找一下这个项目用什么测试框架」；目录树亮出六份代码文件（a.py 到 f.py）；主代理不接，转手派活，描述卡飞进右侧会议室

- [p2-01] 走个例子。你说：找一下这个项目，用什么测试框架。
- [p2-02] 目录里六份代码文件；主代理不动手，直接派活。
- [p2-03] 子代理的新对话里，只有这一句任务。

> 画面：子代理侧特写——六份文件挨个读入、消息条逐条堆高；收尾时全部消息条集体淡出，一句结论卡沿通道飞回；主对话侧只落两条：派活记录 + 结论

- [p2-04] 它开跑：六份文件挨个读，交回一句结论。
- [p2-05] 主对话这边，只多两条：一次派活，一条结论。
- [p2-06] 子代理里面那十五条消息呢？用完就清空，一条不留。

> 画面：三栏对比全景——「派活」4 条/147 字符（钢蓝）·「亲自动手」14 条/2626 字符（灰）·「子代理内部」15 条/2617 字符（紫，自生自灭标注）

- [p2-07] 实测对比：派活，主对话四条、一百四十七字符。
- [p2-08] 亲自动手：十四条、两千六百二十六——过程全数落账。
- [p2-09] 这还只是省；拆了规矩，才见真章。

> 角标：task(description=…) · tool_result · pytest

## P3 只回结论

> 画面：实验装置卡——「规矩开关：只回结论 ↔ 回传全部子历史」拨杆拨到右侧；回流通道变粗，十五条子历史整列涌入主对话（警示红泛起）

- [p3-01] 只回结论这条规矩，值多少钱？拿实验说话。
- [p3-02] 改法一句话：跑完不交结论，整段子历史原样搬回。
- [p3-03] 结果：主对话十六条、两千六百四十九字符。

> 画面：左红右绿消融同屏——右「只回结论在位」：4 条/147 字符（确认绿）；左「回传全史」：16 条/2649 字符，消息条灌满面板（警示红）；「×18」大数字 punch

- [p3-04] 规矩这边：四条、一百四十七字符——差出十八倍。
- [p3-05] 会议室照开、活照干，装置一个没少——就回流那步松了手。
- [p3-06] 多出来的十二条，就是理清就没用的过程，灌满主对话。

> 画面：金句卡（衬线体）落下；随后会议室剖面图——两室之间的墙被高亮打上问号，墙体隐约透出「白板」轮廓（下一拍伏笔）

- [p3-07] 一句话：只回结论不是锦上添花，是主对话上下文的存亡线。
- [p3-08] 不过先别放心：这间会议室的墙，隔住的比你想的少。

> 角标：extract_text · return sub_history

## P4 隔离的边界

> 画面：两间会议室全景拉开——中间墙体内嵌一大块「白板」亮出

- [p4-01] 隔离的到底是什么？消息——不是进程，也不是文件系统。
- [p4-02] 这个比方还有后半句：两间会议室，共用同一块白板。

> 画面：白板特写（同一工作目录）——子代理写的文件、跑的命令痕迹直接出现在主会场视野里

- [p4-03] 写的文件、跑的命令，全落同一个工作目录——主代理看得见。
- [p4-04] 丢弃的是对话，从来不是工作成果。

> 画面：权限门特写——子代理的工具调用走到执行前的检查点，一道门拦下「删光整盘」命令卡（警示红×），弹回一张拒绝条；子代理换下一个动作继续；随后官方文档卡——数字线 15,000 tokens 刻度上指针超标、告警铃亮起

- [p4-05] 更容易漏的是权限：子代理每次用工具，照样过执行前的检查点。
- [p4-06] 实测里它上手就想跑删光整盘的命令——被拦下，吃张拒绝条，接着干活。
- [p4-07] 上下文隔离，从来不等于权限豁免。
- [p4-08] 官方也画了条线：自建子代理的描述合计超一万五——模型计字的单位——启动就告警。

> 画面：真实版对照引入——教学版装置淡出，真实版界面剪影淡入

- [p4-09] 那真实的 Claude Code 呢？
- [p4-10] 拆解过 Claude Code 源码的同学们应该知道：有一种跑法，不建全新对话。

> 画面：两列对话前缀逐字节对齐动画（绿点逐格点亮），缓存命中标记落下；权限弹窗沿「冒泡」轨迹上升回到用户终端；收尾装置全图定格——主会场保持清爽，侧边一堆「知识文档」剪影缓缓压来（P5 知识钩伏笔）

- [p4-11] 它把前缀造得和主对话逐字节一致，专为命中缓存，省钱省时。
- [p4-12] 隔离与效率，是一对真实的权衡；权限弹窗，照样冒回你的终端拍板。
