## P0 三个症状一个病根

- [p0-02] 销售负责人问 AI 上季度收入，答，一千四百二十万美元。
- [p0-03] CFO 同一天、问同一份数据。答，一千两百八十万。

> 角标：$14.2M vs $12.8M · 证据徽（虚线·厂商自报）：Snowflake 公告博客

- [p0-04] 数据是同一份，模型也没换，一百四十万美元的差距从哪来？
- [p0-05] 差在「收入该怎么算」，全公司没有一份说了算的定义。

> 定义卡母题首次出现——画面是一张空卡座（卡不在场）。

- [p0-06] 第二个症状：让 AI 对着裸数据库答业务题。

- [p0-08] 模型不是不会写 SQL，是不知道你家的列名在说什么。

## P1 七机制地图

- [p1-01] 先建立坐标系。数据平台手里的上下文信号，官方分成四层。
- [p1-02] 第一层问「有什么」：表、列、血缘，结构信号；第二层问「正在发生什么」：查询、新鲜度，运行信号。
- [p1-03] 第三层问「它是什么意思」：定义、指标，语义信号；第四层问「它被怎么用」：热度、模式，行为信号。

> 角标：Structural / Operational / Semantic / Behavioral；四层信号并排卡用「折前总金额」列落位

- [p1-04] Horizon Context 干的事，就是把四层信号铸造成受治理的对象。
- [p1-05] 整个系统分八层：底座是数据和引擎，往上依次是定义、执行、供给、应答、账本、身份、出口。

> 八层分层矩阵全景（component-panorama）：承重七格金色描边、供给出口两区降饱和

- [p1-06] 真正承重的是七个机制：定义、策略、治理、背书、血缘、身份、纳管。
- [p1-07] 供给和出口的配件可以换，承重七件拆任何一件，系统塌一角。
- [p1-08] 检验办法也定好了：每讲一件，就把它拆掉一次，看链条在哪一环断。

> 「七机制×十次拆坏」预告墙（mechanism-experiment-matrix）

- [p1-09] 配一个玩具级的原型实验室，十个破坏实验，每个只动一颗螺丝。
- [p1-10] 从最重的那件开始：语义视图。

> 定义卡母题推近，准备注册（转场）

## P2 口径与现算

- [p2-01] 语义视图，存进数据库的定义性对象，一段元数据。
- [p2-02] 主键是唯一标识每一<行|HANG2>的列，外键指向别表主键；粒度，是汇总时按什么分组。

> 术语卡三连（先释后用）

- [p2-03] 这件机制要同时守住两条底线。
- [p2-04] 第一条，口径单点：「净收入是什么」，全公司只允许存在一份定义。
- [p2-05] 它用五段式语法写进库：表和主键、表间关系、行级事实、切片维度、聚合指标。

> 角标：TABLES→RELATIONSHIPS→FACTS→DIMENSIONS→METRICS；定义卡母题正式注册（金描边点亮）

- [p2-06] 注册时过结构校验门：外键须指向主键、关系不许成环、指标必须带聚合——非法定义死在注册那一刻。

- [p2-07] 第二条，查询期重算：视图里不存算好的数字，你问，引擎此刻按定义从头算。
- [p2-08] 为什么非要现算？两个独立的坏法。
- [p2-09] 第一个，存下的数会过期：今天算好存下的收入，明天新进三笔订单就成了旧账，还没有机制提醒你。
- [p2-10] Snowflake 自家团队给 9685 张表建语义视图，覆盖率也不到 5%。

> 角标：<5% of 9,685 · 证据徽（虚线·厂商自报）

- [p2-11] 第二个坏法更隐蔽：顺序错了，合法的 SQL 照样算出错数。
- [p2-12] 一张一百美元的发票关联三条明细行，先拼表再求和，它被复制成三份，记成三百。
- [p2-13] 正确做法是先各自聚合、再拼接，<行|HANG2>话叫「先聚后连」。

> 角标：fan trap · fan-trap 图（红路径 vs 绿路径分叉）

- [p2-14] 「平均的平均」是同一个病的另一种发作。
- [p2-15] 九张单的店平均两人，一张单的店三十人：先各自平均再平均得十六，总客数除以总单数才是四点八。

> mean-of-means 图

- [p2-16] 还有半可加指标：余额今天五百、昨天五百，加起来不是一千——同一笔钱被数了两遍。

> 角标：NON ADDITIVE BY · last-snapshot-gate 图

- [p2-18] 拿 Ann 走一遍：她有三张一百美元的订单，每张挂着数量不等的操作事件。
- [p2-19] 问「Ann 的总收入」，引擎先在本表内聚合：三张订单收敛成一<行|HANG2>，三百。
- [p2-20] 全程根本没碰事件表。
- [p2-21] 要是把顺序写反，先拼表再求和：一张一百块的单挂三次事件，就被复制成三<行|HANG2>、记成三百。
- [p2-22] 玩具原型实测：引擎算两百，朴素写法记成四百四十。

> Ann 端到端走查（逐拍状态变换：请求→本表聚合→连表取名→输出）；证据徽（实心·本仓复算）：engine 300 vs naive 600

- [p2-23] 再拆一次：把校验门关掉。
- [p2-24] 外键指向了根本不是键的列，垃圾定义静默入库；门在，当场拦下——这是第一条保险。

> 消融对比（红/绿同屏）：拆校验门 → 非法结构入库 vs 门在位 → 注册期拦截；角标 D6 · 拦截日志 referenced column is not PRIMARY KEY

- [p2-25] 性能疑问：每次都现算，会不会慢？
- [p2-26] 官方后手是物化，把常用的维度指标组合预先卷好，基准查询加速五十九到九十一倍。
- [p2-27] 两个限定：只加速走语义层的查询；涉及打码、扣行这类安全策略的列，改写直接放弃——治理压过性能。
- [p2-28] 一句收口：SQL 合法，不等于答案对。

> 角标：TPC-DS 4 查询 59–91× · 359GB→120MB · 证据徽（虚线·厂商自报）；金句卡（衬线体）

## P3 规则与执法

- [p3-01] 定义统一了，下一个问题：谁可见。
- [p3-02] 掩码策略，按人把敏感值打码；<行|HANG2>访问策略，把无权的<行|HANG2>整<行|HANG2>扣掉。

- [p3-03] 聚合约束限制汇总粒度，比如禁止数到个人；投影限制让某列干脆不出现在结果里。
- [p3-04] 关键在挂的位置：策略长在数据本体上，在查询执行那一刻由引擎求值。

> 术语卡四连（row-column-policy 图配合）；定义卡母题：策略挂扣件扣上（紫）

- [p3-05] 第一，保护决定权与所有权分离：安全官定保护哪些列；掩码对特权角色同样生效，管理员看到的也是星号。
- [p3-06] 第二，策略自动传播：掩码挂底层表上，直接查、隔视图查、报表工具查，同一套打码。

- [p3-07] 还有一个专为 Agent 设计的开关。
- [p3-08] 策略体里可以问一句：当前会话，是不是 Agent 发起的？
- [p3-09] 同一个人，人工查询见明文手机号；Agent 会话问同一个问题，当场变星号。

> 角标：IS_AGENT_ACTIVATED · hidden-vs-blocked 图

- [p3-10] 走一遍：实习生查客户手机号。
- [p3-11] 请求进引擎，命中该列掩码策略，按策略主人定的规则判定，带星号出引擎。
- [p3-12] 现在把执行层的检查拆掉。
- [p3-13] 玩具原型实测：实习生按查询计划拿到了明文号码，泄露发生。
- [p3-14] 装回去，同一个请求当场被拒。执行层的拒绝是底线。

> 消融对比：拆执行层 → [90,560] 泄露 vs 在位 → blocked；证据徽（实心·本仓复算）；角标 D5

- [p3-15] 再往上一层是设计判断：规则是一回事，执法位置是另一回事。
- [p3-16] 常见做法把语义层外挂在系统旁边，每次查询两套系统对账——定义一漂移，AI 跟着错的走。
- [p3-17] Horizon Context 反着来：语义定义住在治理引擎里，查询时强制执行，不复制、不缓存。

> engine-governance 图：外挂拓扑 vs 内嵌拓扑对照

- [p3-18] 可检验的点：私有资产在检索层就被过滤；绕过检索硬写指标名，执行层再拒一次。
- [p3-19] 双层防线，前后相接。
- [p3-20] 一条底层规律浮现：治理的强制力来自执行点，不是定义点。
- [p3-21] 判断任何治理宣称，先问：绕开这个点会发生什么？什么都拦不住的，是装饰性治理。

> 金句卡：「强制力来自执行点」

## P4 背书与血缘

- [p4-01] 定义对、算得对，还有一层没管住。
- [p4-02] AI 生成的 SQL 可能挑错表、接错关系、用错粒度——语法全对，答案全错。
- [p4-04] 办法朴素：把有人签字的问答对，存进语义视图。
- [p4-05] 一道题、一条验证过的查询、验证人、验证日期，四要素齐全。

> 角标：VQR · Verified Query Repository；定义卡母题：签名盖章位（青）

- [p4-06] 新问题进来，先扫这道核准题库。
- [p4-07] 命中，就直接执行那条验证过的查询，不经过模型现场生成。
- [p4-08] 走一遍：有人问，上个月活跃用户多少。
- [p4-09] 题库命中，这条验证查询按月吐数：两百、一百五、三百，响应里带着验证人。
- [p4-10] 玩具原型同时用引擎重算了一遍，逐月对账，一致。

> 命中短路走查（vqr-lifecycle / one-checkpoint）；证据徽（实心·本仓复算）：verified == 重算

- [p4-11] 未命中走现算；没有治理定义覆盖，就明确告警，不硬猜。
- [p4-12] 三条出路里，没有「静默瞎猜」这个选项。
- [p4-13] 优化回路拿题库反推语义视图缺什么，自动建议补过滤器、补描述。
- [p4-14] 官方手册如实标了代价：优化真跑你的验证查询，每条至多四次，超二十条明显拖慢。

> 角标：up to 4 runs / >20 条拖慢 · 证据徽（虚线·官方文档）

- [p4-15] 第五件机制回答事后追问：这个数，当初从哪来。
- [p4-16] 血缘，就是数据之间的派生关系账本：哪张表的哪列、经什么语句、变成了眼前的哪列。
- [p4-17] 差异在端到端、列级：引擎里的语句自动记边，零配置。
- [p4-17b] 外部管道走开放事件协议，过三道闸——鉴权、可解析、对象可解析，全过才入账。

> 角标：OpenLineage · lineage-ledger 图（三道闸）

- [p4-18] 解析不了的事件整个拒绝，账本里没有虚构的边。
- [p4-19] 答案出错时，沿着答案、指标、表列回溯，找到最后一笔脏数据，而不是对着黑箱猜。
- [p4-20] 拆一次看看：把解析闸关掉。
- [p4-21] 玩具原型里，一条虚构的边混进账本，污染从入口开始。
- [p4-22] 闸在，三道全拒。对账的账本，第一美德是不撒谎。

> 消融对比：ghost-edge-pollution；证据徽（实心·本仓复算）；角标 D8

## P5 身份与纳管

- [p5-01] 前五件机制默认提问的是人，Agent 改变了这个假设。
- [p5-02] 它替用户干活，默认继承全部权限——连生产库写权和管理员角色。
- [p5-03] 一个替你查数的助手，不该拿着你全部的钥匙。

> agent-identity 图首现：入口标记

- [p5-04] 身份机制分两层。第一层，识别。
- [p5-05] 数据库认得出会话是不是 Agent 发起的，四种入口都算；谁授权、谁执行、动了什么，整条链可复盘。

> 角标：agent_type · agents_info

- [p5-06] 第二层，权限天花板。
- [p5-07] 管理员声明 Agent 活跃期间允许做什么，没列出的操作一律隐式拒绝。
- [p5-08] 实际权限等于用户权限与天花板的交集，只减不增。
- [p5-09] 交集每次查询实时求值，不存快照；会话期内锁死，换范围须重开会话。

> 角标：Restricted Session Scope · RBAC ∩ RSS（韦恩图 venn-intersection）

- [p5-10] 走一遍：管理员十点整设好天花板，十点零二分用户开出 Agent 会话，十点零五分回收了订单权限。
- [p5-11] 十点零六分 Agent 再查订单：交集为空，拒绝。回收即时生效，没有过期窗口。

> revocation-timeline / zero-window-sequence 图；证据徽（实线·第三方 Classmethod 实测）

- [p5-12] 拆掉天花板：假设权限改用快照冻结。
- [p5-13] 玩具原型里，权限已被回收，旧会话仍然查得到，越权窗口打开。
- [p5-14] 实时求值的意义，就是把这个窗口压到零。

> 消融对比：快照冻结 → 回收后仍持权 vs 实时求值 → 即刻失效；证据徽（实心·本仓复算）；角标 D9

- [p5-15] 最后一件机制补供给链：该保护的列谁来标？数据每天新增，人盯不过来。
- [p5-16] 分类引擎持续扫描库里的列，识别敏感属性，自动打上系统标签。
- [p5-17] 走一遍：夜里管道写进一张新表，其中一列是电话号码。
- [p5-18] 扫描识别、打标、查映射，治理标签上绑着掩码——次日任何查询拿到的都是打码值，全程无人工登记。

> classification-tagging / tag-gate-linkage 图：四步走查

- [p5-19] 链上有一道人工闸：掩码不能直绑系统标签，必须先经一次性映射，机器判断才接得进组织规则。
- [p5-20] 机器管发现，人管定规。
- [p5-21] 拆掉映射试试：只分类、不绑策略。
- [p5-22] 玩具原型里，新列已经贴上系统标签，照样明文出楼。
- [p5-23] 保护停在「贴了标签的裸奔」——这一环，省不得。

> 消融对比：已贴标仍明文 vs 映射在位自动打码；证据徽（实心·本仓复算）；角标 D10

## P6 供给与生态

- [p6-01] 七个机制放回官方叙事，是三个动词：收集、富化、激活。
- [p6-02] 上下文收进目录，元数据加工成含义，在工作现场自动起效。

> collect-enrich-activate 三段骨架图

- [p6-03] 最现实的问题是：定义从哪来？自家九千多张表，覆盖率不到 5%。
- [p6-04] 两条生产线补缺口。
- [p6-05] 显式轨道吃查询历史、表元数据、问答对文件，产出可编辑草稿，人审后发布。

> 角标：Autopilot（GA）· autopilot-loop 图

- [p6-06] 隐式轨道更激进：不建视图，直接从查询历史和报表指标里挖出一套工作理解。
- [p6-07] 排序按四因子：相关性、权威性、热度、新鲜度，受治理的定义权威最高。

> 角标：Cortex Sense（私预）· four-factor-ranking 图

- [p6-08] 最值得记的设计：冲突浮出，人工裁决。
