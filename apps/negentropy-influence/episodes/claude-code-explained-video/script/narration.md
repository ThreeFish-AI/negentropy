## P0 会写不会做

> 画面：系列片头装置之后冷启动——终端窗口中央一条写好却无人按下的命令行，光标孤闪

- [p0-01] 这是让模型真正动手的全部秘密：把每一次执行的结果，喂回给它自己。
- [p0-02] 听着太简单了，简单到不像话。
- [p0-03] 但你平时用的聊天式模型，缺的恰恰就是这一下。
- [p0-04] 你让它列个目录、跑个脚本，它能写出一条正确的命令。
- [p0-05] 然后就没有然后了。
- [p0-06] 命令停在那儿，等你复制、等你粘贴、等你按下回车。

> 画面：用户头像在「模型—终端—模型」之间来回搬运箭头，搬运次数计数器疯涨

- [p0-07] 输出出来，你把结果贴回对话框，下一条命令才出来。
- [p0-08] 每一个来回，你都在当它的牛马。
- [p0-09] 人当中间层至少有个好处：看到危险的命令，你会停手。
- [p0-10] 可这活儿不该人干，得自动化。
- [p0-11] 自动化一上来，第二个问题跟着到：程序可没有你的直觉。
- [p0-12] 一个真能删文件、真能改系统的程序，凭什么敢让它直接跑？
- [p0-13] 这一集就回答这一对问题：怎么让它自己动手，凭什么敢放手。
- [p0-14] 答案拆开是四样东西：一个循环，一张表，三道闸门，一排挂点。

## P2 三十行的循环

> 画面：陶土橙环体放大占屏，五步循环沿环依次点亮；消息列表在侧边逐条堆叠

- [p2-01] 先看循环本体。
- [p2-02] 会写命令和会做事之间，隔着一条沟。
- [p2-03] 命令只是文本，变成动作得有人按回车、看输出、再定下一步。
- [p2-04] 把这个人换成一个程序，就是给模型接上一双手。
- [p2-05] 手只管做，不管想：走哪一步，还是模型说了算。

- [p2-06] 教学版把这个循环写出来，整个函数三十<行|HANG2>上下。
- [p2-07] 干的事是五步：问题进消息列表，程序带着能用的工具清单调模型。
- [p2-08] 然后查一个信号：回答里有没有要调工具的动作。
- [p2-09] 有，就执行；把结果包成一条新消息塞回列表，再调一次。
- [p2-10] 没有了，循环退出，回答交给用户。
- [p2-11] 「塞回去」就是回喂，这个词后面反复用。

> 角标：tool_result

> 画面：走查实例——购物清单卡片，牛奶<行|HANG2>落进清单；消息列表五条逐格生长，编号同步

- [p2-12] 空讲规则容易晕，走一个具体例子。
- [p2-13] 你说：帮我在清单里加一<行|HANG2>牛奶，然后把清单念给我听。
- [p2-14] 第一回，模型的回答里带一个工具调用：写文件，参数是路径和新内容。
- [p2-15] 程序执行写入，清单多了一<行|HANG2>，结果塞回对话。
- [p2-16] 第二回，模型又调一个：读文件。再执行，再塞回。
- [p2-17] 第三回，模型回答纯文本：清单现在是这些。没有工具调用，退出。
- [p2-18] 三次调用，两次执行，每步决策都踩在程序喂回的结果上。

> 画面：判据对比帧——左「收尾字段」迟到（打字机逐字到达），右「内容块」已就位；火警调度台意象一闪即收

- [p2-19] 这里面藏着一个要命的细节：程序怎么知道该继续转？
- [p2-20] 教学版看一个收尾字段，模型说还要调工具就继续——这个字段就是判据。

- [p2-21] 这个判据看着干净，但生产环境是流式的，回答像打字机逐字到达。
- [p2-22] 内容块已经到了，收尾字段可能还停在上一个值。
- [p2-23] 就像接警：听到着火和地址就该派车，不必等这通报警的官方收尾。
- [p2-23b] 边界：接警员晚点还能补派车，循环错过这一次，没有第二次判断。

- [p2-24] 循环认内容事实，不认收尾字段这种二手信号。
- [p2-25] 原型实验拆这条：模型换成固定脚本，判据换回收尾字段，其他全不动。
- [p2-26] 十轮只跑完八轮，落地的调用从七件掉到五件。
- [p2-27] 两个工具调用被静默丢弃，核对步骤整段缺失。
- [p2-28] 字段晚到时，等字段，等于丢调用。

> 角标：stop_reason vs tool_use

> 画面：基线标尺——30 与 1729 两根高度悬殊的柱；右侧保险丝族谱（阻塞上限/轮次/预算/压缩）逐条点亮

- [p2-29] 那生产版呢？
- [p2-30] 拆过 Claude Code 源码的作者数过：管循环的文件，一千七百多<行|HANG2>。
- [p2-31] 三十<行|HANG2>的骨架就是它的核心，其余全是保险丝。
- [p2-32] 这比方有边界：保险丝烧断就永久断路，这里的保护多数能重试、能续跑。
- [p2-33] 阻塞上限、轮次用尽、预算耗尽，每条退出路径都护着一个判据点。

## P3 查表分发

> 画面：单只 bash 手工具特写；意图词「读」与拼出的命令串之间一条翻译损耗带

- [p3-01] 循环有了，模型的手还只有一只：bash。
- [p3-02] 想读文件，得拼一条读文件的命令；想改文件，得动用文本替换。
- [p3-03] 模型在「我想干什么」和命令语法之间，硬做了一层翻译。
- [p3-04] 浪费不说，还容易拼错。
- [p3-05] 更深一层：命令全是字符串，程序侧没法对读和写区别对待。

> 角标：cat / sed / echo

> 画面：五张工具卡（青色）逐张落位；左右双列——定义表与处理表同步加条

- [p3-06] 解法是给每个动作一个专用工具：有名字，参数长什么样也写清楚。
- [p3-07] 模型直接说意图，程序侧第一次拿到结构化的信息。
- [p3-08] 加一个工具要改几处？两处。
- [p3-09] 定义表加一条：名字、描述、参数说明书。
- [p3-10] 处理表加一<行|HANG2>：名字对到实现函数。
- [p3-11] 循环里的执行，从写死的命令换成一<行|HANG2>查表。

- [p3-12] 教学版从 bash 一个，长到五个：读、写、改、搜文件，加 bash。
- [p3-13] 循环零改动。
- [p3-14] 加东西不动老东西，第二项规格，落地。

> 角标：TOOLS / TOOL_HANDLERS

> 画面：三个调用各自贴单号标签，结果乱序返回；凭单号对回订单；右半屏红绿错绑对比

- [p3-15] 多工具带来一个新问题：模型经常一次要调好几个。
- [p3-16] 读这两个文件，再列出所有 Python 文件，三个调用。
- [p3-17] 每个调用自带一个编号，结果按编号对回。
- [p3-18] 像快递：一次下多个订单，包裹贴单号，乱序到了也凭单号签收。
- [p3-19] 边界：快递单号跨天有效、能查物流；编号只活一轮对话，是一次性回执。
- [p3-20] 原型再拆一次：拔掉配对，让同一轮的两个结果互换归属。
- [p3-21] 配对错误从零变二，读的结果记进了错的账。
- [p3-22] 没有配对，乱序即错位。

> 角标：tool_use_id

> 画面：生产对照条——五步验证管线横向流过；读写分批动画；「读文件=∞」特例卡

- [p3-23] 生产版叠了什么？拆过源码的作者数出三样。
- [p3-24] 每个调用要过五步验证才落地，从参数校验到权限检查。
- [p3-25] 分区保序：互不干扰的调用一起跑，会干扰的排队走，批与批不乱序。
- [p3-26] 作者数出的最后一样：太长的结果落成文件，看预览加路径；读文件不设上限，是唯一例外。
- [p3-27] 不然读的结果存成新文件，下次读它又触发存储，死循环。
- [p3-28] 能力有了，凭什么敢让它跑？

## P4 三道闸门

> 画面：无保护的 bash 通道上悬一道删库命令（警示红描边）；珊瑚红闸门结构体从下方升起

- [p4-01] 走到这里，模型已经能读写文件、能跑任意命令。
- [p4-02] 而 bash 这条通道，完全没有保护。
- [p4-03] 一句删根目录的命令，就能把整台机器抹掉。
- [p4-04] 有句立场值得原样记住：安全不能靠信任模型，要靠代码，在执行之前判断。
- [p4-05] 官方文档说得更直白：权限规则由 Claude Code 执行，不由模型执行。
- [p4-06] 提示词里写什么，影响的是模型会尝试什么，改变不了程序允许什么。

> 角标：rm -rf / · Permission

> 画面：三道闸门纵向串联；一条删除命令逐关通行，关卡灯依次变灯

- [p4-07] 落下来是三道闸门，串在执行之前，顺序固定。
- [p4-08] 第一道，硬拒绝：删根目录、sudo 提权、格式化磁盘，七条写死。
- [p4-09] 命中即拦，不问任何人——这一档，一概不商量。
- [p4-10] 第二道，规则匹配：路径出界、命令带删除、写系统配置，命中就升级处理。
- [p4-11] 第三道，用户审批：打印原因，停下来，等你一个字。
- [p4-12] 三道都不命中，直接执行。

- [p4-13] 走一个：模型发起删除，目标是旧笔记文件。
- [p4-14] 第一道逐条比，七条都不中，放行。
- [p4-15] 第二道查关键词，命令带删除，标记为有潜在破坏性。
- [p4-16] 第三道暂停问你；你点头，删除执行，结果回喂，模型继续。
- [p4-17] 你摇头，这条调用拿到一句拒绝，模型知道此路不通，通常换个安全做法。
- [p4-18] 换成 sudo 开头，第一道直接拦，你根本不会被问。

> 角标：DENY_LIST / PERMISSION_RULES

> 画面：消融对比——左红「放行压过硬拒绝」sudo 落地；右绿「不变式在位」sudo 被拦

- [p4-19] 默认放行、例外才问、极少数一概不商量，目标是打扰最少。
- [p4-20] 这一档能不能松口？原型拆给你看。
- [p4-21] 让用户的放行压过第一道硬拒绝，其他不动。
- [p4-22] sudo 开头的命令，经用户点头后，落地了。
- [p4-23] 谁都能点头，硬拒绝这一档就名存实亡。
- [p4-24] 所以方向反过来：多个来源都点头才放行，一方摇头就拦下。
- [p4-25] 拒绝票，比允许票<重|ZHONG4>。

> 画面：八来源层叠图（【三】级角标「源码分析」）；分级判案机器四段流水线

- [p4-26] 生产版的裁决更厚。
- [p4-27] 拆过源码的作者数过：规则不止一张表，是八个来源，高的盖住低的。
- [p4-28] 自动模式下，问用户被拆成一台分级判案机器。
- [p4-28b] 先查白名单，再交给判断安不安全的小模型，连续拒绝太多次就退回人工。
- [p4-29] 判案机器有个缺口：不给判决理由，判得准不准，官方也没给数字。
- [p4-30] 规则还是小模型判案，这争议还开着，先按下不表。

> 角标：auto · 8 sources · classifier

## P5 钩子注册表

> 画面：循环体剖视图——检查逻辑一段段挤进环体内，环体逐渐「认不出来」（红色告警纹理）

- [p5-01] 最后一个问题：这些检查写在哪？
- [p5-02] 权限检查要是直接写在循环里，每加一个检查，就得改一次循环。
- [p5-03] 记日志、执行后通知、自动暂存，一样来一次。
- [p5-04] 几轮下来，循环里堆满别人的活，它自己都认不出来。
- [p5-05] 病灶不在某一<行|HANG2>，在依赖方向：想扩展的是行为，改动的却是核心流程。

> 画面：环体外圈亮出四个挂点（银灰+橙描边）；注册表格架起，检查函数卡挂到挂点上

- [p5-06] 钩子的解法：把检查搬出循环，挂到固定事件上。
- [p5-07] 注册表就是一张登记表：事件名，对到一串检查函数。
- [p5-08] 循环体里只留一句触发，跑哪些检查由这张表决定。
- [p5-09] 四个事件覆盖一个完整周期：输入提交后、执行前、执行后、停机前。
- [p5-10] 前面那三道闸门，整个降格成挂在执行前的一道普通检查。
- [p5-11] 循环从此不含任何具名的检查逻辑。

> 角标：UserPromptSubmit / PreToolUse / PostToolUse / Stop

> 画面：Stop 走查——退出门口被一只钩子手拦下，新消息注入，循环续跑一轮后放行

- [p5-12] 最反直觉的，是停机前那个事件。
- [p5-13] 判据说没有工具调用了、该退出了，钩子却还能拦。
- [p5-14] 原型日志长这样：模型说做完了，钩子回一句，还没，理由是没核对完。
- [p5-15] 这句话作为新消息塞回对话，循环续跑一轮，再停，第二次放行。
- [p5-16] 多跑的那一轮做了核对，循环源码一<行|HANG2>没动。
- [p5-17] 再拆一次：把续跑指令丢掉。
- [p5-18] 核对轮没有发生，十轮只跑了八轮。
- [p5-19] 退出权也是扩展点，堵上，就少一道质检。

> 角标：stopHookActive

> 画面：4→27→33 增长条（三段口径角标）；不变式卡——allow 票被 deny/ask 压回

- [p5-20] 生产版这层长什么样？
- [p5-21] 教学版四个；拆过源码的作者数出二十七个；官方文档到今年十月，三十三个。
- [p5-22] 清单单调增长，四个核心事件始终是理解骨架。
- [p5-23] 还有一条保险最见功力：钩子说放行，也压不过拒绝规则。
- [p5-24] 官方文档写明的是这条：允许要各方一致，拒绝只要一方摇头。
- [p5-25] 连你自己写的钩子，也不能单方面放行被禁的操作。

## P6 规律与边界

> 画面：全景母图回归，四层依次点亮后整图呼吸一次；金句卡（衬线体）落下

- [p6-01] 回看全程，秘密还是开头那句：把结果喂回去。
- [p6-02] 三十<行|HANG2>没改，长出四层：回喂给它一双手，查表让手更多，闸门让它敢用，挂点给它空间。
- [p6-03] 核心循环不变，能力正交叠加，各层互不牵连。
