## P1 接诊循环

> 画面：接诊循环装置放大特写，五步位逐个点亮（全量进诊→落账→收单→执行→回喂），core 橙流转动；角标逐步浮现 `messages`／`tool_use`／`tool_result`。回溯：§一·1.2-1（五步骨架）

- [p1-01] 先把循环本体拆开，一共五步。
- [p1-02] 第一步，整本病历送进诊室——每一轮都是全量，一条不落。
- [p1-03] 第二步，医生下判断，先落回病历。
- [p1-04] 第三步，看病历里有没有新开的检查单。
- [p1-05] 第四步，有单子就交科室执行。
- [p1-06] 第五步，报告贴回病历本，回到第一步。

> 画面：病历本特写——两栏表头（问方/答方）逐条落字；科室报告卡片没有署名栏，被贴进「问方」栏（mech 高亮一瞬）。角标：`tool_result → user 信封`。回溯：§一·1.2-3/4（两角色协议+先落账）

- [p1-07] 这本病历只认两种署名：问方，和答方。
- [p1-08] 医生的判断，落在答方栏。
- [p1-09] 科室的报告就微妙了——它没有自己的署名，只能贴进问方栏目。
- [p1-10] 协议就这么定的：每一轮，问方答方轮流往下写，谁也不能插队。

> 画面：判停分屏——左「开单→继续转」右「没单→结诊」；循环装置上的判停刻度亮起。角标：`stop_reason`（打叉淡出）vs `内容块`（点亮）。回溯：§一·1.2-2（内容块判据，D7）

- [p1-11] 循环什么时候停？判据只有一个：这一轮，开没开新单。
- [p1-12] 开了单，执行完接着转；没开单，任务完成，结诊。

> 画面：时序竞速图（stop-reason-race 章一）——传真纸页逐页吐出：单子先落盘，盖章标记迟到（表针走格）；迟到标记 deny 红闪。角标：`流式`。回溯：§一·1.5（实验 1 前置机理）

- [p1-13] 这个判据有个坑：真实的输出是流式的，像传真机一页页吐纸。
- [p1-14] 单子先到，盖章的停止标记，可能晚到。
- [p1-15] 有的实现拿停止标记当判据——标记没到，就当没开单。

> 画面：实验 1 正反同屏（stop-reason-race 章二/三）——左轨红：循环第一轮即退，计数器「0 工具」；右轨绿：三轮转完「2 工具」任务勾。角标：`1 轮 0 工具 vs 3 轮 2 工具`。回溯：§一·1.5（实验 1 实测）

- [p1-16] 我们把这个坑做成了实验。
- [p1-17] 信标记的那一版，第一轮就退出，一个工具都没执行，任务半途而废。
- [p1-18] 看病历内容的那一版，三轮跑完两个工具，任务交付。
- [p1-19] 教学版最初教的，就是旧判据；源码最新版，已经改成看病历内容。
- [p1-20] 判据要看不会迟到的事实。

> 画面：生产版对照卡（trend 表述）——「千行级核心文件」大数字位虚化处理，其中一小段循环内核高亮「三十来行」，四周保护壳图标阵列（超时/报错/中止/停机）；角标挂「对外拆解口径」。回溯：§一·1.3（【三】+1729 口径纪律 D2）

## P2 开单表

> 画面：开单表装置首现（dispatch-table 章一）——表格册页翻开，五行走索引式点亮：跑命令/读文件/写文件/改文件/找文件，mech 青；循环环体静置 core 橙。角标：`TOOLS`／`TOOL_HANDLERS`。回溯：§二·2.2-1/2（查表分发+注册契约）

- [p2-01] 起初医生只有一个工具：开命令单，全靠拼命令。
- [p2-02] 想读文件得拼查看，想改文件得拼替换——多一层翻译，白费口舌。
- [p2-03] 解法，是一张开单表。
- [p2-04] 每个工具上表，就添两笔：一张说明单，告诉医生这工具叫什么、怎么开；
- [p2-05] 一行登记，指向执行函数——函数照写，循环照旧不动。
- [p2-06] 表里登记五个科室：跑命令、读文件、写文件、改文件、找文件。
- [p2-07] 医生开单写工具名，循环拿名字查表，查到谁，就谁干。
- [p2-08] 新本事进表，不进循环。

> 画面：四版演进小窗（four-version-ledger 预热）——循环代码行特写：写死调用一行被替换为查表一行（前后两行代码卡对切）；行数尺第二格 135 点亮。角标：`run_bash()` → `HANDLERS[name](**input)`。回溯：§二·2.1（唯一变动口径）、§二·2.2-1

- [p2-09] 四版演进里，执行那行只动过这一回：从写死调用，换成查表。
- [p2-10] 之后加第十个工具，也只是表上再添两笔。

> 画面：实验 2 正反同屏（lookup-failure）——同一张未知单子从顶部分叉：左路径硬取值，整轮栈炸（红）；右路径软查表回一句「不认识」，医生看后改名重开（绿）。角标：`KeyError` vs `Unknown`。回溯：§二·2.5（实验 2）、§二·2.2-3

- [p2-11] 查表也有讲究。我们做了个破坏性实验：把表里一个工具偷偷删掉。
- [p2-12] 一种取值是硬来：名字查不到，程序当场崩，整轮白干。
- [p2-13] 另一种是软查表：查不到，就回一句「不认识这个工具」，贴回病历。
- [p2-14] 医生看到这句，下一轮就换对了名字，任务继续。
- [p2-15] 同一个未知名字，怎么取值，决定了是崩溃，还是改道。

> 画面：多单打包示意——一轮三张单按序过科室，结果合并成一贴回病历；旁侧「分批并行」对照卡（连续块分批，批内并行、批间保序；同一工具两个实例一个✓并行一个✗排队），角标「对外拆解口径」。回溯：§二·2.2-9（按序串行【一】）、§二·2.3（分批并行【三】）

- [p2-16] 一轮可以开好几张单子。教学版老实，按顺序一张张执行，结果打包贴回。
- [p2-17] 有人拆过真实实现：单子会分批并行——批内真同时，批间保顺序。
- [p2-18] 能不能同批，不看工具名字，看具体参数：只读的命令能同跑，带删除的不行。

> 画面：院内围栏特写（dispatch-table 章 dept-exec）——图内文件三科（read/write/edit）被细线围栏圈住，围栏外一条「命令外线」通道直通门外，deny 描边；p2-20..21 回落自制特写为四窗（读/写/改/找全在围栏内——第四窗正是为补上图内未画的找文件；围栏外只有 bash 外线）；埋雷音效点。角标：`safe_path`（仅文件科）。回溯：§二·2.2-4（safe_path 边界）

- [p2-19] 这张表还带一道院内围栏：文件类的单子，不许出你的项目文件夹半步。
- [p2-20] 但围栏只围得住文件科——命令那条外线，不归它管。
- [p2-21] 这个口子，下一幕就要出事。

## P3 三重把关

> 画面：事故快闪——「清理一下项目」指令卡→一张整盘删除命令单（rm 字样）已递到科室门口，deny 红警示描边；三层筛装置旋入。角标：`rm -rf /`。回溯：§三·3.1（起点失败模式）

- [p3-01] 出事了：你让它清理项目，它可能直接递来一张整盘删除的单子。
- [p3-02] 所以执行之前，得先过一道关。
- [p3-03] 教学版的这道关，一共三层。

> 画面：三重把关装置全景（gate-three-tier 章逐章）——禁忌表翻页（词表逐条黑体）、规则卡（文件越界/命令带删除两类）、签字板（默认拒）；三层筛自上而下串联，末端默认直行道。角标：`DENY`→`RULES`→`ASK`。回溯：§三·3.2-1/2/3/6（三闸门+默认拒）

- [p3-04] 第一层，禁忌表：整盘删除、冒充管理员、格式化这类词，沾上就拒，也不问。
- [p3-05] 第二层，规则：定「什么情况要问人」。文件越界，问；命令带删除，问。
- [p3-06] 第三层，问人：只有你点头，单子才放过去；不吭声，默认就是拒。
- [p3-07] 三层都空过的单子呢？查看、列目录这类日常单，直接放行。
- [p3-08] 日常大多数单子，走的都是这条直行道。
- [p3-09] 被拒的单子也不失踪，回执贴回病历，医生看得见，才好换路。

> 画面：禁忌铁律卡——禁忌表格上盖一枚封条章（「翻不了案」）（顺序基准预备由 gate-order-ablation 图内承担——R12 消「顺序箭头卡」未兑现项）。回溯：§三·3.3（最严者胜【三】）、§三·3.5（实验 3）

- [p3-10] 这道关的铁律：禁忌翻不了案——后面环节签再多的字，也盖不过它。
- [p3-11] 铁律靠什么保证？靠顺序。

> 画面：实验 3 双泳道（gate-order-ablation）——上泳道正常序：禁忌表先拦，绿灯；下泳道调序：规则与问人提前→签字框弹出一个「y」→整盘删除执行→虚拟文件系统格子 4→0（红闪）。角标：`4 文件 → 0`。回溯：§三·3.5（实验 3 实测）

- [p3-12] 我们把顺序翻过来做了实验：规则和问人提到最前，禁忌表殿后。
- [p3-13] 用户顺手按了一个同意——整盘删除真的跑了起来。
- [p3-14] 虚拟文件系统里四个文件，清零。
- [p3-15] 把关的次序，本身就是机制。

> 画面：字面匹配两面卡——「过拦」侧：绝对路径删除全被连坐（列表逐条划掉）；「漏拦」侧：命令变体/套层展开绕过（小字逃逸箭头）；作者自认引语卡上屏。角标：`词边界`（新补丁点亮，归属规则层非禁忌表）。回溯：§三·3.5（两面性）、§三·3.2-4（词边界正则【一】）

- [p3-16] 当然，这层关拦得糙。
- [p3-17] 禁忌按字面匹配，宁可错拦：一切绝对路径的递归删除，全被连坐。
- [p3-18] 换个写法、套层展开，又可能漏过去。
- [p3-19] 教学版的作者自己说：这是示意，不是可靠的安全边界。
- [p3-20] 源码最新版补上了词边界辨认——删文件的词，不再误伤恰好含它的其他单词。

> 画面：生产版对照三层卡（gate-four-result 逐章）——四态转盘（多出的一格「不表态」也转向问人）；八来源分层塔；分类器示意（单子连同对话上下文，发给判断模型——2026-10-02 评审改：原「蒙眼看不到工具结果」为必改 #3 判双零支撑的残留）。角标：「对外拆解口径」＋`官方分层口径`（分层【官】，其余【三】）。回溯：§三·3.3（四态/八来源/分类器【三】）、§三·3.4（分层【官】）

- [p3-21] 真实产品里这道关厚得多。
- [p3-22] 有人拆过：判断不止三种，是四种——多出的「本工具不表态」，也转成问人。
- [p3-23] 规则也不是一张表：八个来源分层合并，高层盖过低层——官方文档这么分层。
- [p3-24] 自动模式里还有一个分类器：把单子和对话一起，发给一个判断模型代审。
- [p3-25] 连拒太多次，还会退回人工，把决定还给你。
- [p3-26] 但有一样不变：放行的，永远是关卡；不是开单的医生。

## P4 规程节点

> 画面：循环代码卡臃肿动画——检查项一行行塞进循环体，注释行「很快认不出来」；循环装置变胖变形抖动。角标：`check_permission()` 内嵌。回溯：§四·4.1（反模式引语）

- [p4-01] 关建好了，新问题跟着来：把关的代码，写死在循环里。
- [p4-02] 想再加一条「跑完命令自动登记」？又得改循环。
