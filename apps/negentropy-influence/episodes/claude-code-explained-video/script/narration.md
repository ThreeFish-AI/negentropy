## P0 人肉循环

> 画面：开场字卡直入（片头改版 2026-10-06：五层栈落板职责已由系列片头 series-intro.tsx 吸收，0-A=常驻条 Badge 淡入）；主问题字卡（「敢」字 deny 红点睛）；结尾三债三装置预告剪影（mech 青 ×3，从右缘挂入，不触碰左中 core 橙内核锚位）。角标：`while True`。回溯：§一·定位与标语、§二·定位与标语、§三·定位与标语、§四·定位与标语

- [p0-01] 一个能读文件、能跑命令的模型，凭什么敢放它在你机器上动手？

> 画面：无循环世界分屏——左：模型吐命令即停（师傅剪影摊手）；右：人工跑命令、贴输出的往复箭头（dim 灰＝人色）。角标：`cat`、终端往复。回溯：§一·定位与标语

- [p0-02] 没有循环的时候，模型吐完一条命令就停，不会自己跑。
- [p0-03] 你替它跑，把输出贴回去，它才接得上下一句。
- [p0-04] 每一个来回，你都在做中间层。

> 画面：`while True` 落下把「人」换下场（「人肉循环」字卡）；循环三拍微缩首现（core 橙）。回溯：§一·机制（while True 主循环）

- [p0-05] 一条不停转的循环，把这个人换了下来。
- [p0-06] 模型每要一次工具，就执行、喂回去、再问一轮。
- [p0-07] 所以第一代用法里，人自己就是那个循环。

> 画面：三债三卡并列（安全债 deny 红／能力债、扩展债 mech 青）＋「改到认不出来」的循环体膨胀滚屏。角标：`rm -rf`（危险命令卡，不口播）。回溯：§二·定位与标语（能力债）、§三·定位与标语（安全债）、§四·定位与标语（扩展债）

- [p0-08] 但裸循环一出场，就欠了三笔债。
- [p0-09] 第一笔是能力：想加一件新本事，就得动循环本身。
- [p0-10] 第二笔是安全：它什么都敢执行，不挑活。
- [p0-11] 你说清理一下项目，它可能真去执行删库命令。
- [p0-12] 第三笔是扩展：想记日志、加自动动作，还是得改循环。
- [p0-13] 改多了，很快循环就认不出来了。

> 画面：悬念立碑——「更聪明的循环」字卡划掉 → 三层装置剪影自右缘点亮（mech 青）；金句卡衬线体。回溯：§一·定位与标语（「循环始终不变」）

- [p0-14] 答案不是造一个更聪明的循环。
- [p0-15] 是三层挂在循环外面、随时可拆的装置。
- [p0-16] 三笔债，三种挂法，循环一行不改。

## P2 工具号码簿

> 画面：翻译层痛点——师傅举「读这个文件」字条，手里却要拼命令（拼错红闪）。角标：`cat path/to/file`。回溯：§二·定位与标语

- [p2-01] 第一笔债是能力，从师傅的憋屈说起。
- [p2-02] 传送带认得的机器，最初只有命令行这一台。
- [p2-03] 师傅想读这个文件，手里却得拼一条命令——多一层翻译，还容易拼错。

> 画面：archify dispatch-map（dataflow，全屏独占）——号码簿翻页（mech 青条目逐条点亮），内核 core 恒静；四工具图标上带。角标：`TOOL_HANDLERS`、`TOOLS`。回溯：§二·机制（TOOL_HANDLERS 查表分发／两步注册）

- [p2-04] 改法很克制：执行那一行，换成查一本转接号码簿。
- [p2-05] 号码簿左边是工具名，右边是干活的函数，一一对应。
- [p2-06] 循环从此不认识任何机器，它只会查号、转接。
- [p2-07] 这一版一次注册了四个新工具：读文件、写文件、改文件、找文件。
- [p2-08] 说明书厚了，号码簿长了几行，循环一行没再动。
- [p2-09] 加一个工具，改的是号码簿，不是传送带。

> 画面：archify registry-contract（dataflow，全屏独占）——签名咬合卡，错配即 deny 红闪。角标：`handler(**block.input)`、`Unknown: {name}`、`try/except`。回溯：§二·机制（隐含第三契约／未知名字兜底／每工具自带异常）

- [p2-11] 注册说是两步：一步写工具说明书，一步登记处理函数。
- [p2-12] 但藏着第三步暗契约：说明书里的参数名，必须和函数入口名一字不差。
- [p2-13] 名字对不上，运行时就地炸——两步注册，其实有三处要对齐。
- [p2-14] 查不到的号码也不崩，回一句不认识这个名字，继续干活。
- [p2-15] 每台机器自己兜故障，把错误写成一张字条回传。
- [p2-16] 所以坏名字、坏输入，伤不到循环分毫。

> 画面：archify tool-batch-layers（workflow，全屏独占）——托盘三账对照（教学版串行／仓库索引关键词／产品并行与批）。角标：`PostToolBatch`、`parallel tool calls`。回溯：§二·机制（多 tool_use 按原始顺序逐个执行）、分歧 D3、§二·官方文档对照 3【官】、§二·生产版对照【三】（归属句口播已带）

- [p2-17] 师傅经常一口气递出好几个调用，装进同一个托盘。
- [p2-18] 教学版的托盘讲规矩：一件一件上，绝不并发。
- [p2-19] 有意思的来了：仓库自己的章节索引，却把并发列为这一章的关键词。
- [p2-20] 承诺了代码里没有的东西——实测这个版本，零并发原语。
- [p2-21] 官方文档倒是确认：产品真有并行工具调用，还有批这一层。
- [p2-22] 这个开源项目的作者拆过真实实现后说：
- [p2-23] 调度是批内并行、有并发上限，批与批之间严格排队。
- [p2-24] 能不能并行，看这一次调用的实参，不看工具挂什么名。

> 画面：围墙装置首现（mech 青细框围住文件工具区，bash 区在框外）——为下一幕拆墙埋雷。角标：`safe_path`、`is_relative_to(WORKDIR)`。回溯：§二·机制（safe_path 工作区路径围栏）

- [p2-25] 这一版还悄悄立了第一道围墙：文件工具，只能碰工作区里的文件。
- [p2-26] 路径越出工作区，直接报错，没有商量。
- [p2-27] 但围墙只围文件工具，命令行那台机器，不归它管。

## P3 三道门禁

> 画面：债到期卡（deny 红脉冲）＋上一版末尾警告引语卡（口播回指已删，引语卡代言）。角标：`bash 不受 safe_path 保护`。回溯：§三·定位与标语（起点失败模式／章末交棒）

- [p3-01] 第二笔债到期了，安全。
- [p3-02] 围墙管不着命令行——一句清理项目，可能就真把库删了。

> 画面：archify three-gates（state，全屏独占）——三道门空间装置：焊死门（deny）→ 对讲机（dim 灰）→ 敞门（ok 瞬态），次序锁死永不换位；接入点单行高亮。角标：`DENY_LIST`、`PERMISSION_RULES`、`ask_user [y/N]`、`check_permission()`。回溯：§三·机制（三道闸门权限管线／仅对 bash 生效／默认拒绝／只加一行）

- [p3-03] 这一版的改法，是在门口装三道门禁。
- [p3-04] 第一道，焊死的铁门：一张永远拒绝的清单，碰到就拦，不问理由。
- [p3-05] 这张表只盯命令行那台机器，别的工具它不管。
- [p3-06] 第二道，规则匹配：每条规则写明，什么情况必须问人。
- [p3-07] 第三道，对讲机：循环暂停，原因参数念给你听；不回话，默认拒绝。
- [p3-08] 三道门次序焊死：先碰哪道，按哪道办。
- [p3-09] 整套门禁接进循环，只加了一行代码。

> 画面：危险品名册按词辨认——命令位的 `rm`/`del` 高亮命中，`model`/`delimiter` 灰置不报（反例只进画面，不口播）。角标：`DESTRUCTIVE_COMMAND_WORD`。回溯：§三·机制（命令词位正则）

- [p3-11] 拒绝清单按词辨认，不再只看字符串包含。
- [p3-12] 只有站在命令位置上的那个删字，才算危险品。

> 画面：官方对齐卡（官方文档页样 + 三条中文摘要）。角标：`deny → ask → allow`、`Bash(aws *)` 开洞反例。回溯：§三·官方文档对照 2/3【官】

- [p3-14] 官方文档明写：规则按拒绝、询问、放行的次序求值，第一个命中就定案。
- [p3-15] 规则写得多具体，都改不动这个次序。
- [p3-16] 还有一条更硬：放行不能在拒绝上开洞。

> 画面：闸门倒置假想卡（次序翻转箭头，拒绝表命令被放行，deny 红闪）。回溯：§三·机制（三闸门顺序的倒置推演，工具链简报 R2）

- [p3-18] 一倒置，清单就成了摆设——所以，焊死的铁门，永远排在对讲机前面。

> 画面：archify fence-to-intercom（architecture，全屏独占）——拆墙双联画：左「有墙无门」／右「有门无墙」；拆除动效用虚线残影。角标：`safe_path` 拆除标记、前后两版对照。回溯：§三·机制（工具章硬边界的拆除·净效应）

## P4 插线口

> 画面：循环体膨胀滚屏（日志／自动动作一行行叠进 while True）→「认不出来了」毛玻璃模糊。角标：`git add` 类横切行为示意（不口播）。回溯：§四·定位与标语（动机·反模式）

- [p4-01] 第三笔债是扩展：想记日志、想自动留档，按老办法都得写进循环体。
- [p4-02] 你想扩展的是行为，动的却是心脏。

> 画面：插线口母题＋LottieEmphasis plug-pulse（装置插入脉冲，mech 青）；传送带锁芯恒 core 橙静止。角标：`HOOKS`、`register_hook()` / `trigger_hooks()`、四事件名 `UserPromptSubmit / PreToolUse / PostToolUse / Stop`。回溯：§四·机制（HOOKS 注册表四事件／两函数）

- [p4-03] 这一版的答案：在传送带边，留一排插线口。
- [p4-04] 挂在循环上，不写进循环里。
- [p4-06] 实现是一排插口：四个事件，每个口挂一串装置。
