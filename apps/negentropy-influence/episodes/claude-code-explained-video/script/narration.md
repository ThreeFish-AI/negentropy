## P0 你在当那个中间人

> 画面：终端窗口，光标闪烁。用户提问逐字打出，模型回一条命令后画面凝住。
> 随后「复制 → 粘贴 → 复制 → 粘贴」三轮，把画面塞满灰色的搬运痕迹。

- [p0-01] 你让 AI 跑个脚本：它把命令写好，然后就停在那儿了。
- [p0-02] 复制、粘贴、回车、再把输出贴回去——每一轮的搬运工，是你。
- [p0-03] 从「写出命令」到「真的跑起来」，缺的那一层，官方起了名字。
- [p0-03a] 这一层有多要紧？他们刷编程评测的战报里写过一句话——
- [p0-03b] 同一个底层模型，换一套脚手架，成绩能差出一大截。
- [p0-03c] 你花在这一层上的力气，直接变成它的分数。
- [p0-04] 名字就叫 Harness：把动力源，套进一个可控的结构里。
- [p0-05] 官方说得直白：这套东西是 Harness，模型装在 Harness 里面。
- [p0-06] Harness 给它四件：一个循环、一套工具、上下文管理、一道护栏。
- [p0-07] 这集就把这个 Harness，一层一层拆开看。

## P1 一个循环，就是全部

> 画面：陶土橙闭合轨道成形（全片恒定视觉锚）。角标：Agent Loop · "One Loop Is All You Need"

- [p1-01] 先说结论：那一层的核心是一个循环，像一条不停转的传送带。
- [p1-02] 它只做一件事：反复去问模型，接下来干什么。
- [p1-03] 每问一次，就看模型的回答里有没有夹着一次工具调用。
- [p1-04] 有，就说明模型举手了，它要用工具。
- [p1-05] 那就替它把工具跑一遍，把结果原样塞回对话里，再问下一轮。
- [p1-06] 没有，就说明它觉得活干完了，循环停机，把话交给你。

> 角标：`tool_use` block · 「有工具调用 → 继续 / 没有 → 退出」

- [p1-08] 把这件事翻成代码，只有五步。
- [p1-09] 先把你的问题放进消息列表，再连同「我有哪些工具」发给模型；
- [p1-10] 把模型的回答追加进列表，挑出里面所有的工具调用；
- [p1-11] 一个都没有就地返回，有就逐个执行、收好每条结果；
- [p1-12] 最后把结果打包成新消息追加进去，回到第二步。写完了。
- [p1-12a] 说明一下：有人照着这套机制搭了一份开源的最小实现。
- [p1-12b] 下面拿它当例子，边读边说实际实现的做法。
- [p1-13] 有人给它的评价是：三十多行，最小可运行的内核。
- [p1-14] 我自己数过这一版：光循环那个函数，去掉空行和注释，二十三行。

> 角标：实测 `agent_loop` 非空非注释 23 行 @ pinned commit（口径与取数见 sources.toml）

- [p1-15] 分工也说清楚了：模型决定要不要用工具、用哪一个，
- [p1-16] 脚手架负责真的去跑、把结果搬回来——判断力在那边，手脚在这边。
- [p1-17] 模型回话时会附一个「我为什么停下来」的标记。
- [p1-18] 最直觉的写法是直接看它；但最简实现改了，
- [p1-19] 改成翻开回答本身，看里面有没有工具调用。为什么？
- [p1-20] 有人拆过它的源码，他给的理由是：
- [p1-21] 回答是一个字一个字流出来的，工具调用早就流出来了，
- [p1-22] 那个标记却可能还没更新——他说源码注释写得很直白，这标记不可靠。
- [p1-23] 所以真正的做法是一边流一边看，见到工具调用就记下还得再来一轮。
- [p1-24] 别听它说「我说完了」，去看它手里还有没有活。

> 金句卡（serif）：「别听它说『我说完了』，去看它手里还有没有活。」
> 角标：`stop_reason` is unreliable —— 第三方的源码分析

- [p1-25] 官方给这个循环画过像：三件事交融着转——
- [p1-26] 收集上下文、采取行动、验证结果，不是硬阶段。
- [p1-27] 而且你随时可以打断它、补一句、让它改道。
- [p1-28] 最简实现身上只带一份消息列表；实际的 Harness 带着十样，
- [p1-29] 压缩进度、补救次数、钩子拦没拦过停机、轮数——细节进角标。
- [p1-30] 循环没长个，长出来的是它随身带的状态。
- [p1-31] 退出的路子也有一大把：报错、中断、钩子叫停、预算烧完。
- [p1-32] 但它们全是保护装置，不是骨架；骨架还是那二十来行。

## P2 加一个工具，只改一行

> 画面：循环环保持不动（陶土橙），右侧长出第一层外挂——石青色的字典分发表。
> 角标：Tool Use · "Add a Tool, Add Just One Line"

- [p2-01] 刚才那个循环，手里只有一件工具：一个能跑命令的壳。
- [p2-02] 想读文件，它得拼出一条读文件的命令；想写文件，得拼一条重定向。
- [p2-03] 模型心里想的是「读这个文件」，嘴上却要翻译成一条命令行。
- [p2-05] 那就把常用动作直接做成工具，于是从一件变成五件：
- [p2-06] 跑命令、读文件、写文件、改文件、按模式找文件。
- [p2-07] 问题是循环怎么知道该调哪一个？答案朴素得让人意外：查一张表。
- [p2-08] 一张字典，左边写工具的名字，右边写对应的处理函数。
- [p2-09] 像前台的转接号码簿：来电报个名字，前台照着簿子转接。
- [p2-10] 于是加一个新工具只要两件事：在清单里加一条描述，在表里加一行。
- [p2-11] 循环那边呢？我把两个版本逐行比过，
- [p2-12] 实质改动只有一行——原来写死了去跑命令，现在改成查表。
- [p2-13] 换掉的是「执行」这一个动作，传送带一寸没动。

> 角标：实测 diff —— 唯一实质变更即 `run_bash(...)` → 查表调用
> 金句卡：「换掉的是执行那一步，传送带一寸没动。」

- [p2-14] 接着来了个新麻烦：模型经常一次要好几个工具。
- [p2-15] 最简的做法是老实排队，一个一个来；实际实现里能并行的就并行。
- [p2-16] 而它判断能不能并行的方式，是这一集我最想让你记住的一处。
- [p2-17] 直觉会说：只读的可以一起跑，要写的不行。
- [p2-18] 但按第三方的源码分析，这两件事其实不是一回事。
- [p2-19] 同一个跑命令的工具，让它列个目录算能并行，让它删个文件就不能。
- [p2-20] 同一件工具，同一个名字，结论相反。
- [p2-21] 因为判断的不是这件工具，是这一次具体要干什么。
- [p2-22] 反过来还有更绕的：有的工具明明在改东西，却可以并行，
- [p2-23] 原因是它每次改的都是不同的文件，谁也不挡谁。
- [p2-24] 所以「能不能一起跑」跟「是不是只读」，是两条独立的判断。

> 金句卡（serif）：「『能不能一起跑』跟『是不是只读』，是两条独立的判断。」
> 角标：`isConcurrencySafe` ≠ `isReadOnly` —— 第三方的源码分析

- [p2-25] 判断完了怎么排？按原来的顺序切段：连着能并行的划成一组一起跑，
- [p2-26] 中间夹着不能并行的就单独一组；组内并行，组间严格按顺序。
- [p2-27] 他还提到，工具输出太长时它不会全喂给模型，而是存成文件，
- [p2-28] 只给它一段预览和一个路径。
- [p2-29] 但「读文件」这件工具被特别开了口子：输出永远不许存成文件。
- [p2-30] 因为一旦存了，模型下次去读那个文件，输出又太长，又被存成文件。
- [p2-31] 读、存、再读、再存，它会自己套住自己，转不出来。

## P3 执行之前，先过闸门

> 画面：循环环仍在（陶土橙），执行口前落下三道竖闸。警示红首次出现。
> 角标：Permission · "Check Permissions Before Execution"

- [p3-01] 现在这个 AI 有五件工具，其中一件能跑任意命令。
- [p3-02] 读写文件那几件都被拦在工作目录里，但跑命令那件，没人管它。
- [p3-03] 你随口说一句「帮我把项目清理一下」，
- [p3-04] 它完全可能给你递上一条把整块盘删干净的命令，循环照跑。
- [p3-06] 官方把话说死了：权限由这层代码执行，不由模型执行。
- [p3-07] 拦法是三道闸门，顺序写死。
- [p3-08] 第一道是一张硬拒绝表：删根目录、提权、关机、格式化。
- [p3-09] 命中就直接挡回去，连问都不问。
- [p3-10] 第二道是规则匹配，管「看情况」的操作：
- [p3-11] 读写工作目录之外的东西，或者命令里带着删除、改权限这类动作。
- [p3-12] 第三道就是问你：画面停下来，把工具名和参数摆给你看，等你点头。
- [p3-14] 最简实现自己承认：这张拒绝表只是字符串匹配，换个拼法就绕过去。
- [p3-15] 它告诉你闸门装在哪儿，不替你把门守住。

> 金句卡（serif）：「它告诉你闸门装在哪儿，不是替你把门守住。」（与 p3-15 音画同句）

- [p3-19a] 真正的边界在更底下一层：它给跑命令那件工具，套了一层沙箱。
- [p3-19b] 能写哪些目录、能走哪个网络出口，由操作系统说了算。
- [p3-19c] 规则是劝，沙箱是锁——两道墙少一道，笼子就不成立。
- [p3-19d] 官方工程博客给了数：内部用下来权限提示少八成四。

> 角标：Seatbelt / bubblewrap + socat · 文件系统与网络双边界 · 权限提示 −84%（官方工程博客，取数 2025-10）

- [p3-20] 回到闸门这边：有人拆过它的源码，判定结果是四种，不是三种。
- [p3-23] 多出来的第四种最有意思：工具选择不表态。
- [p3-24] 也就是说，弃权不等于放行，兜底永远是问你一句。
- [p3-25] 规则求值顺序官方文档也写死了：拒绝、询问、放行，
- [p3-26] 头一个命中就出局——规则写得多具体，都改变不了顺序。
- [p3-28] 裸名拒绝更狠：整件工具从模型身上直接消失。
- [p3-29] 就算全放行模式，也压不住一条写死的拒绝。

> 角标：user < project < local < flag < policy（+ cliArg / command / session）——第三方的源码分析

- [p3-30] 全自动模式不靠你点头的次数，靠另一个模型当闸门。
- [p3-31] 官方遥测补一刀：权限提示，九成三都被点了批准。
- [p3-31a] 这个当闸门的模型，自己也进过考场。
- [p3-31b] 快筛误杀率百分之八点五，复核之后压到千分之四。
- [p3-32] 审判者的视野是做减法的：只看用户消息和裸命令。
- [p3-34] 评它做了什么，不看它说了什么——注入的谎话骗不到它。
- [p3-35] 让模型帮忙看门，同时不敢把门全交给模型。

## P4 挂在循环上，不写进循环里

> 画面：循环环外围浮出四个空插槽（石青），回调卡片依次插入。
> 角标：Hooks · "Hang on the Loop, Don't Write into It"

- [p4-01] 到这一步，这个 AI 已经能安全地动手了。
- [p4-02] 接下来的麻烦所有做过工程的人都熟悉：你想加点东西。
- [p4-03] 比如每次跑命令都记一笔日志，或者某些操作做完自动提交一次代码。
- [p4-04] 每加一样，你都得回去改那个循环。
- [p4-05] 有人画过一张很扎心的图：循环体里记日志一行、查权限一行、
- [p4-06] 发通知一行、自动提交又一行，加到后面那段代码已经认不出来了。
- [p4-07] 原话说得很准：你想扩展的是它的行为，你改的却是循环本身。

> 金句卡（serif）：「你想扩展的是它的行为，你改的却是循环本身。」

- [p4-08] 正确的做法是把循环留成稳定的内核，让扩展挂在外面。
- [p4-09] 具体做法又是一张表：左边是「时机」，右边是这个时机要跑的函数。
- [p4-10] 循环到了某个时机只喊一声名字，至于该跑什么，由那张表说了算。
- [p4-11] 像墙上的插线口：循环是插座，功能是插头。
- [p4-12] 加功能是插一个插头，不是重新布线。
- [p4-13] 最简实现留了四个插口，正好串成一整轮。
- [p4-14] 第一个，你的话交出去、还没进模型之前：校验输入，或者补点背景。
- [p4-15] 第二个，工具要执行之前。刚才那三道闸门就搬到了这个插口上，
- [p4-16] 循环从此不再认识任何一个检查函数。
- [p4-17] 第三个，工具执行完、还没进下一轮之前：收尾的副作用挂这儿。
- [p4-18] 第四个，循环准备停机之前。这个插口最有权力：
- [p4-19] 它返回一句话，这句话就被当成新输入塞回去，循环继续转。
- [p4-20] 四个插口覆盖一整轮，循环只在这四个点上喊一声。
- [p4-22] 有句话我很喜欢：这个循环是故意保持无聊的。

> 金句卡（serif）：「这个循环是故意保持无聊的。」

- [p4-23] 实际实现里这样的时机，官方文档口径三十一个，
- [p4-24] 分三种节奏：会话一次、回合一次、每次调用前后。
- [p4-25] 处理器也不只是跑脚本，还能让小模型单轮判决。
- [p4-27] 表态的契约值得单独记：沉默，不等于批准——
- [p4-28] 不吭声的意思是「我不作决定」，流程照走。
- [p4-28a] 反过来，想真拦住只有一个硬信号；写错成惯用的失败码，
- [p4-28b] 闸门不响、动作照跑——静默失效。
- [p4-28c] 第一次给循环挂扩展的人，几乎都栽在这一脚上。
- [p4-29] 插口上的函数说「这个我批了」，就真的放行吗？不。
- [p4-30] 它的放行，仍要穿过后面的拒绝与询问两站。
- [p4-31] 方向是单向的：扩展点能加限制，不能解除限制。
- [p4-32] 而且这条单向，官方画成过六道闸门的流水线。
- [p4-33] 这一层超出了最简实现的范围，拆源码的人评语是：
- [p4-34] 做示例够用，生产环境就是一个安全漏洞。

> 金句卡（serif）：「扩展点能加限制，不能解除限制。」
> 角标：hook `allow` 不能绕过 settings 的 deny/ask —— 第三方的源码分析

- [p4-35] 那个能说「别停」的插口本身很危险——它叫模型接着干，
- [p4-36] 模型干完又要停，它又叫接着干，就转不出来了。
- [p4-37] 据他所说，它放了个标记，后面的轮次看到就不再拦。

## P5 四层叠起来是什么

> 画面：四级台阶升起，循环那一段自始至终同色同宽（陶土橙恒定）。
> 随后四层拼合成一个整体。

- [p5-01] 我们回头看这四层。
- [p5-02] 第一层，一个循环：反复问模型，替它执行，把结果搬回来。
- [p5-03] 第二层，一张分发表：让工具可以随便加。
- [p5-04] 第三层，三道闸门：让危险的事在执行之前被拦住。
- [p5-05] 回到官方那四件：循环、工具、上下文管理、护栏。
