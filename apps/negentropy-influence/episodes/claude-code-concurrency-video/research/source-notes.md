## 一、s13 Background Tasks —— 慢操作丢后台

### 定位与标语
- 【二】标语「慢操作丢后台，agent 继续处理」；Harness 层「后台——异步执行，不阻塞主循环」。

### 问题（原文，轨 A）
> 【一】洗衣机比喻（README 原话）：「你用过洗衣机吗？把衣服扔进去，按下启动，然后去干别的。
> 30 分钟后洗衣机滴滴滴提醒你：好了。你不会站在洗衣机前面干等 30 分钟。」
> 【一】「pip install 要 10 分钟、npm run build 要 3 分钟。Agent 等 10 分钟什么都不做，
> 而 LLM 按 token 计费，空转就是浪费。」

### 机制【一】
- **谁决定丢后台**：模型在 bash 工具的参数里**自己勾选**「后台执行」；没勾时教学版用关键词
  兜底猜（命令里含 install/build/test/deploy 等词 → 多半要跑超过半分钟）。
- **怎么跑**：慢操作包成一个工人函数扔进后台线程；每个后台任务有唯一编号；状态记在一张表里。
- **怎么接回来**：占位条**立即**返回（「任务 bg_0001 已开始，好了会通知你」）——一次调用永远
  对应一条结果，符合配对语义；干完后，完成通知排进队列，与下一轮的工具结果**合并成同一条
  用户消息**注入。通知不复用原调用编号（那是独立事件）。
- 线程是「守护」位：进程退出，线程跟着退。

### 生产版对照【三】
- ★ **「后台」其实不是线程**：CC 跑在 Node.js 单线程事件循环里，后台 = 「不等它」（不 await），
  stdout/stderr 重定向到文件让进程独立跑。所谓并发，是没有并发的并发。
- 完成通知走**共享命令队列**（`messageQueueManager.ts` / `framework.ts:267`），优先级分
  **「下一轮」＞「稍后」**——后台完成默认排「稍后」，**不插队**：排在用户的输入后面。
- ★ **停滞看门狗**（`LocalShellTask.tsx:59-98`）：后台命令 **45 秒**输出无增长，就去检查它是不是
  停在一个「要不要继续？(y/n)」的交互提示上等人点头——防止后台任务干等一个永远不会来的回答。
- 后台任务有**七种**（`Task.ts:7-13`）：跑命令 / 本地分身 / 远程分身 / 进程内队友 / 工作流 /
  监控外接 / 做梦（记忆整理，见记忆那一集）。跑命令只是其一。
- 顺手贴标签：每批工具执行完，一个小模型后台生成约 **30 字**的完成标签（像 git 提交说明，
  `toolUseSummaryGenerator.ts:15`）——一句带过。
- 前台并发上限默认 **10** 个（环境变量可调）；后台子进程无硬性上限。

## 二、s14 Cron Scheduler —— 按时间表生产工作

### 定位与标语
- 【二】标语「按时间表生产工作，调度与执行解耦」；Harness 层「调度——独立线程判断时间，
  队列传递触发」。

### 问题（原文，轨 A）
> 【一】闹钟比喻（README 原话）：「闹钟不需要你盯着它才会响。你设好 7:00，到点它自己响。」
> 【一】「s13 之后所有操作仍是你手动触发的。你说一句，它动一下。周期性的活不该每次都要人来推。」

### 机制【一】
- **四层**：调度线程（**每秒看一眼**表，时间到了把任务塞进队列）→ 队列 → 队列处理器（发现队列
  非空**且 Agent 空闲**才拉起一轮）→ 循环（从队列取出，注入成一条「定时触发」的用户消息）。
- **五格时间表**（cron，Unix 用了五十年）：分钟/小时/日/月/星期；支持 `*`、`*/N`、`N`、`N-M`、`N,M`。
  例：「每天早上九点」= 0 9 * * *；「每五分钟」= */5 * * * *；「工作日早上九点」= 0 9 * * 1-5。
- **分钟标记防重复**：同一分钟只放一枪（记「年-月-日 时:分」），第二天不会因此跳过。
- **单任务隔离**：一个坏任务抛错不杀调度线程（每个任务自己 try/except）。
- **校验先于注册**：时间表写错直接拒收，坏表进不了门；从磁盘加载时也跳过非法条目。
- **持久化真话**【一】：任务定义写进一个 JSON 文件，重启后恢复；但**调度器活在进程里**——
  把进程关了，表就停了。它不是系统闹钟服务。（README 用「重要前提」框强调。）

### 生产版对照【三】
- ★ **抖动防踩踏**（`cronScheduler.ts`）：重复性任务触发延迟最多可达周期的 10%（封顶 15 分钟），
  且**按任务编号的确定性哈希定死**——不是随机数，同一任务每次偏移一样。
  动机：全世界的定时器都卡整点（9:00:00），几千个任务同一秒全触发就是自我攻击。
- 一次性任务若落在整点/半点，最多**提前 90 秒**触发。
- **七天自动退休**（可配，上限 30 天）：过期前最后一次触发，触发后自动删除。上限 **50** 个任务。
- 文件锁防同项目多会话重复触发；还有文件观察者监听任务文件变化。
- 触发入队带**低优先级标记**：容量紧张时，定时任务发起的请求以更低的服务等级对待。

## 三、跨章主线：三种开始

| 开始 | 谁按 | 谁等 | 章 |

| 有人按并等 | 你 | 它和你一起等 | —（默认态） |

把「触发」挪出这个人。系列锚：本集的环**一秒不停**——工作块沿环外轨道走。

## 六、站点可视化文字规格（供 Remotion 重建）

1. **Background Overview（s13）**：主循环环 + 环外一条旁轨；慢命令块滑出环到旁轨跑，
   占位条立刻贴回环口；完成通知卡从旁轨末端排入环入口的队列。
2. **Notification Queue（s13）**：队列两级（下一轮/稍后）；用户输入卡永远插在「稍后」前。
3. **Watchdog（s13）**：秒表狗盯着后台命令的输出线；45 秒无增长，狗吠 + 检查放大镜
   对准「(y/n)」提示。
4. **Cron 四层（s14）**：调度线程（秒摆）→ 队列 → 队列处理器（闸）→ 循环（消费）。
5. **Jitter（s14）**：一排相同的表全指向 9:00；各自按算好的偏移错峰落下（确定性偏移，
   同表同偏移）。
