## P0 一个干不完

> 画面：系列片头装置之后冷启动——单个金色循环环体居中，大量任务块涌入环内、堆叠、溢出跌落；p0-01 落字同时一个任务块摔碎（警示红涟漪）

- [p0-01] 这是把一个 AI 变成一支队伍，真正缺的：不是更聪明的模型，是一组朴素的设施。
- [p0-02] 反直觉？先把问题摆出来。
- [p0-03] 给一个 Agent 派大活，比如重构整个后端。

- [p0-04] 它可能先写调用数据库表的接口，写到一半发现表不存在。
- [p0-05] 修到后面，前面认证的细节已经挤出上下文，就是它能同时记住的全部。
- [p0-06] 而认证、数据库、路由、测试，本来可以同时干。

- [p0-07] 执行清单是内存里的会话清单，不记依赖不记归属，换会话就没了。
- [p0-08] 子 Agent 倒是能叫，可那是一次性临时工：干一件事，回一句结论。
- [p0-09] 不能通信，不能协作，任务做完身份就散。

- [p0-10] 直觉的答案是：多开几个。
- [p0-11] 但从一到一群，几乎全是工程问题：谁干什么、怎么说话、怎么协商。
- [p0-12] 空闲了怎么找活、怎么不踩对方的文件、别人的工具怎么接。
- [p0-13] 这六个问题，一个都轮不到更聪明的模型来解决。
- [p0-14] 接下来把这六个问题，一个个修掉。

## P1 全景坐标

> 画面：archify 全景母图首次亮出——金色 Lead 大环居中，数个队友小环环外展开；六类设施以「共享文件」形态（青任务卡/紫收件箱/霜蓝目录条/银灰工具池）连线各环；本幕高亮「地基层」

- [p1-01] 这套解法朴素到意外：六个问题的答案，全写成文件系统上的普通设施。
- [p1-02] 文件系统，就是硬盘上按目录摆东西的那一层。
- [p1-03] 任务是目录里的 JSON 文件；消息是收件箱文件里的一<行|HANG2>一<行|HANG2>。
- [p1-04] 施工面是各自的工作目录；外部工具，是统一命名的池子条目。

> 角标：.tasks/ · .mailboxes/ · worktree · mcp__

- [p1-05] 六问列成规格：可恢复的目标、跨 Agent 通信、可追踪的协商。
- [p1-06] 自主分工、不冲突的施工面、可扩展的能力。
- [p1-07] 最后一条：机制再多，得挂在一个可运行的整体上。

- [p1-08] 跟你对话、提分工方案、等你确认才拉人的，叫 Lead。
- [p1-09] 被拉来干活的叫队友：各有角色指令、消息历史、精简工具。

- [p1-10] 记住这张全景图：大环是 Lead，小环是队友，中间连着全是文件。
- [p1-11] 队友写收件箱、认领任务，影响 Lead 的下一轮。
- [p1-12] 最关键的一件事在图外：Lead 从头到尾，没有第二个循环。
- [p1-13] 先看地基的第一件：任务板。

## P2 任务板与收件箱

> 画面：任务卡阵（青）从 .tasks 目录升起，六字段卡翻开；三状态灯与两动作按钮成型

- [p2-01] 每个任务是一个 JSON 文件，你就当一张结构化卡片，人能读，程序也能读。
- [p2-02] 六个字段：编号、标题、描述、状态、归属人、依赖列表。
- [p2-03] 状态只有三个：没人做、有人在做、做完。动作只有两个：认领、完成。

> 角标：blockedBy · pending / in_progress / completed

- [p2-04] 认领前有一道依赖检查：依赖里每个任务，都得是做完。
- [p2-05] 有一个没做完，甚至文件根本不存在，都不许开始。
- [p2-06] 引用错编号，不放行也不崩——不存在，按被挡处理。
- [p2-07] 完成时还主动扫一遍任务，把依赖刚凑齐的下游挑出来报告。
- [p2-08] 这叫解锁：完成动作自己带回，接下来谁能开工。

> 画面：走查实例——内容工厂四任务卡（初稿/配图/排版/发布）落位，依赖边生长；「认领≠完成」对比帧

- [p2-09] 走一个具体例子。
- [p2-10] 内容工厂四个任务：写初稿、配图、排版、发布。
- [p2-11] 排版依赖初稿和配图，发布依赖排版。
- [p2-12] 建完板，只有初稿和配图能领——排版的依赖没做完。
- [p2-13] 初稿做完，解锁报告亮出：配图能开工了。
- [p2-14] 注意：认领不算完成，初稿被领走，排版不会解锁。
- [p2-15] 初稿和配图都做完，排版解锁；排版做完，发布解锁。

> 画面：消融对比（左红右绿）——左：把「不存在视为被挡」改成「忽略」，陷阱任务卡被认领；右：在位拦截

- [p2-16] 原型拆一条给你看：把「依赖不存在就挡住」改成「忽略」。
- [p2-17] 一个依赖写错编号的陷阱任务，被认领了。
- [p2-18] 「不存在」和「没做完」必须分开：放行一个引用错误，就是在错的地基上开工。

> 画面：收件箱文件（紫）居中，消息行逐条追加；读取时整文件清空；快递柜小图一闪即收

- [p2-19] 任务板管「谁干什么」，接下来是「怎么说话」。
- [p2-20] 为什么不能共享同一个对话数组？
- [p2-21] 一个队友的工具结果，会灌进另一个的推理里，互相污染。
- [p2-22] 这里的做法：每个 Agent 一个收件箱文件，发消息是往对方文件里追加一<行|HANG2>。
- [p2-23] 读消息，是读掉整个文件再删掉——读和删，一体。
- [p2-24] 像快递柜：谁取出谁得到，柜格就空了，没人取到同一件两次。
- [p2-25] 边界：收件箱文件可以一直追加，快递柜满了会拒收。

- [p2-27] 子 Agent 是一次性调用：上下文只服务一个任务，只回结论。
- [p2-28] 队友是多轮存活的：跨任务保留上下文，能收发消息、参与协商。
- [p2-29] 什么时候叫临时工、什么时候组队，就看这条线。
- [p2-30] 能说话了，可关键动作光说不够——得有凭据。

## P3 带编号的握手

> 画面：关机场景——硬杀线程的红色叉打在队友小环上，半写的文件卡悬空；洗衣店两联票据小图（1.5 秒即收）

- [p3-01] 两个场景逼出同一套结构。
- [p3-02] 关机：硬杀队友的执行流，写到一半的文件就悬在那里。
- [p3-03] 计划审批：要动高风险的东西，先亮计划，批了再动手。
- [p3-04] 这两件事结构一样，像洗衣店两联取衣票：各持一半，对上号才交衣，票上写品类。
- [p3-05] 拿取衣票去取修的鞋，柜台会拒绝。
- [p3-06] 落成机制：请求带编号出去，回复带同号回来，登记表管状态。

> 角标：request_id · pending → approved / rejected

> 画面：四步握手时序动画——登记表（紫）记 req_000142，消息进收件箱，回复带回同号，登记表对号翻牌

- [p3-07] 以关机为例走四步。
- [p3-08] 第一步，Lead 生成编号，登记表记下：一个待定的关机请求。
- [p3-09] 第二步，把带编号的关机消息，放进对方的收件箱。
- [p3-10] 第三步，队友收到，按消息类型处理：是关机请求，先收尾。
- [p3-11] 第四步，队友回复带回同一编号和态度；Lead 对号改状态。

- [p3-12] 改状态前，有三道检查，各拦一种错。
- [p3-13] 编号对不上就不理——拦住误更新别人的请求。
- [p3-14] 类型对不上就不理——拦住一条关机回复误批准计划。
- [p3-15] 状态不是待定就不理——拦住同一回复生效两次。

> 画面：消融对比——左红：拆掉类型检查，一条关机回复把计划请求翻成「已批准」；右绿：在位拦截

- [p3-16] 原型把第二道拆掉实测：一条关机回复，把一个待定的计划请求改成了已批准。
- [p3-17] 编号对上还不够，品类对上，才算同一件事。

> 画面：坑——两个读取入口（工具直读+主循环）各自伸进收件箱，消息被先到者拿走，登记表停在「待定」灰化

- [p3-18] 接下来有个坑，就埋在读和删一体上。
- [p3-19] 查收件箱的工具和主循环各自去读：先读的拿走消息，核对没做。
- [p3-20] 所以收件箱要收敛成统一入口：先按编号路由回复、更新登记表，再交出消息。
- [p3-21] 原型实测：拆掉后回复被读走，再读剩零条，状态不动。
- [p3-22] 读即消费，必须配单点入口——这两件事是成对的。
- [p3-23] 说话和协商都稳了。可活儿呢，谁派？

## P4 自己找活干

> 画面：任务板上十张未认领卡排队，Lead 环手动派单箭头繁忙闪烁（霜蓝转红）；随后箭头撤掉，队友小环自己亮起扫描光圈

- [p4-01] 板上十个没人认领的任务，等 Lead 手动派，得派十次，不能扩展。
- [p4-02] 答案：让队友自己看板、自己认领、做完再找下一个。

- [p4-03] 队友的生命周期，是三阶段循环。
- [p4-04] 干活阶段：查收件箱、调模型、执行工具，不要工具了本轮结束。
- [p4-05] 空闲阶段：不退出，每五秒醒一次，这是教学版的取值。
- [p4-06] 醒来先看收件箱：关机请求和点名指令优先。
- [p4-07] 收件箱空了再扫任务板：没人做、依赖齐了的就认领，回到干活。
- [p4-08] 六十秒没等到活，发总结收摊，同样是教学取值。
- [p4-09] 为什么收件箱优先？点名指令耽误全局，公共的活晚一轮没事。

> 画面：深水区——两个队友小环同时锁定同一张任务卡；认领三步（读文件/查归属/写归属）时序展开；影院选座小图一闪（≤2 秒）

- [p4-10] 真正的深水区，在认领这一步。
- [p4-11] 两个队友同时看上同一个任务，而认领是三步：读文件、查归属、写归属。
- [p4-12] 影院线上选座就是这个问题：两人看到同一个空座，锁座必须做成一步。
- [p4-13] 看见，不等于抢到。
- [p4-14] 边界说清楚：这比方说的是目标状态。教学版恰恰没有这把锁，真会后写覆盖。

> 画面：消融对比——左红：无锁交错，两条写入先后落下、都亮「成功」徽章，终值是后写者；右绿：锁内在位，仅一人成功

- [p4-15] 原型实测：无锁交错，两个队友都以为抢到了——重复劳动，后写覆盖先写。
- [p4-16] 修法：检查和写入一口气做完；扫描只出候选，改归属只在锁内。

- [p4-17] 上下文压缩，可能把队友的消息历史压成一段摘要。
- [p4-18] 教学版查消息长度，过短就判定被压缩，重新注入身份：你是谁、角色是什么。
- [p4-19] 都自己找活了，下一个坏法立刻出现：两个队友，改同一个文件。

## P5 各改各的目录

> 画面：两束编辑光标同时落在同一份 config 文件上，改动互相覆盖、版本线纠缠成乱麻（警示红）

- [p5-01] 两个队友真的同时改起了同一个文件。
- [p5-02] 互相覆盖，分不清谁的改动，回滚都不干净。
- [p5-03] 现成答案是 git worktree：同一份代码铺开多个目录，各挂各的分支。

> 角标：git worktree · wt/{name}

- [p5-04] 这里的用法是任务级绑定：建目录、建分支、把目录名写进任务文件。
- [p5-05] 绑定不改任务状态：队友空闲时，自然领走带目录的活。
- [p5-06] 领到之后，它的读写和命令都在那个目录下执行。

- [p5-07] 收尾的保护，比创建更值得学。
- [p5-08] 删目录之前先<数|SHU3>两样：没提交的文件<数|SHU3>、没推送的提交<数|SHU3>。
- [p5-09] 有一样不是零就拒绝删；丢弃要显式，或留分支等审查。
- [p5-10] 完成和清理是两回事：完成记结果，收不收目录，人决定。

> 画面：边界护栏帧——worktree 目录墙（霜蓝）上一把虚线锁；Shell 命令箭头绕过墙体直达全盘（警示红描边）

- [p5-11] 边界必须说死：worktree 分开的是 Git 工作目录和分支，不是安全沙箱。
- [p5-12] Shell 命令还是能碰任何它够得着的路径。
- [p5-13] 拿它挡不可信代码，是把它当成它不是的东西。

> 画面：工具池（银灰+金描边）——内置工具条整齐排列，新服务连接后清单滑入、全名标签贴牌、池子重拼

- [p5-14] 最后一类设施，管能力从哪来。
- [p5-15] 到这里，工具全是手写的：接新服务要再写一套，改了还得跟着改。
- [p5-16] 开放标准 MCP 拆成两半。
- [p5-17] 外部服务给清单、执行；Agent 端管连接、命名、权限和组装。
- [p5-18] 连接：找到服务，拿到清单，每个工具带名字和说明。
- [p5-19] 命名：统一成服务名加工具名的全名，同名也不顶。
- [p5-20] 非法字符一律替换，撞名报错，超长拒绝。
- [p5-21] 组装：每轮把内置和外部工具拼成同一个池，全名靠对照表翻译。

> 画面：消融对比——左红：沿用旧池调新工具，弹出「Unknown tool」；右绿：池子重建，调用正常返回

- [p5-22] 连接后有个容易漏的动作：工具池变了，依赖它的缓存必须作废。
- [p5-23] 原型实测：沿用旧池调新工具，返回未知工具；重建后正常。
- [p5-24] 池子是动态的。缓存旧清单，新工具永远调不到。
- [p5-25] 六组设施到齐了，还差最后一步：放回同一个系统。

## P6 循环一个

> 画面：archify 母图回归——金色大环居中，挂点表沿环体展开（钩子/队列注入/权限/告警/收尾），六类设施图标逐层点亮归位

- [p6-01] 前面每组设施都是单讲的。真实系统，不带单一机制出门。
- [p6-02] 最后一步，把全部机制放回同一个系统——价值不在新机制，在位置感。
- [p6-03] 输入之后，钩子先看一眼；调模型之前，队列和记忆先注入。
- [p6-04] 执行前权限拦一道，执行后有告警；没有工具调用了，收尾统计。
- [p6-05] 循环周围越来越厚，循环还是四句：调模型、看工具调用、执行、喂回去，再转一圈。

> 画面：两组对比卡——「两层计划」（会话清单 vs 任务图）与「两种委派」（一次性子 Agent vs 持久队友）双门对照

- [p6-06] 两层计划：会话内清单防漂移；跨会话任务图，可依赖可认领，撑起协作。
- [p6-07] 两种委派两道门：只要结论用一次性子 Agent；要长期并肩用持久队友。

> 画面：基线增长条（Baseline-Anchored Bar）——8→14→18→27 四段阶梯柱生长定格，口径角标「教学版逐章实测」；五层机制栈依次点亮（系列身份卡）

- [p6-08] 工具从八个长到二十七个，循环零改动。
- [p6-09] 这一路讲下来：先让它动手，再替它安排，帮它记住，教它同时干，今天让它带队伍。
- [p6-10] 收在一句话里：代码越来越复杂，核心始终没变。
- [p6-11] 复杂的不是另一个 Agent 大脑，是这层外壳本身。
- [p6-12] 机制很多，循环一个。
