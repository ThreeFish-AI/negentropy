## P0 没人派活的队伍

> 画面：系列片头装置之后冷启动——任务墙全景：十几张任务卡挂墙无人认领，队长方块挨个点名派活、忙得团团转，两名队友方块做完活原地立正待命；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一支没人派活、也从不停工的队伍。
- [p0-02] 老办法：干完一件，站着等队长派下一件。
- [p0-03] 墙上挂十个任务，就得手动派十次——队伍撑不大。

> 画面：值班钟装置首次亮出——每位队友胸口挂一座小钟（天蓝），钟摆每五秒落一拍：先探收件箱格口、再扫任务墙；三条件全齐的卡上亮起名字

- [p0-04] 答案朴素得出奇：自己看板，自己认领。
- [p0-05] 每个队友身上，装一座值班钟。
- [p0-06] 空闲了，钟每五秒敲一拍：先看信，再看板，能干的写名领走。
- [p0-07] 听着万事大吉——偏偏「认领」这一步，藏着最深的坑。

## P1 先看信，再看板

> 画面：三状态指示环——队友机体上「干活 / 空闲 / 关机」三格灯依次点亮（干活=暖白高频、空闲=天蓝呼吸、关机=暗灰收束）；环体〔M-001〕在队友身后同步转动

- [p1-01] 先立全貌：队友的一生就三个状态——干活、空闲、关机。
- [p1-02] 干活：收信、想、调工具；空闲：不退出也不干等，钟开始敲。

> 画面：每拍动作分镜特写——钟摆落下两个落点：第一落点收件箱（点名信封弹出置顶），第二落点任务墙；「冲你来的」与「公共的」两枚标签对照亮出

- [p1-03] 每一拍动作固定：先看收件箱，再看任务墙。
- [p1-04] 顺序有讲究：关机和点名是冲你来的，晚一步耽误全局。
- [p1-05] 墙上的活是公共的，晚一轮没关系。

> 画面：任务墙卡面放大——每张卡三枚条件灯：没人做、没归属、依赖全完成；三灯齐亮才放行写名，缺一条的卡滑过（跳过动效）

- [p1-06] 信箱空了才看墙：找没人做、没归属、依赖全完成的卡——缺一条跳过。
- [p1-07] 找到就写名认领，回干活；找不到，睡到下一拍。

> 画面：队友消息清单压缩动画——长清单叠成一小段摘要（灰），一段「身份说明」卡（天蓝）重新注入清单头；「回到干活」箭头亮起

- [p1-08] 回干活前还有道检查：自己攒下的消息记录短得反常、被压成摘要，就把「我是谁、干什么活」重写一遍。

> 画面：十二拍计数环走满、六十秒表到点——队友发一条总结卡进队长收件箱，钟停、机体收拢成暗灰；小结卡「规矩就这么几条」

- [p1-09] 敲满十二拍、六十秒还没活：发一条总结，收摊走人。
- [p1-10] 规矩就这么几条——灵不灵，走一遍。

> 角标：WORK · IDLE · SHUTDOWN · IDLE_POLL_INTERVAL · IDLE_TIMEOUT · blockedBy

## P2 走查：一个空闲拍

> 画面：走查舞台——内容工厂任务墙特写：初稿、配图、排版、发布四张卡挂墙，依赖线（排版←初稿+配图、发布←排版）依次点亮

- [p2-01] 走个例子。内容工厂四件活：初稿、配图、排版、发布。
- [p2-02] 排版依赖初稿加配图；发布，依赖排版。

> 画面：队友一交完「初稿」卡（打勾变绿）——值班钟落下第一拍：先探收件箱（空），再扫墙：配图卡上队友二的名字亮起；陷阱卡依赖栏写着不存在的编号、红灯常亮

- [p2-03] 队友一交完初稿，钟响：先看信，空的。
- [p2-04] 再看墙：配图刚被队友二写上名字，不动。
- [p2-05] 有张陷阱卡：没主没人做，依赖写着不存在的编号——按被挡算，不许开工。

> 画面：第二拍——队友二交完「配图」卡；排版卡三枚条件灯齐亮，队友一伸手写名、卡面翻成进行中，环体〔M-001〕重新转起

- [p2-06] 这一拍没活，睡。下一拍，队友二交完配图。
- [p2-07] 再扫：排版三条全齐——写名，认领，回干活。

> 画面：四张卡全部翻绿、陷阱卡纹丝不动挂着；全景拉远——没人指挥，活全部落地；「同一拍、同一张卡」的阴影从画面边缘渗入

- [p2-08] 四件活全部落地，陷阱卡纹丝不动——没人指挥过一句。
- [p2-09] 可要是两个队友，同一拍看上同一张卡呢？

## P3 看见不等于抢到

> 画面：双镜分屏——两个队友的视线同时落在同一张空卡上；卡面下方认领三步流水条亮出：读卡 → 查归属 → 写名字，第二、三步之间裂开一道窗口

- [p3-01] 最要命的巧合：同一拍，两人扫到同一张空卡。
- [p3-02] 认领其实是三步：读卡、查归属、写名字。
- [p3-03] 扫描看到的只是某一时刻的快照；查完到写入，隔着一道窗口。

> 画面：电影院选座界面——两个光标同时悬停同一个空座；真实系统的「锁座下单」合成为一枚不可分割的按钮

- [p3-04] 像电影院线上选座：两个人，同时看到同一个空座。
- [p3-05] 选座系统把锁座下单做成一步——看见，不等于抢到。
- [p3-06] 教学版，恰恰没有这把锁。

> 画面：左红右绿消融同屏——左「撤掉锁」：两条写名箭头先后交错刺入同一张卡，卡面名字被后写者覆盖（警示红）；右「装回锁」：洋红临界区框住写名一步，仅一人进入成功（确认绿）

- [p3-07] 教学原型上实测：撤掉锁，让两边交错认领。
- [p3-08] 日志两<行|HANG2>：这边写「归属：队友一」，那边写「归属：队友二」。
- [p3-09] 双方都以为到手；卡上只留一个名字——后写的那个。
- [p3-10] 同一件活干两遍，另一边还蒙在鼓里。
- [p3-11] 把锁装回去重跑：同一个场景，只有一个人成功。

> 画面：金句卡（衬线体）压屏——「看见 ≠ 抢到」；锁形图标在卡右下角亮起问号

- [p3-12] 被挡就当没领到，不可怕；无锁交错，连这点感知都没有。
- [p3-13] 看见不等于抢到，查与写一口气做完——这把锁，谁来上？

> 角标：simulate_concurrent_claims · atomic · owner · TOCTOU

## P4 补上一把锁

> 画面：锁结构剖视图——认领被拆成两个独立房间：「扫描间」只出候选快照；「写名间」门上两道闩（进程锁 + 文件锁，洋红描边），门内立着「重读一遍卡」提示牌

- [p4-01] 补这把锁，另一版做得更完整：发现和认领，拆成两步。
- [p4-02] 扫描，只负责把卡挑出来；写名字，锁进一次只许一个人进的代码段。
- [p4-03] 门有两道闩：进程里一把锁，磁盘上一把文件锁。
- [p4-04] 进门先重读一遍卡，掐死查与写之间的窗口。

> 画面：真实版认领流程条——五步（重读 / 查归属 / 查完成 / 查依赖 / 写名字）被洋红括弧一口气框住；锁占用时的退避重试时钟（三十次上限、五到一百毫秒刻度）；官方文档页角标亮起

- [p4-05] 拆解过 Claude Code 源码的同学们应该知道：真实版认领，也包在文件锁里。
- [p4-06] 官方文档也明说：这把锁防的，就是同时抢任务。
- [p4-07] 重读、查归属、查完成、查依赖、写名字——五步一口气锁完。
- [p4-08] 抢不到锁就退避重试：最多三十次、五到一百毫秒。
- [p4-09] 空闲的节奏也快得多：约五百毫秒一轮，还不设固定超时。

> 画面：天平两端——左「六十秒收工」小钟（计价器滴答，怕空转烧钱）、右「长驻等待」常亮灯（积木堆越摞越高，怕重建贵）；天平停在中间不打摆

- [p4-10] 闲多久，两版选得不一样：六十秒收工怕空转；长驻等待，怕队友记忆从头重建。

> 角标：task_store_lock · RLock · flock · proper-lockfile · claimTaskWithBusyCheck
