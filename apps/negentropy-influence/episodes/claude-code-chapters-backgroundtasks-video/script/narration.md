## P0 卡住的十分钟

> 画面：系列片头装置之后冷启动——环体〔M-001〕在「执行」段被一块「等待」砖压停（陶土橙转暗）；旁边终端窗口两条命令对比：读文件毫秒返回、安装命令进度条缓慢爬行；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一条能把整个循环，卡在原地干等的命令。
- [p0-02] 读个文件，眨眼就完；装一套依赖，十分钟能跑满。
- [p0-03] 这十分钟，模型一步动不了，按文字量计费，空转也在花钱。

> 画面：洗衣机三拍示意（衣服扔进去→按下启动→人走开，洗毕提示灯自亮）；A#1 失配边界以角注小字承载（滚筒一次一桶，后台任务可并行挂多条）

- [p0-04] 可没人会站在洗衣机前，盯满三十分钟。
- [p0-05] 衣服扔进去，按下启动就走人——好了，它自己提醒。

> 画面：对话协议卡浮起——「一次调用 → 一个结果」的槽位尚未展开（悬念留给下一幕）；环体仍被压停

- [p0-06] 循环也该这样：慢命令丢出去，结果自己回来。
- [p0-07] 只差一步——对话的规矩，不答应。

## P1 名额与闸门

> 画面：协议特写——每个调用块只带一个结果槽位（单槽高亮）；两条岔路演示「等它跑完」（计时器膨胀）与「先回再补」（违规红叉）分别撞墙

- [p1-01] 对话协议有条硬规矩：一次调用，只配一个结果。
- [p1-02] 名额就一个：等它跑完是干等；先回再补，是违规。

> 画面：双闸门装置首次亮出——第一道闸门读参数卡（确认绿放行）、第二道扫描命令文本（关键词逐个点亮，十一词全表进角标）；细节拍：显式「不要」小卡被兜底闸门无视

- [p1-03] 解法是丢后台——可谁说了算，哪条命令算慢？两道闸门来把关。
- [p1-04] 第一道看模型：参数明写了要后台，直接放行。
- [p1-05] 第二道是兜底：模型没开口，就翻命令找字眼。
- [p1-06] 安装、构建、测试这类词一撞上，就猜它是慢操作。
- [p1-07] 容易漏看的细节：明说「不要后台」，也拦不住这道兜底。

> 画面：左红右绿消融同屏——左「拔掉兜底」：安装命令落回同步执行、阻塞条涨到 600 秒（警示红）；右「兜底在位」：分派转后台、阻塞 0 秒（确认绿）；600 秒处标注「＝十分钟全程」

- [p1-08] 实测说话：拔掉兜底，同条安装命令落回原地干等——主循环从零秒一路卡到六百秒。
- [p1-09] 模型忘说一句「丢后台」，代价就是十分钟全程陪等。
- [p1-10] 可就算进了后台，真结果要怎么进对话？名额只有一个。

> 角标：tool_use → tool_result · run_in_background · should_run_background · slow_keywords（install / build / test / deploy / compile / docker build / pip install / npm install / cargo build / pytest / make）· dispatch: heuristic → sync · 0s → 600s

## P2 占位回执

> 画面：登记表装置视觉首次亮出（后台执行蓝）——三列：编号／状态／摘要；三件事逐一点火：命令卡滑入后台线程轨、编号落表、占位回执卡弹回模型

- [p2-01] 决定后台化，循环当场做三件事。
- [p2-02] 第一，交给后台线程，程序里另开的一条并行执行线。
- [p2-03] 第二，发编号：从零零零一递增，状态记进登记表。
- [p2-04] 第三，马上回占位回执：任务已启动，结果完成后可得。

> 画面：小票三拍示意（店员递小票→订单当场闭合 → 餐好叫号广播→新事件卡点亮）；失配边界小卡随行（名额用掉不退）

- [p2-05] 像点单取餐：店员先递小票，订单当场闭合。
- [p2-06] 餐好了叫号广播，那是新事件，没人收回小票重写。
- [p2-07] 边界：小票丢了还能凭记忆取；名额用掉，就是用掉了。
- [p2-08] 模型拿着占位转头干下一件，真结果在后台赶路。

> 角标：bg_0001 · daemon thread · BackgroundTasks.start · registry + lock

## P3 迟到的通知

> 画面：通知卡结构展开（通知注入紫）——任务号／状态／原命令／摘要≤200 字四栏；主循环环体每转一圈过一遍登记表，收走的行点亮成独立通知卡，与当轮结果合入同一条消息条

- [p3-01] 后台跑完，真结果怎么回来？不补旧账。
- [p3-02] 它被包成一条独立通知：任务号、状态、原命令，加一段摘要。
- [p3-03] 摘要最长两百字——再长的输出，也只留开头。
- [p3-04] 送它进对话的是主循环自己：每轮交结果前，顺手查一遍登记表。
- [p3-05] 做完的，收进通知，跟当轮结果合进同一条消息送进对话。

> 画面：两回合时间轴走查——回合一：安装命令（带后台参数）→占位回执→预告读配置；回合二：配置内容当场返回＋安装通知点亮，同框定格（Animated State Trace）

- [p3-06] 第一回合：模型发起安装命令，带上了后台参数。
- [p3-07] 循环回占位回执；模型顺势预告，要把配置文件也读了。
- [p3-08] 第二回合：读配置是快命令，当场拿到内容。
- [p3-09] 主循环顺手收集后台结果，安装通知和配置内容同框出现。
- [p3-10] 从发起到收尾，主循环一分钟都没干等——路通了，坎还在后头。

> 角标：task_notification · turn 1 / turn 2 · npm install · package.json · summary ≤ 200

## P5 写下不等于会跑

> 画面：纸质日程本示意卡（写好的计划跨年都在）→ 程序进程窗口关闭、日程本静置无人翻；重启后任务卡被调度器自动拾起、下次到点照常触发（确认绿）

- [p5-01] 收尾前一个误会：还有一类到点才跑的任务——定义写进磁盘，调度却活在程序进程里。
- [p5-02] 进程一关，一切停摆——保住定义，保不住「到点会发生」。
- [p5-03] 像纸质日程本：计划跨年都在，没人翻开就不会发生。
- [p5-04] 纸本永远等人翻；任务重启后自动被拾起，下次到点照常触发——停摆错过的，不补跑。

> 画面：环体定格收束＋金句卡（衬线体）；「等待」砖块已清走，环体照常旋转

- [p5-05] 一句话收束：慢操作不能赊账——占位先闭合问答，真结果走新消息进场。
- [p5-06] 主循环还是那个循环，只是不再傻等。

> 画面：下期卡（视觉层）——日历上九点的测试任务＋「谁来提醒」问号（不出现调度器／时间表意象，只点问题）→ 淡出
