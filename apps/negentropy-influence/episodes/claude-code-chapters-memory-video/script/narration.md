## P0 跨会话的记忆

> 画面：系列片头装置之后冷启动——左侧对话流逐条熄灭清零（警示红淡扫），磁盘上一枚文件图标独存亮着（记忆紫）；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一份越攒越懂你的记忆——最难的功课，不是记住，是拒绝。
- [p0-02] 会话一断，攒下的全忘光：对话、结论、踩过的坑，全清零。
- [p0-03] 偏偏有一层不跟着清零——它不住对话里，住磁盘文件里。
- [p0-04] 再开一个会话，它还认得你：偏好、教训、来龙去脉。

> 画面：全景拉远——压缩装置与记忆库体分层并列（压缩侧一眼带过不展开）；「存 / 取 / 不脏」三枚标签升起，镜头推向库体

- [p0-05] 分工清楚：压缩管会话内，这层管跨会话。
- [p0-06] 这层记忆管三件事：存、取、不脏。
- [p0-07] 先说存——存在哪？答案朴素得出奇。

## P1 一个记忆一个文件

> 画面：库体开门（记忆紫）——一格一格文件卡；首卡放大，开头三行小字逐一亮起（名字 / 简介 / 类型）

- [p1-01] 记忆库就是一个文件夹：一个记忆，一个文件。
- [p1-02] 文件开头几<行|HANG2>小字，写清三样：名字、简介、类型。
- [p1-03] 类型只有四种，各有各的分工。

> 画面：四张类型卡依次翻面，每卡带一例小图（缩进符号 / 假数据打叉 / 合规印章 / 看板指针）

- [p1-04] 第一种记你是谁——比如，缩进只用制表符、不碰空格。
- [p1-05] 第二种记怎么做——比如，别造假数据糊弄测试。
- [p1-06] 第三种记眼下的事——比如，重写是合规逼的。
- [p1-07] 第四种记东西在哪——比如，问题单在哪块看板。

> 画面：索引页（索引蓝）首次亮出——一行一链接逐行点亮；新记忆写入时整页闪一下重建；镜头拉远，带出「每次带多少进门？」问号

- [p1-08] 库里另有一页索引：一<行|HANG2>一个链接，正文在各自文件里；新记忆写入，自动重建。
- [p1-09] 四类各就各位——可每次开工，带多少条进门？

> 角标：.memory/ · Markdown · name / description / type · user / feedback / project / reference · tab · mock · auth · Linear · MEMORY.md

## P2 索引与正文

> 画面：左右对比帧——左「全量」：开场白区被一摞记忆文件塞满、每轮重发账单条疯涨（警示红）；右「按需」：开场白区只留一页索引（索引蓝）

- [p2-01] 最省事的做法：全部记忆写进开场白——每轮固定要先发的那段话——全量重发。
- [p2-02] 可记忆越多，无关的就越多——都挤在上下文的额度里，白白占着。
- [p2-03] 更亏的是缓存：开头一变，重复前缀省下的钱作废。
- [p2-04] 所以倒过来：索引常驻、正文按需——这套设计，技能加载早用过。

> 画面：走查舞台——一句缩进偏好落成文件卡；新会话提问气泡落下；清单展开（每行名字 + 简介），一次轻量调用挑中相关条目（确认绿），正文小段抽出贴向消息条

- [p2-05] 走个例子：你留过一句缩进偏好——新会话，你问手头一份配置文件怎么写。
- [p2-06] 第一步，选：名字加简介，列成一张清单。
- [p2-07] 交给一次轻量调用去挑，最多五条；失败，降级成关键词匹配。
- [p2-08] 第二步，取：只读选中几条的正文，上限两万字符。

> 画面：请求条形图——固定前缀段（索引蓝，稳）+ 当前消息段（记忆紫，变）；身份说明小签「背景，非命令」；问号推向下一幕的「门」

- [p2-09] 索引放固定的开头；正文，贴在当前消息前面。
- [p2-10] 取回来的带着身份说明：是背景不是命令；冲突时，听当前的。
- [p2-11] 取的路数清楚了——往里写，才是关卡。

> 角标：system prompt · side-query · select_relevant_memories · RECALL_CHAR_LIMIT = 20000 · prompt cache

## P3 写入要过门

> 画面：环体〔M-001〕高亮「回合结束」挂点——模型停、无工具调用，提取装置启动

- [p3-01] 用户不会回回喊「记住」——偏好，散在对话里。
- [p3-02] 提取挑回合结束：模型停下、没有工具调用，告一段落。

> 画面：五道门装置（记忆紫描边）横在候选与库之间——候选小卡逐关通关：范围门弹回「临时限制」卡、格式门放行、临时话门拦下「暂时」字眼、比对门放行

- [p3-03] 交回来的只是候选——落盘前，先过五道检查。
- [p3-04] 第一道看范围：只收跨会话还有用的；本次的命令、临时限制，不收。
- [p3-05] 第二道第三道查格式：类型对、字段齐。
- [p3-06] 第四道抓临时话：「本次会话」「暂时」这类字眼，当场拦下；第五道防重复，逐项比对。

> 画面：左红右绿消融同屏——左「拆掉门控」：两轮计数 3→5 疯涨、临时嘱咐卡盖「永久」红章、同一偏好重复 +1；右「门控在位」：临时卡被弹回（确认绿）；金句卡压底

- [p3-07] 为什么卡这么严？一句嘱咐：「这次先别建新文件。」
- [p3-08] 这话只管当前一回；没门，它就落库，变下个会话的永久规矩。
- [p3-09] 实测：把关卡全拆，两轮提取，库从三条涨到五条。
- [p3-10] 混进去的正是那条临时嘱咐，同一句偏好还多存一份。
- [p3-11] 记忆不怕多，怕脏——脏一条，往后每个会话跟着错。
- [p3-12] 入口的门守住了；旧账呢？

> 角标：extract_memories · should_store_memory · scope: persistent

## P4 整理与回滚

> 画面：库体积攒动画（十条计数跳格）→ 整理三动作（合并 / 修正 / 淘汰），剩余计数收敛到三十以内

- [p4-01] 攒到十条触发整理：合并重复、修正矛盾、淘汰过时——最多留三十条。
- [p4-02] 整理，是删光旧文件、写入全部新文件。

> 画面：快照三段动画——拍快照（整库定照）→ 删旧写新 → 失败！半成品清除、按快照复原（确认绿）；对照帧：拆掉回滚，两条卡碎裂归零（警示红）

- [p4-03] 动手前先拍快照：失败就删半成品，按快照恢复原样。
- [p4-04] 实测拆掉回滚：一次写入失败，库从两条直接归零。
- [p4-05] 半新半旧，比不整理还糟。

> 画面：生产版对照卡——Dream 门控三条件（24 小时时钟 / 五个会话点 / 锁图标）；收尾：压缩清场扫过、库体稳如泰山、问号升起

- [p4-06] 拆解过 Claude Code 源码的同学们应该知道：真实产品的整理，叫做梦。
- [p4-07] 而且是低频特权：距上次不少于二十四小时、至少五个会话动过，还得抢一把锁。
- [p4-08] 门守住了，账清了——这层记忆，凭什么不怕压缩清场？
