## P0 万能的手没有形状

> 画面：系列片头装置之后冷启动——终端窗口中央三条命令行越拼越长（引号套引号、转义叠转义），最后一条拼到折<行|HANG2>；右下角常驻署源角标（信源名，首部署源位，随画面淡入）

- [p0-01] 这是一双什么都拿得动，却事事要先拼咒语的手。
- [p0-02] 家什只有一件：bash。
- [p0-03] 想读，拼一条读的命令；想写，引号套引号；想改，请出更拗口的命令。
- [p0-04] 模型想的是读这个文件，说出口的，却是一串字符。

> 画面：灰色的「翻译层」箭头压在命令行上，把意图（一个文件图标）翻译成一长串字符；「费」字计数小卡弹出又收起

- [p0-05] 这层翻译费钱粮，还容易拼错——错一个字符，整条作废。
- [p0-06] 更深一层：bash 万能，却没有形状——在程序眼里，读和写都是一串字符。
- [p0-07] 今天，给它长出更多的手：一只手一件事，各有名字。

## P1 两件事与一张表

> 画面：琥珀色对照表首次亮出——左列名字、右列函数；一条新定义滑进工具清单（名字+描述+参数说明书三件小卡）

- [p1-01] 先摆答案：加一个工具，只做两件事。
- [p1-02] 第一件，定义：清单加一条，名字、描述，一份参数说明书。
- [p1-03] 第二件，注册：往对照表里加一行，名字，对上干活的部件。

> 画面：环体〔M-001〕高亮「执行」段：拆下写死的「跑命令」方块，换上查表动作（名字→表→函数→参数递入）；五件工具卡沿表依次入场

- [p1-04] 循环里唯一的变动在执行：写死的跑命令，换成查表，名字对出部件，参数递过去。
- [p1-05] 从一件长到五件：跑命令、读文件、写文件、改文件、找文件。
- [p1-06] 加一个工具，两处改动；循环，一<行|HANG2>没改。

> 画面：对比定格——五件工具卡 vs 一件 bash 卡，能力面等高；「看得清」透视镜叠上：调用卡片显出结构（动作名+参数齐整排列）

- [p1-07] 值得停一拍：这五件没给模型新本事——同样的活，原来那件也能干。
- [p1-08] 它们改善的是接口：模型直接说意图；装置第一次看得清——这是读，那是写。

> 画面：四件文件工具卡外框亮起同一条边界线（工作目录范围框）；一枚越界的路径卡撞上边界、弹回

- [p1-09] 文件类的四件各带一道边界：路径必须落在工作目录内，越界即报错。
- [p1-10] 安全这件事，第一次有了抓手。

## P2 同一件事，两种说法

> 画面：走查舞台左右分屏——左「bash 咒语」右「专用工具」；指令气泡落下：读 a、读 b、列出 Python 文件

- [p2-01] 走个例子。你说：读一下 a、b 两个文件，列出所有代码文件。
- [p2-02] 交给 bash：三条命令，读要拼路径，列要配模式，错一个字符就废。
- [p2-03] 专用工具版：一次回答带三个调用——两枚读文件、一枚找文件，参数就位。
- [p2-04] 照表分发，逐个执行，结果原路回喂。
- [p2-05] 同一件事，两种说法：左边咒语，右边意图——那层翻译，消失了。

> 画面：右侧消息条放大——三个调用块并排，各带一枚编号小签（单号雏形，下一幕主角）

- [p2-06] 顺带一件新事：一次回答，可以同时带好几个调用。
- [p2-07] 那结果怎么各归各？往下看。

## P3 谁的结果归谁

> 画面：编号特写——每个调用块弹出一枚单号签；结果包裹逐一贴上同号回执，沿回喂流对回原调用（确认绿）

- [p3-01] 秘密在编号上。每个调用，自带一个唯一单号。
- [p3-02] 执行侧把结果包成同号回执，喂回去时按单号对回原调用。
- [p3-03] 像快递并发派送：多个订单，包裹各贴单号——谁先到都对得回。
- [p3-04] 边界：快递单号跨天有效、可查物流；这个单号只活一轮，回执也只此一份。

> 画面：打字机式顺序执行动画（教学版按序逐个跑）；画面深处乱序与并发的影子一闪

- [p3-05] 教学版按顺序执行——配对的价值，要到乱序与并发才显形。
- [p3-06] 实测说话：先让结果乱序到达，再拔掉编号——同轮结果当场错绑。

> 画面：左红右绿消融同屏——左「拔掉编号」：轮次十格全亮、活计七件全落地，但一轮两枚结果互换归属（珊瑚红旋转箭头）；右「配对在位」：全绿零错绑

- [p3-07] 十轮照跑完十轮，七件活照做——外面看不出异样。
- [p3-08] 错处在里面：有一轮两个调用，结果互换——模型拿到别人的答案。
- [p3-09] 教训一句话：没有配对，乱序即错位。
- [p3-10] 顺序好的时候它白拿工资；一乱，就翻车。

> 角标：tool_use_id · tool_result

## P4 生产版：五道关

> 画面：五道关门卡依次落位（琥珀描边）横在工具调用与执行之间；调用小方块逐关通关

- [p4-01] 那真实的 Claude Code 呢？
- [p4-02] 拆解过 Claude Code 源码的同学们应该知道：每个工具调用，落地前要过五道关。
- [p4-03] 参数查两道：格式、取值；再一道先行检查、一道放行权，第五道才是执行。

> 画面：连续批分区全景——一串调用切三批：前批并发（多箭头同时出）、中批单独串行、后批再并发；批间顺序箭头恒定

- [p4-04] 谁能一起跑，不按「只读都能跑」粗判——按具体输入判：列目录能，删除不能。
- [p4-05] 还有改了状态也能并发的：比如建任务，每次写不同的文件。
- [p4-06] 一串调用按连续批分区：批内并发，批间保序。

> 画面：「∞」特写卡——读文件工具的结果上限无穷大；旁边小动画：禁止标志掐断「落盘文件再读再落盘」的循环

- [p4-07] 结果太长就存成文件，模型看预览加路径。
- [p4-08] 唯独读文件，上限无穷大——不然读的结果存成新文件，新文件又被再读、再存，无限循环。
- [p4-09] 例外，也有例外的道理。

> 角标：Zod / validateInput · PreToolUse · canUseTool · partitionToolCalls · maxResultSizeChars
