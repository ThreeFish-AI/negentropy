## P0 让会写专著的人去盖章：小判断的错配（200 §1）

- 【二】Agent 里塞满「小判断」：这条工单归谁、这个动作要不要放行、这次输出及格没、这个候选选哪个（N:24）。
- 【三】今天交给 LLM 的代价：**慢**（3–329 秒，对照 llm-benchmarks.diegoromero.es）、**贵**（$0.20–10/MTok 输入）（N:24，厂商博客口径）。
- 【二】**类型不稳**：生成的是字符串，要解析，会越界、截断、概率和不为 1（N:24，官方文档承认的解析负担）。
- 【二】**口头概率不可信**：RLHF 为「辅助人」优化，偏好对齐压扁了诚实的不确定性（N:24，官方 primer 自述）。
- 【二】错配点破：判断的答案空间本来就是封闭可枚举的，却用开放字符串逐 token 表达（N:26）。
- 【二】Jev 的设计规格四条（N:28-33）：答案空间先定（M1）/ 输入只读一次、多问并行（M2）/ 概率能当错误率读（M3）/ 按把握分流（M4）。
- 【二】一句话定位（N:11，本集标题「让判断变便宜」的出处语义）：Jev 把「让 LLM 写一段文字、再由程序去解析」的小判断，改成「程序先把答案空间写死，模型一次前向给每个选项打出带概率的分数」——交付的不是更聪明，而是**让判断变成软件可直接消费、便宜到可以随处调用的函数调用**；代价是放弃生成，且校准只在分布内成立。
- 【二】接口契约（N:35，api.md）：`POST /v1/systemone`；请求 = `state` + 命名问题集（key 不发给模型）；三种题型 noul（是非，返回 0–1，无 confidence）/ choice（≤255 选项，返回选项 + 全概率 + confidence）/ score（≥2 级、API 接受 ≤10 级，返回概率加权期望值——可落在级间——+ 概率 + confidence）；同一请求内问题互不可见；上下文 64k/请求、32k = state + 最长单问；输入仅文本；价格 $42/十亿输入 token、输出免费；官方自认英文为主、CJK 较弱。
  - A 轨行号锚点：api.md:14 端点；:23/:31/:36 state+questions 与 key 不发模型；:75/:230 noul 形态（confidence 由 :223 的 "also" 反证仅 Choice/Score 携带）；:125 choice ≤255（返回 :251-265）；:163 score ≥2 级、API ≤10 级、级间值（返回 :288-306）；:332 422 校验；:16/:21 仅文本。models.md:13/:18 $42/B 输入、输出免费；:15/:20 64k/32k、state 只摄入一次、并行评估；:52 CJK 自认。⚠️「问题互不可见」的官方原文措辞不在 api.md——官方侧最接近的是 models.md:20（并行评估）+ jaggedness.md:26（跨问题结构不变量失败，反证隔离）；复刻侧直说在 kev README:20「Questions share the input text but can't read each other」；隔离的硬证据是 Hume 探针（见 P2）。
- 【二】命名来历（launch-blog 正文）：System One 取自 Kahneman 的快慢系统意象，Jev 取自 Jevons（杰文斯）——判断变便宜之后用量反增的经济学名字（N:168 杰文斯效应；blog 归属）。
- 【一】**官方 adapter 证明「让 LLM 陪跑同一接口」的代价**（N:209 争议 2 / _client.py）：LLM 基线须一次口述所有问题的完整概率分布（verbalized probabilities，非 logprobs），schema 校验失败要带错误信息纠正重试、概率和≠1 要重缩放——更慢更贵。
  - A 轨行号锚点：_client.py:70-77（概率系统提示：每题口述全标签概率、保留真实不确定性、和为 1；全文 grep logprob 零命中——无 logprobs 通道）+ :349/:365（模式参数）；:434/:442-445（全部问题合成单个输出 schema、单次对话；run_sync :247-261 每轮仅一次 provider.request）；:222-231（ValidationError → 带错误信息纠正重试，提示词 :112）；:47-53/:131-158（概率归一与重缩放接线；1e-6 容差在同仓 _utils/probability_normalization.py:9，同 commit 核验拉取）。
- ANALOGY 主剧场（N:13，全片统一）：**一座快递分拣中心**。调度员（System 2 LLM）会规划线路、会写说明，但慢且贵；老分拣员（Jev）扫一眼面单（state 只编码一次），同时填好几张分拣小票（noul 是非 / choice 选格口 / score 打等级），只能往已挂牌的格口里投（闭合输出空间），心里的把握分配就是概率、把握集中度读数就是 confidence；分拣中心定期对账（校准），爱说「十拿九稳」就给他统一打折（温度缩放）；三条去向按把握分流——直投格口（执行）、送调度员复核（升级 System 2）、滑向人工异常台（转人工）；传送带与推杆（代码）照单执行。
- ANALOGY 失配自检（纪律 1）：老分拣员是「看得懂手写地址与备注的熟练工」，不是扫码机——真实分拣靠条码查表，Jev 靠前沿预训练的语义理解（N:79）。

## P1 闭合输出空间：合法 ≠ 正确（200 §3）

- 【二】机制：Choice 的 `criteria` 就是全部可能答案，模型输出对每个选项的概率打分，「给出选项之外的答案」在类型层面无法表达（N:85）。
- 【二】推论①：「零幻觉 / 零类型错误」是**构造保证**而非实测——官方自己声明 0% 不是经验数字（N:85）。
- 【二】推论②：它消灭**形式类错误**（越界标签、截断、不可解析、概率和不为 1），保留**语义类错误**（合法格口里指错）（N:85）。
- 【三】官方 evals 准确率 67.8%（9 模型第 4）——约三分之一的案例是在合法选项里选错（N:85，自报口径）。
- 【四】HN 批评与回应：批评者指出「合法但错误的值」仍然可能（jacobgold、StevenWaterman），Almeida 以「随机森林也不会『幻觉』」回应让步（N:85）。
- 【四】选项间互相影响：加入无关选项使两个既有选项的对数几率移动 −0.28（95% CI −0.36 到 −0.19，Hume 探针）；选项乱序导致 13% 答案翻转（nibzard 实测）——「读出」并非对每个选项独立打分（N:85）。
  - A 轨：hume-reverse 正文（对数几率/顺序反转探针）；归属句必须。
- 【四】255 上限的裂缝：官方文档写校验错误返回 422；nibzard 实测 256 个选项收到的是 `400 Too many choices`（N:87）。口播不展开（细节留给画面角标）。
- 【二】255 之外走两阶段：先独立打分再显式选择，偶尔变慢（launch-blog 正文，N:26 局限转述）。
- 【一】原型实景（LAB 复跑 2026-09-24，逐字一致）：
  - S1 契约校验：256 选项 → 422；11 级 → 422；空问题 → 422。
  - S4 闭合输出空间：正常单 → 'billing' conf=0.86 合法 ✔；陷阱单（"This is not about refunds…"，字面误读）→ 'billing' conf=1.00 **合法 ✘ 应为 technical**；边缘单 → conf=0.93 合法 ✔。
  - 陷阱单正是官方 jaggedness 第 1 类「字面理解」的复刻（N:112）。
- 【一】B2 破坏性实验（拆掉闭合输出空间，换「生成文本 + 宽松解析」）：标签漂移（'billing'→'Billing team'）立即越界，5 单 3 单输出越界（N:101-109）。
- 【一】B2 教训（金句候选）：**类型安全不是属性，是选择**（N:112、N:276）。
- 【二】jaggedness 自曝节选（J 轨）：九类失败模式含字面理解、数学与数字（计数/hex/RGB）、日期比较、间接引用、大量无关 state（context rot）、对抗注入、指令与 criteria 矛盾、**跨问题无结构不变量**、生成（N:248 表；jaggedness.md:17-27（九行失败模式表：19 字面理解 / 20 数学数字 / 21 日期比较 / 22 间接引用 / 23 大量无关 state / 24 对抗注入 / 25 指令矛盾 / 26 跨问题无不变量 / 27 生成；页面自述 :7「Jev isn't perfect」，最后审阅 :10 = 2026-09-17））。
- ANALOGY：只能往已挂牌的格口里投——绝不会投进不存在的格口，但可能投错格口。一面墙最多 255 个格口；再多就先分大区、再分小区（两阶段）（N:83）。

## P2 一次编码、分支隔离、选项读出（200 §4）

> ⚠️ 本节全部机制形状证据是【四】逆向 + 【一】开源复刻（kev/laya 代码），Jev 本体未公开（N:75、N:118、N:285）。口播表述模板：「有研究者用上万次探针做过逆向，两个开源复刻也实现了同一接口——最可信的假设是……」

- 【四】机制假设（Hume 探针 + kev 代码，N:118）：state 只编码一次（前缀 KV 缓存，参照 Hydragen / DeFT 的共享前缀注意力）；每个问题是一条独立分支，注意力掩码保证它只读 state 与本题；选项隐状态对决策位打分（pointer 式读出）。
  - A 轨行号锚点：kev/model.py:75/:88-95（<state>/<q>/<opt>/</opt>/<decide> 打包）；:124/:141-144（掩码：attend(i,j) iff j≤i 且 (seg[j]==0 或 seg[j]==seg[i])——state 段人人可读、同段=本问题）；:77/:98/:104（每问 position 在 state 之后重启）；:174-187/:273/:338（PointerHead：h_decide 与各 </opt> 隐状态点积 → logits → softmax）。
- 【一】laya 证明同一接口可以由完全不同的骨架承载：双向编码器 + 选项位 MLP 打分（N:118；laya-common.py + dev.to 架构文）。
- 【四】三条实测证据链（Hume，N:118）：
  1. **延迟对问题数近平坦**：1 问 86.5ms → 1,500 问 610ms，约 100 问内基本不变；对 state 长度线性（360 token 57.5ms → 29,835 token 218ms）。
  2. **`output_tokens` 是计费口径**（4 + 每个是非 15 + 问题 ID 长度），延迟并不随它增长——200 选项（1,911 output tokens）与 2 选项一样快。
  3. **隔离探针**：暗号放进兄弟问题，本问题判「state 里有暗号」的概率 0.00；放进 state，0.90–0.92。
- 【二】官方自曝的反面代价——**跨问题无不变量**（N:120，jaggedness.md:121/:125（Noul 0.22 vs Choice yes 0.01 表）与 :129/:133（0.72 + 0.47 = 1.19 表））：同一退款问题，Noul 问得 0.22，yes/no Choice 问得 yes=0.01；「退款」「不退款」两个 Noul 分问，概率 0.72 + 0.47 = 1.19。
- 【二】编排解（N:120）：互斥判断合并为单个 Choice（只挂合法组合的选项），或由代码做事后校验——而不是指望模型自觉。
- 【一】原型实景（LAB 复跑）：
  - S5 分支隔离探针：暗号在兄弟问题 → P=0.047；暗号在 state → P=0.924。
  - S6 共享前缀：13 问 × 2000 token state，一次调用 2078 token（state 编码 1 次）；逐问分调 26078 token → **12.5×**。
  - B1 拆分支隔离：暗号泄漏 0.047 → 0.924。
  - B5 拆共享前缀缓存：token 比 12.5× → 1.0×（多问合调的全部红利来自「读一次」）。
  - B6 互斥决策拆两个 Noul：概率和 1.85，「退款」与「拒退」**同时过线执行**——不是模型犯错，是编排把「互斥」丢给了两次独立判断（N:141）。
- 【三】官方 cookbook 自报：13 问合并 12.2× 便宜、10.0× 快（N:129，自报口径，与原型 12.5× 同构）。
- ANALOGY：扫一眼面单，几张小票共用这一眼；小票互不相看；作答时手指在挂出的格口里比较着点一个（N:116）。**失配提醒（纪律 1-①）**：人是跨小票统一思考的，Jev 的隔离是硬约束。

## P3 校准概率：能当错误率读，但只在分布内（200 §5）

- 【二】RLCD（Reinforcement Learning for Calibrated Decisions）：官方定义为与 RLHF（人类偏好）、RLVR（可验证奖励）并列的第三条训练路线，目标是「认知上诚实的概率」——0.8 就是约 80% 正确（N:147，官方 primer）。
- 【二】RLCD 配方未公开（N:147、N:284）。
- 【一】两个开源复刻给出两条可行路径（N:147）：
  - kev 用**交叉熵**（log score 本身就是严格适当评分规则，直接梯度下降即可，无需 RL）+ 每个 checkpoint 一个后验温度（约 2.1–2.4）。
  - laya 用 GRPO 式策略梯度，奖励 = log score + 0.5×spherical score − 1.0×ranked probability score。
  - A 轨行号锚点：kev README:232（「Training uses cross-entropy on the correct answer」+「No Jev outputs were used for training」；⚠️「适当评分规则而非 RL」是 200 笔记的意译转述，README 无此原词）；:153（每 checkpoint 一个后验温度约 2.1–2.4，加载时由 pointer head 施加）；laya/common.py:201-227（proper_reward：docstring :210「Strictly proper scoring rule reward」；:217 log score + :218 ×0.5 spherical + :226 −1.0×ranked probability score；权重 :206-207）；「GRPO 式策略梯度」的框架表述出自作者架构文（dev.to 2026-09-18，组采样/优势归一化代码不在已钉文件内，按【四】作者口径对待）。
- 【一】**confidence 不是模型学得的**——官方 adapter 代码逐式给出（N:147，confidence_metrics.py:23-24（Choice：(p_max − 1/K)/(1 − 1/K) 的逐式实现）与 :11-14（Score：1 − 离众数期望距离 / 均匀分布平均绝对偏差，下限 0））：Choice 用 `(p_max − 1/K)/(1 − 1/K)`，Score 用 `1 − 离众数期望距离 / 均匀分布平均绝对偏差`；文档示例（choice 0.88/0.12/0 → 0.81、score [0,0.95,0.05] → 0.92、score 值 1.05）均可由公式复算到舍入带内（LAB S2 复算：0.820/0.925/1.05）。**它只是概率分布的另一种读数，不是新信息**（N:147）。
- 【四】校准的领地——分布内与分布外是两个世界（N:149）：
  - 公开基准上 ECE 0.024–0.032（scienthoon；Hume 的 MMLU 1,200 题 10-bin ECE 0.0313）。
  - 合成工单（分布外）0.107，为噪声底的 4.4×（scienthoon）。
  - nibzard「强制不确定题」上 ECE 0.246 为实测最差（LLM 0.039–0.122）；Jev 仅 49.7% 承认「不知道」，LLM 是 97.3–100%。
  - 不可知题上仍有 9% 以 ≥0.9 置信作答（kev README:368）。
  - DAIR Emotion 上 16% 的样本给真标签零概率（AbdelStark）。
- 【二】温度缩放能修整体的过度自信，修不了排序（准确率不动），更修不了分布漂移——Ovadia et al. 的经典结论在决策模型上复现（N:149）。
- 【一】原型实景（LAB 复跑，替身设定：声明概率锋利度 2.4，真实区分力 1.0，OOD 降到 0.45，不可知题 1/3）：
  - S8：拟合 T=2.40；raw ECE 0.141 → cal 0.013，**acc 0.77 一字不变**。
  - S9：OOD 沿用分布内 T：直投 19.5%、实际错 23.1%、自称 3.4%；OOD 自有切片重拟 T=5.45 后直投归零；不可知题 ECE 0.433、实际错 66.1%。
  - B3 拆温度校准：ECE 0.013→0.141；直投 19.7%→68%；自称错 0.7% 实际 12%；gate 成本 10.8→4.6 但 acc 0.972→0.91。
- 【一】金句候选（N:164、N:186）：未校准时「68% 的决策被直投，自称只错 0.7%，实际错 12%——**账面好看，车间失火**」；「**校准拆掉的是你看得见的成本，烧掉的是你看不见的质量**」；诚实重校准的结局是「学会闭嘴」——直投归零，全部升级。
- 【四】kev README 自陈局限佐证：单一温度不能重排置信、选项顺序可改变答案、知识差距由底座决定（README:376-379）。
- ANALOGY：老分拣员心里对每个格口各有几成把握，把握的集中度就是 confidence 读数；分拣中心定期**对账**——自称九成把握的件是否真有九成投对；查账发现他爱说「十拿九稳」，就给他的口头把握统一打折（温度缩放）（N:145）。**失配提醒（纪律 1-③）**：对账只对应温度缩放，RLCD 是训练期奖惩。

## P4 快慢分工：收益在编排，不在模型（200 §6）

- 【二】三条去向（N:168）：把握高直投格口（执行）、不足送调度员复核（System 2）、再低滑向人工异常台；调度员负责规划线路、开当日格口、写异常备注（生成），老分拣员只在格口里挑（判断）。
- 【三】官方 evals 的 workflow 模式（N:170，自报）：每个决策拆成**代码规则 + 窄问题**（close/escalate/contain 等），参考答案由 GPT-6 Astra 与 Fable 5.1 平均给出。
- 【三】结果（N:170）：Jev 准确率 67.8%（9 模型第 4），但 $0.0004/例、0.4s/例，成本与时间是两个数量级的优势；「让 LLM 在思维链里做全部逻辑」（prompt 模式）普遍更差——haiku 4.5 从 53.6% 跌到 18.1%。
- 【四】社区案例（N:170）：Minecraft 速通——Astra 做高层规划（约 15 秒一次）、Jev 从程序生成的候选动作里挑、执行代码负责寻路放置，一次成功运行 **131 次 Jev 决策 + 35 次 LLM 调用**；浏览器 Agent「读页面 → 生成候选 → Jev 选 → 执行」约 7 秒完成航班查询。
- 【四】Jev-as-a-Judge（N:170，LangChain；注意样本极小、单一评审人、与厂商联合营销——口播必须带全部三个限定）：5 个固定输出 × 100 次重复对照一名人工评审，Jev 一致率 100%（500/500）、评分方差比 LLM 评委低 92–913×、$0.00035/次。
- 【一】原型实景（LAB 复跑，S10/B3；单价取 evals 自报口径：Jev $0.0004/0.4s、terra $0.0304/10.1s；System 2 替身准确率 0.97；人工档视作全对、成本不计）：
  - S10 阈值三档（≥0.95 执行 / 0.6–0.95 升级 LLM / <0.6 转人工）：act 118 / llm 346 / human 136，acc 0.972，cost 10.758 vs 全 LLM 18.24。
  - **省多少取决于「有把握的大多数」有多大，而不是模型单价**——替身数据里只有 19.7% 的决策够自信直投（N:186）。
- 【二】杰文斯效应（N:168）：Jevons 1865《煤炭问题》——煤的利用效率提高，煤耗总量反增；分拣越便宜，拿来分拣的东西越多，连内部传阅件都要「过一遍分拣」，判断密度上升。
- ANALOGY：传送带与推杆（代码）照单执行；三条去向按把握分流（N:13）。

## P5 冷思考：三个争议（200 §8）

- **争议 1「这不就是个分类器吗？」**（N:202-204）
  - 【四】通俗版：老分拣员 vs 专门为一个中心训练的扫码分拣机——机器在固定格口上又快又准，换一批格口就得重训；老分拣员看得懂任何面单，换块牌就能上岗。
  - 【四】证据：laya 微调后在 typed-decisions 上 0.766 > Jev 0.727（该 Jev 数来源不明，laya README 自注为第三方发布未实测；laya 基座零样本 0.36/0.34 近随机、多数类基线 0.461，Banking77 上 0.425 vs Jev 0.870）。
  - 【四】知识差来自底座：Kev MMLU-Pro 0.52 vs Jev 0.84——属资源问题，不属本质难题。
  - 【二】选址谱（推演自 200）：按「任务稳定度 × 调用量 × 标注成本」连续谱选址；取样不同，两派都对。
- **争议 2「自报基准的信度」**（N:206-210）
  - 【三】通俗版：分拣中心自家出考核卷、拿两位资深调度员答案的平均当标准答案，还让竞争对手按自家流程答题。
  - 【三】倍数口径疑云：首页 193.6× 快 / 444.6× 便宜，疑为各轴对不同基线取最大比值；首页自家 demo 数字复算仅约 **75×/171×**（typesafe.ai 首页 Demo 面板：$0.000081/0.114s vs $0.013880/8.566s）。
  - 【四】第三方：p50 236–276ms，仅比 Cerebras 上 gpt-oss-120b 快 1.2×（nibzard/AbdelStark）。
  - 【二】对冲而非消除：预注册第三方基准、CI 核验声明如 kev 的 claims.json；闭源前提下不可消除。
- **争议 3「校准能外推吗」**（N:212-216）
  - 【二】通俗版：本地线路上对账极准的老分拣员，面对外文面单，还该信他的「九成把握」吗？
  - 【四】台阶：0.03 → 0.107 → 0.246；且公开基准可能本就在训练分布里。
  - 【二】本质难题：新分布上没有标签就无法验证校准；只能对冲（自有数据重校准 + 分布外检测 + 保守阈值 + 升级路径），不可消除。
  - 【一】原型 B4：诚实重校准使直投归零——分布外要么嘴硬要么闭嘴，没有免费的中庸（N:216、N:278）。

## P6 判断与生成的分工：收尾（200 §1 定位 + §11 边界）

- 【二】不是替代 LLM：Jev 把小判断挪出生成通道，让「会写专著的人」回到专著上去（N:11 推演；官方 coding agents 页明言 Jev 不能替代 coding agent 里的 LLM）。
- 【二】批判性边界（N:282-289，口播收尾的开放问题原料）：
  1. 架构与 RLCD 零公开——「新模型架构 / 并行采样器 / RLCD」只有名字；逆向的 MoE 与 ~10B 规模猜测是最弱一环（自称「相当推测性」）。
  2. 「0% 幻觉」不是实测：是 schema 构造保证，且不等于答对（evals 67.8%）；第三方已给出反例数据（16% 真标签零概率）。
  3. 倍数口径未对齐；evals 无校准指标、参考标签由两个 LLM 平均、workflow 自家编写。
  4. **中文 / CJK 未证明**：官方自认 CJK 较弱；全部第三方证据都是英文任务。中文场景的校准、准确率均无数据。
  5. 「并行采样」的机制证据是间接的（黑盒探针，非实现披露）。
- 【二】理性收尾（开放问题，不贩卖焦虑）：判断的边界不在模型，在你的分布——「当你把判断变便宜，你会拿它去量什么？」（由 N:77 焦点排序②「校准的边界是自动化执行的生死线」与杰文斯效应合成；表述为开放问题而非结论）。
