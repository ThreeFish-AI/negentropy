# 知识库平台方案 × Negentropy 知识库子系统：差距分析与补充诊断

> **定位**：以已审批的《[知识库平台技术方案](./knowledge-base-platform.md)》（下称「方案」）为标尺，对 Negentropy 知识库子系统（as-built）做逐机制取证与差距判定；**实施载体为独立新建平台**，Negentropy 定位为参考实现与经验库（可移植代码件 + 工程教训）。结论直接驱动《[M1–M3 工程实施计划](./knowledge-base-platform-implementation.md)》。完整机器可审计证据（82 判定 + 复核记录）随本文档入库：[`knowledge-base-platform-gap-evidence.json`](./knowledge-base-platform-gap-evidence.json)。

## 1. 方法与口径

- **as-of 2026-11-02**，代码为准（035 设计文档与代码的漂移单列 §9，不作为判定依据）。
- 五域并行取证（文档管理 / 索引构建 / 检索服务 / 权限管控 / 应用集成与闭环），每条判定带仓库相对路径:行号证据；判 missing 前须 Grep 并在证据中注明检索词；随后逐域独立对抗复核（打开证据实看，专防「已实现误判 missing」与「有类无链路」两类错），复核另补 16 条取证遗漏事实（已并入正文）。
- 判定档位：**implemented**（链路接通）/ **partial**（部分具备）/ **divergent**（已实现但与方案取向不同）/ **missing**（未具备）。工作量口径（独立新建平台视角，含设计/编码/测试）：S <1 人日，M 1–3 人日，L 1–2 人周，XL >2 人周。
- 证据路径缩写：`NE/` = `apps/negentropy/src/negentropy/`。

**五条主结论**（差距的结构）：

1. **权限平面整体缺位是第一结构性差距**。knowledge 全部 HTTP 路由未挂鉴权依赖（auth 全局默认 OPTIONAL 即 fail-open；唯一例外是 `/mcp/knowledge` 子应用自带 bearer 强校验）；035 §11 声称的 RBAC 与 `knowledge_manager` 角色在代码中不存在；产品域/ACL 谓词、匿名/客户身份面全缺；visibility 三级取交集在读路径**零执行**（§9-D4）。方案 §5 安全面在 Negentropy 近乎从零开始——这是独立新建平台最有力的依据。
2. **版本化缺失是第二结构性差距**。无 DocumentVersion（`markdown_content` 原地覆写）；本地 chunk 编辑会被下次同步的整源原子替换**静默删除**；CorpusVersion 快照写入路径本身损坏（引用不存在的列与属性，实跑必崩，live 库 0 行），「版本历史」端点成了读空表的空转路由。「版本库 SSOT」须按方案 §1/§2.2 从头建。
3. **检索面「有引擎件、无执行管线」**。RRF/hybrid 的 DB 原生函数从未进迁移且 SQL 绑定缺陷致恒回退 Python（hybrid 分支连降级日志都没有）；`knowledge.embedding` 无任何 HNSW 索引（HNSW 仅建在 KG 实体表）；中文关键词腿因 tsvector english 配置全失效（I-196，被向量腿成功掩盖、测试恒绿）；重排默认 Noop 且不传参时隐式截断 top_k=10；统一检索服务引用不存在的 ORM 属性、一调即 500。执行计划层须按方案 §3.3 重建。
4. **同步与闭环完全缺失**。无 webhook / 定时增量 / 全量重扫（唯一批量面是换 embedding 时的逐源 enqueue，且只认 blob 源、url 源必败）；无 KnowledgeTask；反馈链路三处断裂（路由不 commit、NOT NULL 违约、非法列 kwarg 恒 500）——「表在、链路死」。删除语义双入口分叉（物理删 vs 软删不级联 chunk），软删文档的 chunks 仍可被召回；live 库存在同文档 gs://与 pgblob:// 双份摄取残留（幂等锚为可变 URI 所致）。
5. **反向经验密度高**。44 条实证经验（24 条 high），从原子换版、确定性 chunk_id、原生路径随迁移交付，到权限参数必填、逐腿回归、PDF 保真巡检、A/B 护栏——是独立平台最直接的「免费学费」；高价值项已回写方案正文（见 §8 沉淀去向列），其余进实施计划的工程铁律清单。
