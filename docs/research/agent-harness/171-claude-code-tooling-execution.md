# ① 工具与执行：一个循环，和挂在它外面的东西

> [!NOTE] **定位与钉点**
> 五层依赖链的地基（[总纲 §1](./170-claude-code-harness-overview.md)）。本章只讲一件事：让模型能在你机器上动手的那个循环长什么样，以及为什么 agent 工程反复给出的答案不是「更聪明的循环」，而是**循环外面挂着的三层可拆卸装置**。
> 机制层以课程仓库 main 轨 @ `0dcafa2a`（2026-08-27，取数 2026-09-28）为基；站点轨（`67a9126`，2026-07 冻结快照）的差异以「轨道差异注记」内联。类比角色沿[总纲 §2](./170-claude-code-harness-overview.md) 台账，全章单射。证据分级：【一】main 轨钉点实测／【二】站点轨正文／【三】课程作者对闭源源码的分析（文面载体＝站点轨各章「深入 CC 源码」节，main 轨已无此节，一律带归属句）／【官】Anthropic 官方文档（`code.claude.com`，访问 2026-09-28，页面清单见[参考](#参考)）。章→集归属与钉选只登记在[系列信源地图](../../../apps/negentropy-influence/source-map/claude-code-explained.md)；main 轨 s03_permission/s04_hooks 与旧 12 课轨撞号，涉两轨同号一律「轨道＋章全称」。

**一句话本质**：它敢在你机器上动手，靠的不是更聪明，是传送带外面挂着的三层可拆卸装置。

---

## 1. 这一层要解决什么问题

模型能推理代码，但碰不到机器：不能读文件、跑测试、看报错。没有 harness 时，每次工具调用都要人把结果手动粘回去——**人自己就是那个循环**。一个 `while True` 就能把人换下来：把模型响应里的工具调用拿出来执行，结果作为新消息追回去，再问一次模型。

但裸循环有两个致命伤。其一，**它什么都敢执行**——一条删库命令和一条列目录命令在它眼里没有区别。其二，如果每加一个约束都往循环体里写一行 `if`，循环很快就会膨胀成没人敢动的烂泥——而循环恰恰是唯一必须永远稳定的东西。

本层的答案是：循环保持极小，把所有可生长的东西**挂到外面**——能力挂进一张号码簿，检查挂成一排扫码口，闸门和扩展逻辑挂在传送带边的插线口上。后面四层的每一个机制，也都是照这个路子挂上来的。

| 缺口 | 机制 | 大白话 |
|:---|:---|:---|
| 模型碰不到机器 | 循环 + 续轮判据 | 一趟趟把活送到手边，干完看手里还有没有活 |
| 每加一个能力都要动核心 | 工具分发表 | 加工具改号码簿，不动传送带 |
| 检查该按什么顺序排 | 执行前校验链 | 便宜的、不可协商的排前面，人的时间放最后 |
| 什么都敢执行 | 权限三道门禁 | 硬拒绝不可协商，问不问人放在最后 |
| 扩展逻辑会把循环撑爆 | 钩子插线口 | 装置插在带边，锁芯不动 |

## 3. M1 · 传送带：循环与续轮判据

> [!TIP] **类比**
> 传送带只做一件事：把活送到师傅手边，接住他递回的东西。它每转一圈都做同一个**验活动作**——看他手里还有没有活。有，就继续转；没有，才考虑收工。注意它看的是**手里**，不是师傅嘴上说自己干没干完。

**不变式**：循环体只回答一个问题——**本轮响应的内容块里还有没有工具调用**。有就执行并把结果作为新消息追回去，没有就退出（main 轨 s04_hooks 起，退出前先过退出事件）。配套三条落账纪律【一】：assistant 回合先落账；只有实际存在工具调用才追加结果消息（不会追出空的结果消息）；每条结果带 `tool_use_id` 与调用一一配对。这个判据是本地可直接观察的**结构事实**；而停止标记是模型/传输层给出的**声明**。二者在流式输出下可能不同步：内容块里已经排好了工具调用，标记却报了结束——信声明，活就丢了【三，课程作者拆过闭源源码后指出（载体＝站点轨 s01_agent_loop「深入 CC 源码」节）：产品不把停止标记当续轮的唯一依据，而是另设一个独立标志位，流式过程中一旦收到工具调用块就置真，源码注释自述理由正是「声明会滞后于事实」】。

> [!WARNING] **轨道差异注记**
> 判据在课程两个现行修订上正好相反——这是「站点与仓库有时间差」的最小样本（拓扑见[信源地图](../../../apps/negentropy-influence/source-map/claude-code-explained.md) §一）：
>
> | 轨道 | 退出判据 | 读法 | 证据级 |
> |:---|:---|:---|:---|
> | 站点轨 s01_agent_loop（`67a9126`） | 停止标记不是工具调用，即返回 | 信声明 | 【二】 |
> | main 轨 s01_agent_loop（`0dcafa2a`） | 从内容块过滤工具调用，空才退出（s04 起先问退出事件） | 看事实 | 【一】 |
>
> 且 main 轨固定提交四章全文没有一处流式调用、也没有一处停止标记判据——判据的选择是**代码里的事实**，不是注释里的口号【一】。官方文档对此不披露实现层（六页全文只有 "repeat until done" 等产品级表述），**无法裁决这场判据之争，也不能为上述【三】主张背书**【官，how-claude-code-works · glossary】。

第二条续轮通道是 main 轨 s04_hooks 加上的：`if not tool_calls:` 之后并非直接返回，而是先触发一次退出事件；若某个回调返回非空，就把它作为用户消息追加并继续循环【一】。也就是说——**「手里没活」的收工可以被传送带边的插线口否决**，退出不是循环一个人说了算的（产品侧的量化保险丝见 M5：8 次连续续轮上限）。

官方文档给了这条实现级骨架一个产品级对照层，**互补不矛盾**【官，how-claude-code-works · glossary】：产品叙述循环为三阶段——"gather context, take action, and verify results… repeat until done"；并明说「可以随时打断循环」与「**多数扩展点（hooks、skills、MCP）插在循环的特定阶段**」——后者与本章「可生长的东西挂在循环外」同构互证。用户侧另补两条打断语义：`Esc` 立即停止并**取消正在运行的工具调用**；排队消息在工具调用结束后**同轮内**被读取、下一步前调整【官，how-claude-code-works § Interrupt and steer】。

> [!IMPORTANT] **实景**
> `main 轨 s01_agent_loop/code.py @ 0dcafa2a`
>
> ```python
> messages.append({"role": "assistant", "content": response.content})
> tool_calls = [block for block in response.content if block.type == "tool_use"]
> if not tool_calls:
>     return                      # 验活动作：手里没活，收工
> ```
>
> 配套原型（[`assets/cc_harness_lab.py`](./assets/cc_harness_lab.py)）把判据拆回「信停止标记」的破坏性实验（本文换钉后重跑，实际运行输出）：
>
> ```text
> == D1 · 循环判据退回「信 stop_reason」 ==
>   改动：Switches.trust_stop_reason = True
>   退化：ran_late_tool  True  →  False
> ```
>
> 内容块里明明还有一件排好的活，循环提前收工——判据错，活就丢。

**口播落点**：停止标记是声明，内容块是事实；信声明就会丢活。

## 4. M2 · 转接号码簿：工具分发表与一托盘

> [!TIP] **类比**
> 师傅会用的机器越来越多，但传送带不需要认识任何一台——它只按**转接号码簿**查号：活上写着名字，簿上名字对着处理函数，查到就转过去。一批活算**一托盘**，教学版的托盘是一件一件上的。

**不变式**：工具能力的增长发生在**表**里，不发生在**循环**里。main 轨 s01_agent_loop 的执行行是硬编码的 `run_bash(...)`；s02_tool_use 起改成「按名字查表、以实参展开调用」，此后课程再未变过【一】。把「调哪个」从循环体里拿走，循环才可能在后续十几章里保持逐字不变——否则每加一个机制都要动核心。

**「只改两处」其实是三处耦合**【一】。课程正文说加一个工具＝在 schema 数组加一条、在处理函数字典加一行。但调用方式是按关键字展开（`handler(**block.input)`），于是 **schema 的属性名必须与处理函数的形参名逐字一致**——名字对不上，运行时直接炸。注册表只有两条显式条目，却隐含第三个契约：签名对齐。这条课程正文没写，是这一层最容易被「两行搞定」话术盖住的坑。查不到名字时回退为一句「未知工具」字符串而不是抛异常，循环因此对坏名字免疫【一】。

**托盘的真实分布，按三层写**：

1. **教学版没有批次并行**——多个工具调用严格按模型给出的原始顺序逐个执行，该章自己的说明也明写逐个执行；并发原语排查（`import threading/asyncio/concurrent`、`ThreadPool`、`gather`、`async def`）作用于 main 轨 s01–s04 全部代码，**零命中**【一】。
2. 但**仓库的章节索引表把「并发」列为本章关键概念**，与代码和该章自身说明直接矛盾【一】——索引承诺了代码没有的东西。
3. 产品侧则是另一回事【官，hooks § PostToolBatch】：官方确认产品存在**并行工具调用**与**「批」层**（`PostToolUse` 在并行调用时并发触发；`PostToolBatch` 等整批汇合后才发下一次模型请求）。至于批间次序与并行判定的调度细节，官方不披露，只能【三，课程作者拆过闭源源码后指出（载体＝站点轨 s02_tool_use「深入 CC 源码」节）：工具调用被切成**连续的批次**，批内并行且有并发上限、批间严格有序；能否并行由**本次调用的实参**判定，而非工具的读写属性——同一个 shell 工具，列目录可并行、删除不可并行，而某些会写状态的工具反而可并行，因为每次写的是不同文件】。

官方另给产品工具面一个规模对照【官，how-claude-code-works § Tools】：内置工具五类（文件操作／检索／执行／Web／代码智能）外加 subagent、向用户提问等编排工具——教学版个位数工具 vs 产品全集，「加工具改表、不动循环」的结构主张在产品规模下依然成立。

**演进注记**（相对旧钉 `f9e8b280`）：本章仅机械级变化（有界递归 glob：`**` 递归＋条数上限＋收窄提示；fork-ledger 归机械级，上限数值见对应集 notes），无机制级变更。

> [!IMPORTANT] **实景**
> `main 轨 s02_tool_use/code.py @ 0dcafa2a`
>
> ```python
> handler = TOOL_HANDLERS.get(block.name)
> output = handler(**block.input) if handler else f"Unknown: {block.name}"
>
> # 第三处契约就藏在这一行展开里——schema 属性名 ↔ 处理函数形参名：
> #   read_file 的 schema 属性是 path / limit，函数签名就必须是 run_read(path, limit=None)
> ```

**口播落点**：加一个工具，改的是号码簿，不是传送带。

## 5. M3 · 上件前的多道扫码：执行前的校验链

> [!TIP] **类比**
> 活件上机器前要过一排扫码口：先看外形对不对（结构合法），再看这台机器认不认它（语义合法），再看今天允不允许上机（许可），全过了才通电。越便宜、越不可协商的检查排越前面。

**顺序不变式**：**结构校验 → 工具自校验 → 前置钩子 → 权限判定 → 真正执行**——外形合法先于语义合法，语义合法先于是否许可，许可先于动手。注意**稳定的是顺序，不是段数**：站点轨两个深潜节对这条链分别给出五段与六段口径（六段版把输入回填与钩子-管线裁决各自单列）【三】，本文只写顺序不数段。排法的因果很直白：结构检查是纯本地计算、几乎免费；语义检查可能要读文件；而「要不要问人」是唯一要付出**人类时间**的一步，必须放到最后——且问完人之前，前面的检查已经把明显非法的都挡掉了，人不至于被垃圾问题轰炸。这条链上「前置钩子先于权限判定」的顺序已获官方确认："PreToolUse hooks run before the permission prompt"（钩子在工具参数生成之后、调用处理之前运行）【官，permissions § Extend permissions with hooks】；官方另分出一个 `PermissionRequest` 事件，仅当真的要弹权限提示时才触发——位置口径与互补面都齐了。

教学版只实现了这条链的**后两段**【一】，前半段不是不存在，是被外部件代工了：

| 链段 | 教学版由谁负责 |
|:---|:---|
| 结构校验 | SDK 侧承担（未自建校验层） |
| 工具自校验 | 无 |
| 前置钩子 | main 轨 s04_hooks 起：一次前置事件触发 |
| 权限判定 | main 轨 s03_permission 为循环里一行调用；s04 起为前置回调第一项 |
| 真正执行 | 号码簿查表分发 |

前半段之所以能省，是因为教学版工具个位数、SDK 替它扛了外形检查；规模一大，被代工的段迟早要自己接回来。

这条链上还有一个「保护机制反成递归发生器」的反直觉样本【三，课程作者拆过闭源源码后指出（载体＝站点轨 s02_tool_use「深入 CC 源码」节）：产品给工具结果配了「过大就溢写到磁盘」的上限，唯独**读文件工具把它设为无限**——否则会出现「读到大文件 → 结果被溢写成一个路径 → 模型再去读那个路径 → 再次溢写」的自噬死循环】。上限本是保护，落到读文件上恰好变成递归发生器。

> [!IMPORTANT] **实景**
> `main 轨 s03_permission/code.py @ 0dcafa2a`
>
> ```python
> # s03：循环里插入的一次权限调用（校验链的许可段）
> if not check_permission(block):
>     results.append({...}); continue
> # s04（main 轨 s04_hooks/code.py @ 0dcafa2a）：换成一次前置事件触发，循环不再点名任何检查函数
> blocked = trigger_hooks("PreToolUse", block)
> ```

**口播落点**：越便宜的检查排越前面，人的时间放在最后。

## 6. M4 · 门口三道门禁：权限

> [!TIP] **类比**
> 门口三道门禁按固定次序开：第一道是焊死的铁门（硬拒绝），第二道是对讲机（问一下），第三道才是敞开的门。先碰到哪道就按哪道办——铁门永远排在可以对讲的那道前面。

**顺序不变式**：**硬拒绝 → 需询问 → 放行，先匹配到哪一档就按哪一档办**，规则写得多细都不改变先后。这条不必只信课程作者的源码分析——官方权限文档明写【官，permissions § Manage permissions】：规则按拒绝、询问、放行求值，**第一条命中即决定结果，规则的具体程度不改变次序**；一条宽的拒绝规则会盖住更窄的放行规则，**放行无法在拒绝上开洞**。因果在于：拒绝是不可协商的，同意是可协商的；若把可协商的排前面，一句「同意」就能把整张拒绝表架空。配套原型实测印证：把人工审批挪到硬拒绝表之前，拒绝表上的命令被放行执行（见下实景 D4）。还有一条更上游的分工官方说得很死【官，permissions，Note】：**权限规则由 Claude Code 执行、不由模型执行**——提示词只影响模型**尝试**什么，改不了门禁**放行**什么。决定权与放行权，是两个人的活。

教学版的三条实测细节【一】，每条都值得单独记：

1. **硬拒绝表只对 shell 工具生效**：第一道闸门被「仅当工具是 bash」包住，文件类工具越界只会落到第二道闸门，变成「问一下」。同一道门禁，不是对所有活都开。
2. **引入权限管线的同时，撤掉了文件工具原有的硬边界**。上一版的文件工具全部经过一个把路径钉死在工作区内的辅助函数，越界直接报错；加了门禁的这一版起，文件工具不再调用它，越界改由规则去「问用户」（换钉复核：该辅助函数在上一版 grep 命中数行为正、本章起零命中，定性成立）。**装门禁那天，原来那堵墙被换成了一句问话**——这是「引入机制反而放松了约束」的最干净的样本。
3. **被拒也要补一条结果**：拒绝路径不是跳过了事，而是先补一条内容为「拒绝」的工具结果再继续。这就是执行层为记忆层留下的**配对义务**——每一个工具调用都必须有一条结果与之成对，否则历史不再合法（详见 [③ 记忆管理](./173-claude-code-memory-management.md) 的 D3 实验）。官方对产品同口径：拒绝理由作为消息回给模型、工作继续【官，permissions】。

**演进注记**（main 轨 0dcafa2a 相对旧钉 `f9e8b280`，本章唯一机制级演进）：`DESTRUCTIVE_COMMAND_WORD` 词位正则（PR #548）——只在「命令位」（行首或 `;`、`&`、`|`、`(`、`)`、换行之后）识别 `rm`/`del`，大小写不敏感，叠加在原有关键词子串检查之上；`model`、`delimiter` 这类子串与 `echo del` 这类参数位不再误报【一】。归入角色台账：**门禁的危险品名册按词辨认，不再只按字符串包含**。该正则传播到 13/17 个根级章（s03–s14 与 s17，即带 s03 权限层的章）【一】。

产品侧还有四条结构性差异，其中官方口径可加固的直接列官方：

| 产品侧（【三】，载体＝站点轨 s03_permission 深潜节） | 官方口径加固 |
|:---|:---|
| 表态多一种「不表态、交回通用管线」（passthrough） | —（官方未披露表态内部结构） |
| 规则来自多个配置来源合并、有固定优先级 | 官方明列设置五层优先级：**受管 ＞ 命令行 ＞ 本地 ＞ 项目 ＞ 用户**，受管连命令行也覆盖不了；同键列表跨文件**取并集**、任意层拒绝压过任意层放行【官，settings · permissions】 |
| 一个名字看起来像安全字段的标记，实际只是界面标签、不参与任何决策 | — |
| 有「先自动判、判不了再问人」的自动批准路径 | 官方即 auto 模式：由分类器模型代替人审、看不到工具结果原文；且 **auto 已是 v2.1.283+ 交互终端与 VS Code 会话的内置起步权限模式**【官，permission-modes】 |

正文以官方口径为准，课程的源码级说法降为佐证。官方还在规则之外给了三层产品面【官，permissions · permission-modes】：其一，**按工具类型分层的默认免批面**（工作目录内读免批、内建只读 Bash 白名单免批、预批文档域名免批——白名单不可配置，只能以 ask/deny 覆盖）；其二，**bare 工具名 deny 连工具定义都移出模型上下文**（模型「看不见」该工具，自然不会尝试）——教学版 deny 只拦执行，产品连菜单都撤了；其三，规则之上另有**六模式层**（default／acceptEdits／plan／auto／dontAsk／bypassPermissions，`Shift+Tab` 循环切换），规则在模式内求值。再加一道**信任门**：项目文件里授予权能力的规则（allow、额外目录）需先过 workspace trust 对话框才生效，而 deny/ask 规则「只收紧」、免信任【官，permissions § Project allow rules and workspace trust】。

> [!IMPORTANT] **实景**

## 7. M5 · 插线口：钩子

> [!TIP] **类比**
> 传送带边留了一排插线口，每种活的前后都能插装置。装置挂在带边，换不了传送带的锁芯。

**不变式**：**事件名 → 回调列表，返回值 None／非 None 是唯一控制流信道**。前置事件返回非空＝拦下这次工具调用；退出事件返回非空＝把循环拽回去再跑一轮；另两类事件（输入提交、执行后）的返回值在调用方被丢弃【一】。四个事件看似对称，**实际只有前置与退出握有刹车和油门**。因果很清楚：循环要保持稳定，权限、日志、副作用、收尾这些横切行为就必须有一个**不侵入循环**的挂载点；而挂载点一旦统一，**权限就不再是特权逻辑，只是众多插件中的第一个**——main 轨 s03_permission 里权限还是循环体中的一行硬编码调用，s04_hooks 之后它只是前置事件回调列表里的第一项，和日志回调平级【一】。这是本层最值得学的一笔结构决定，也是本层最大的争议（见本节末）。

但共用扩展点有代价。教学版四个事件、五个回调的注册格局与返回值去向如下【一】：

| 事件 | 教学版回调（注册序） | 返回非空的实际效果 |
|:---|:---|:---|
| 输入提交 | 打印工作目录 | 无——调用方丢弃返回值；文档却称其用途为「注入上下文」 |
| 前置 | 权限（第一）、日志（第二） | 拦下本次调用，并**就地短路**后续回调 |
| 执行后 | 大输出提醒 | 无效果——返回值被丢弃，却仍会静默吞掉同事件后续回调 |
| 退出 | 收尾统计 | 拽回循环续跑一轮 |

由此可实测的三处瑕疵【一】：

1. **短路会让审计漏记**：权限回调注册在日志回调之前，一旦拦截就地短路——**被拒绝的调用永远不会被日志回调记录**。注意这是**教学版结构特有**的推论：官方明写产品「全部匹配钩子并行执行」、多决策按 **拒绝 ＞ 延迟 ＞ 询问 ＞ 放行** 合并【官，hooks § PreToolUse decision control】——产品里不存在注册顺序遮蔽，不存在「被前面钩子吞掉」这回事。教训升格为通用原则：**审计回调不得被可短路回调吞掉**。
2. **执行后事件的返回值被调用方丢弃，触发函数却仍会在非空时短路**——一个执行后回调若返回非空，会静默吞掉它后面所有同事件回调，且没有任何其他效果。短路语义统一了，消费语义没统一。产品方向相反：PostToolUse 有真实决策语义——block 反馈把 reason 加在工具结果旁、`additionalContext` 注入、`updatedToolOutput` 改写模型所见；且官方带警告：**工具此刻已经跑完，写过的文件、执行过的命令、发过的请求都已生效，改写只改模型所见、不可撤销**【官，hooks § PostToolUse decision control】。教学版「丢弃」与产品「有语义且不可撤销」构成一组双向对照。
3. **输入提交事件的回调文档口径是「注入上下文」，实现却只打印一行、返回值也无人读**——文档承诺与实现能力不符，是又一处文档—实现不一致。

**安全不变量**（官方口径，比「钩子能拦」重要得多）【官，permissions § Extend permissions with hooks · hooks】：官方明写**钩子的决定不能绕过权限规则**——"Claude Code evaluates deny and ask rules regardless of what a PreToolUse hook returns"，钩子放行，拒绝规则照样拦、询问规则照样问；反向却成立——**一个以阻断方式退出的钩子（exit 2）在权限规则求值之前就把调用停住**，因此它压得过放行规则。合起来是一条干净的对称不变量：**插线口只能收紧，不能放松**。三态纪律同源【官，hooks】：exit 2 是阻断错误（连 JSON 的 allow 都盖不过它）；**沉默不等于批准**（无输出＝无意见、走正常权限流）；**超时不算拦截**（拖住的钩子当不了门）。官方还直接建议：要硬性放行或拒绝，用权限系统而不是钩子（`if` 过滤是 best-effort）。教学版与产品在这里方向相反【三，课程作者拆过闭源源码后指出（载体＝站点轨 s04_hooks 深潜节）：产品里钩子是喂进权限管线的输入、从属于拒绝/询问规则——「权限实现成一个钩子」只是教学版的权宜】。

产品侧的批层与退出保险丝【官，hooks】：`PostToolBatch` 是**批级事件**，整批恰好触发一次，返回 block 或 `continue: false` 可在**下一次模型调用前停掉整个循环**——循环外装置可终止循环的又一实例；`Stop` 事件的 `decision: "block"` 阻止收工，防死循环靠 **`stop_hook_active` 字段＋8 次连续续轮上限**（连续八次后官方直接覆盖下一次 block、结束回合）【官，hooks § Stop】——课程作者早前分析出的「退出钩子接管标志位」【三】被这组量化口径证实并细化。官方还给出第四个决策值 `defer`（供 `-p` 子进程场景暂停/恢复工具调用）与钩子处理器的五类形态（command／http／mcp_tool／prompt／agent）——教学版的进程内回调只是其一【官，hooks 首段】。

**争议：权限该不该只是第一个钩子**。教学统一派（本课程 s04 的结构美学）：一切横切行为等价挂同一扩展点，权限与日志平级，扩展点统一、循环去硬化；产品分层派（官方文档＋课程作者源码分析同口径）：权限规则**独立求值**，钩子决定不能绕过、钩子从属于权限管线。本质是**扩展点统一的美学 vs 安全边界的不可绕过性**——把安全语义交给「回调列表的注册顺序」等于把它放回可协商层。工程合成答案官方已经给出：统一用于观测与注入，硬性门禁独立成层；教学版不是错，是演示装置与产品架构的方向差。

> [!IMPORTANT] **实景**
> `main 轨 s04_hooks/code.py @ 0dcafa2a`
>
> ```python
> def trigger_hooks(event: str, *args):
>     for callback in HOOKS[event]:
>         result = callback(*args)
>         if result is not None:   # 第一个非空返回值 → 就地短路
>             return result
>     return None
>
> register_hook("PreToolUse", permission_hook)  # 先注册：拦截即短路
> register_hook("PreToolUse", log_hook)         # 后注册：被拦的调用永远到不了这里
> ```
>
> 配对义务的破坏性实验（[`assets/cc_harness_lab.py`](./assets/cc_harness_lab.py)，本文换钉后重跑，实际运行输出）：
>
> ```text
> == D3 · 关掉 tool_use/tool_result 配对保护 ==
>   改动：Switches.pair_protection = False
>   退化：pairs_intact  True  →  False
> ```

**口播落点**：挂在循环上，不写进循环里；插线口只能收紧，不能放松。

## 8. 教学版与生产版的距离

教学版砍掉了什么、为什么砍了仍然成立——每条都是结构性结论：

| 距离 | 为什么教学版能这么简化 |
|:---|:---|
| 续轮只有一条判据、一条退出路径 | 非流式调用下停止标记与内容块不会分叉；产品因流式而必须另设标志位并铺开多条退出/续跑分支【三，带归属：载体＝站点轨 s01_agent_loop 深潜节】 |
| 批次＝严格串行的 `for` 循环 | 单用户、单任务下「同时」不产生收益；产品的批内并行与实参级并行判定，收益在多工具并发场景才兑现【官：官方确认「存在并行与批」；调度细节【三】归属见 M2】 |
| 无独立 schema 校验层 | SDK 侧已承担外形检查；产品侧是五段验证管线（结构→语义→回填→前置钩子→权限）【三，载体＝站点轨深潜节】；教学版工具个位数、签名契约靠人眼盯得住 |
| 钩子无匹配器、无并行执行、无超时语义 | 官方钩子体系另有按模式匹配、并行执行、超时且「超时不算拦截」等完整语义【官，hooks】；教学版四个事件、五个回调，冲突面近乎为零 |
| 四事件 vs 产品事件全集 | 官方按节奏三分：per session（SessionStart/SessionEnd）、per turn（UserPromptSubmit/Stop/StopFailure）、每次工具调用（PreToolUse/PostToolUse，EndConversation 例外）【官，hooks § Hook lifecycle】；站点深潜节称产品有二十余个事件【三】 |
| 权限是教学版里「实现成钩子」 | 产品方向相反：权限求值独立于钩子【官，permissions § Extend permissions with hooks】。教学版的写法演示的是**扩展点统一**这个结构，不是产品的权限架构 |

一句话：教学版省掉的都是**规模**才逼出来的东西；留下的恰恰是任何规模下都不变的骨架——判据看事实、能力长在表里、检查有次序、扩展不进循环。（演进净判定：main 轨 0dcafa2a 相对旧钉，本维四章唯 s03_permission 有机制级演进，余章仅机械级变化。）

## 11. 批判性边界

本章独有六条（跨章的五条见[总纲 §7](./170-claude-code-harness-overview.md)）：

1. **「加一个工具只改两处」不可外推**。第三处签名契约是隐含的；产品侧的工具注册代价没有任何公开证据——官方文档只给工具清单与能力分类，不披露注册机制【官，how-claude-code-works § Tools】。教学版的「签名对齐」是教学实现耦合，产品是否同构无证据。
2. **续轮判据的产品级主张证据链单薄**。「另设独立标志位」的文面载体只在站点轨深潜节【三】，main 轨取证面（README＋code）不含此节；官方六页文档不披露实现层，**既无法核验也无法背书**。引用必须带归属，不得升格为已证事实。
3. **闸门的字符串匹配不是安全边界**。课程自己说明那张表只用来说明闸门位置、不能视为安全边界【一，main 轨 s03 README 自述】；官方对产品也是同口径：shell 规则匹配的是模型写出的命令文本，同一程序换种写法即失配，官方甚至对会被复合命令绕过的写法直接忽略并在启动时告警【官，permissions】。需要不依赖命令文本的强制，应交给权限系统与系统级沙箱。
4. **引入机制可能放松既有约束**。权限管线落地的同时，文件工具的硬路径边界被拆除（上一版命中、本章起零命中）——评价新机制要看**净效应**，不能只数加了什么、不数拆了什么。
5. **教学版的结构瑕疵不得外推产品**。串行短路的「审计漏记」、执行后返回值丢弃，都是教学版结构特有；产品并行合并、PostToolUse 有真实语义（M5、§9 对照）。拿教学版瑕疵批评产品，与拿产品能力夸教学版，都是轨混。
6. **两套 harness 分解不同构**。课程把 harness 拆成五元（工具、知识、观测、行动接口、权限），官方术语表是三元（工具、上下文管理、执行环境）加能力清单——课程的「权限」在官方口径里只是 harness 供给的能力之一【官，glossary · Agentic harness】。引用时必须并列标注并以官方为准。

## 13. 验收问答

1. **为什么续轮判据要看内容块，不看停止标记？** 停止标记是声明，内容块是事实；流式输出下声明会滞后于事实【三，带归属：载体＝站点轨深潜节】。main 轨固定提交四章全部按内容块判定【一】，站点轨旧修订信声明——同一门课两个修订判据相反，官方文档不披露实现层、无法裁决【官】。原型 D1 实测：信标记的版本会在标记失真的那一轮提前收工，丢掉已排好的活。
2. **加一个工具到底要改几处？** 显式两处（schema 一条、处理函数映射一行）＋隐式一处：处理函数形参名必须与 schema 属性名逐字一致，否则按关键字展开的调用直接失败【一】。产品侧注册代价无公开证据，不可外推。
3. **引入权限管线时，教学版发生了什么「倒退」？** 文件工具原有的工作区硬边界（越界直接报错）被整体拆除，越界降级为「问一下用户」——硬墙变成了对讲机。教训是评价新机制要看净效应：门禁加上了，墙却拆了。
4. **「决定权」与「放行权」的分界线画在哪里？** 画在工具调用落地与处理函数执行之间——main 轨 s03_permission 里就是接入循环的那一行权限调用。模型决定调什么工具，harness 决定放不放行、怎么执行；官方把这条分工说得更死：权限规则由 Claude Code 执行、不由模型执行，提示词只影响模型尝试什么【官，permissions】。两个人的活，不能交给一个人。
5. **为什么说钩子「只能收紧，不能放松」？** 官方口径：钩子放行绕不过拒绝/询问规则；而阻断型钩子（exit 2）在权限求值之前就停住调用，压得过放行规则【官，permissions】。要硬性放行或拒绝，官方指定用权限系统，钩子沉默也不等于批准。
6. **教学版与产品的钩子执行语义差在哪？** 教学版按注册顺序串行、第一个非空返回值就地短路（由此才有「拦截导致日志漏记」的结构性盲区）；产品全部匹配钩子**并行**执行，多决策按拒绝＞延迟＞询问＞放行合并【官，hooks】——不存在注册顺序遮蔽。教学版演示的是扩展点统一的结构，不是产品的执行语义。
